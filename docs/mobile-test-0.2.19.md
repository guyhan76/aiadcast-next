# aiadcast Preview 0.2.19 휴대폰 테스트

2026-10-11. 패키지 `com.selluplabs.aiadcast.next.preview`, versionCode 21.

## 이번 변경

- 사진 첨부: Android 13 이상에서는 사진 전용 선택창을 연다. 여러 장 선택 결과가 `ClipData`에만 들어오는 경우도 모두 전달한다. 이전 Android 및 선택창 미지원 기기는 문서 선택창으로 대체한다. 최대 10장, 전체 10MB이며 PNG/JPEG/WebP만 앱에 보관한다. JSON 프로젝트 가져오기는 한 파일만 선택한다.
- 미리보기 바로 아래에 입력 규격, 치수 표기 여부, 현재 적용 방식을 표시한다. `원본 사진 형상 유지`, `AI 규격 참고`, `모서리 확인 후 규격 박스 구성`을 구분한다. 일반 상품의 자동 3D 비례 검증은 구현되어 있지 않다.
- 규격 수정과 원본/결과 비교를 미리보기에서 바로 열 수 있다. AI 시안 사용 확정 후 규격·원본·참조 정보가 바뀌면 이전 시안을 적용하지 않는다.
- Preview/Dev 앱의 `테스트 계정 · 서버 연결`에 공개 HTTPS 테스트 서버 주소를 기기별로 저장할 수 있다. 출시 빌드에는 주소 변경 기능이 없다. 로그인은 서버 주소에 묶고 서버를 바꾸면 로그인·이메일 인증 요청·결제창 권한을 지운다. 현재 편집본은 기기에 보관한다. API 응답 리디렉션 및 다른 서버의 로그인 재사용은 거부한다.
- 준비 상태는 서버 응답, 이메일 설정, 테스트 결제 설정을 따로 보여준다. 설정 연결은 실제 메일 수신·결제 승인 증명이 아니다.

## 설치와 상품 제작

1. ZIP 압축을 풀고 `aiadcast-preview-0.2.19.apk`를 실행한다. 이미 설치된 Preview를 업데이트한다. 기존 앱을 삭제할 필요가 없다. Dev/다른 앱의 작업은 자동으로 옮겨지지 않는다.
2. 광고 만들기 → 사진 여러 장 추가 → 한 번에 사진 3장 선택. 3/10과 각각의 사진을 확인한다.
3. 상품명 입력 → 업종·규격 → 직육면체 → mm → 가로 340 / 세로 250 / 높이 210. 치수 표기는 선택이다.
4. 다음 → 추가 설정에서 제작 방식 선택 → 광고 만들기. 미리보기 아래 규격 적용 확인을 읽는다.
5. 원본 사진 그대로 합성은 원본 비례를 보존하고, 치수를 변경해도 일반 상품 사진을 자동으로 변형하지 않는다. AI 광고는 치수를 참고값으로 전달한다. 세 면이 보이는 직육면체 박스는 규격 탭의 모서리 7점 확인 후 계산된 입체에 원본 면을 배치할 수 있다.
6. 원본과 결과 비교 → 입력값, 원본, 완성 이미지 확인. 비교 PNG와 점검 정보, 광고 PNG를 기기에 저장해 본다. 사선 사진에서 보이는 픽셀 길이는 실물 변 길이와 같지 않다.

## 이메일 가입부터 테스트 결제까지

실제 HTTPS 서버, 발송 서비스와 Toss 테스트 키가 연결되어야 한다. 이 APK에 이메일/결제 비밀 키를 넣지 않는다. 현재 전달 시점에는 배포된 서버 주소와 외부 설정을 확보하지 못했으므로 실제 수신 및 결제 승인 시험은 미완료이다.

서버 준비는 [이메일·테스트 결제 연결](email-test-checkout.md), [비공개 서버 운영](beta-server.md)을 따른다. 필요한 공개 정보는 서버 주소와 인증메일 발신 주소다. Resend 비밀 키와 Toss 테스트 비밀 키는 호스팅 서비스의 비밀 환경변수에 직접 저장한다. 이 문서·채팅·저장소·APK에 기재하지 않는다.

1. 서버에서 `dist`와 Node 24 백엔드를 같은 HTTPS 주소에 제공한다. SQLite 데이터 디스크는 지속 보관하고 `scripts/run-beta.sh`로 단일 프로세스를 실행한다.
2. 휴대폰 → 테스트 계정 · 서버 연결 → 공개 HTTPS 서버 주소 입력 → 연결 주소 저장. 웹사이트 하위 경로나 토큰이 들어간 주소는 받지 않는다.
3. 다시 연결 상태 확인. 서버 응답, 이메일 설정, 테스트 결제 설정이 연결되어 있는지 확인한다. 설정이 없으면 버튼은 활성화되지 않는다.
4. 회원가입 시험 시작 → 자신의 이메일 입력 → 인증메일 받기. 메일 링크에서 이메일 인증하기를 눌러 원래 앱으로 돌아온다. 메일을 여는 브라우저에는 로그인 권한을 부여하지 않는다.
5. 내 이용권 → 수량/가격 확인 → 테스트 결제 동의 → 테스트 결제 준비 → 외부 브라우저 테스트 결제창. 실제 금액 청구 없이 시험한다.
6. 승인 후 앱으로 돌아와 결제 상태 확인. 서버가 승인 금액·주문·소유자·KRW 통화를 확인한 뒤 이용권을 한 번만 추가한다. 취소/미확인 상태에는 이용권을 추가하지 않는다.
7. 사진·상품명·규격이 로그인/결제 전환 뒤에도 유지되는지 확인한다. AI 유료 호출은 서버 키·기능 설정·개별 사용자 예산이 별도로 있어야 하며 테스트 결제만으로 예산이 자동 증가하지 않는다.

## 검증의 범위

이번 확인: 도메인 테스트 197개 통과, 모바일/데스크톱 브라우저 테스트 43개 통과(데스크톱의 터치 전용 시험 1개 제외), Android 단위 테스트 7개 통과, lint 오류 없음. 생성 결과를 대체한 테스트는 유료 이미지 생성이나 이미지 모델의 실제 품질 시험이 아니다.

증분 패키징 결과에서 서명 누락을 발견하여 clean 빌드로 다시 만들고 v2 서명 및 기존 Preview와 같은 인증서 SHA-256 `4df47020da101fcde3ab80cfa72449603d636e1f25e24ee7eb8423317f7d0dcd`를 확인했다. 후속 Preview 빌드도 clean 및 APK 서명/정렬 검사를 통과해야 완료된다. ZIP은 단일 영문 APK 파일만 포함하고 CRC 및 실제 압축 해제 후 바이트 동일성을 확인한다.

자동 테스트는 실제 HTTP+SQLite 흐름 및 브라우저 UI를 검증한다. 이메일 발송 서비스와 결제 승인 응답을 대체한 내부 테스트는 외부 서비스 성공을 증명하지 않는다. Android 빌드·서명·단위 테스트는 휴대폰의 실제 사진 선택창/설치/결제 브라우저 복귀 성공을 증명하지 않는다. 휴대폰 확인은 위 절차로 별도 수행한다.

사용자의 특허는 출원 단계다. 원본·규격 정보 보관, 요청 전달, 원본 합성/선택적 박스 면 배치/수동 비례 비교가 실제 구현 범위다. 특허 명세서 및 청구항을 확보하지 않은 상태에서 전체 출원 기술이 구현되었다고 표현하지 않는다.
