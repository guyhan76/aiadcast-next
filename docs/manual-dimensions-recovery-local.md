# Local manual dimensions and automatic result lookup

New creative-photo requests with manual dimension placement carry `manualDimensionBase: true`. The server validates this contract before dispatch, and asks the image provider to omit dimension text/arrows. This instruction is not automatic image verification: the user must confirm the returned base contains no baked-in measurements. Existing results are not erased or migrated.

The user selects two endpoints for every supplied measurement, adjusts spacing, and confirms the measured spans. An inset also needs an explicit crop and placement. No product-edge detector or reference-to-output coordinate mapper is called. Bounds and overlay-to-overlay collisions are checked geometrically; product correctness and overlap with baked-in advertisement text remain human review. Snapshot changes invalidate confirmation. Preview and downloaded PNG use the same renderer; the server artifact remains the unannotated base, and physical Android share integration is not newly verified.

Initial result lookup retries only transient GET failures, at most three attempts with 1/2-second backoff, 15 seconds per read and 45 seconds per recovery burst. Definite authentication, missing-job and invalid-response errors stop. A manual recovery remains available after bounded reads. Running jobs have a finite polling window; uncertain jobs receive three read-only checks. No generation POST, credit settlement or hold release is automatically repeated. A complete normalized server request fingerprint is required to recover a current preview after marker loss; mismatched or unknown snapshots remain blocked.

Local verification uses fixture images and mocked HTTP responses. It does not establish the cause of the prior production lookup failure, actual provider rendering quality, or physical-device behavior. No production migration is required by the new computed job fingerprint. Server and client must both support the manual-base contract before new manual requests can run.
