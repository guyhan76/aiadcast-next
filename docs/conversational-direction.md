# 대화로 광고 요청·수정하기

## 사용 흐름

편집기에서 ‘대화로 요청·수정하기’를 선택한다. 사용자는 원하는 광고를 문장으로 남기고, 필요하면 배경·조명·구도·상품 인쇄·상품 색상·광고 문구·비율/규격 표시 중 변경할 범위를 고른다. 프로젝트별로 최대 40개 요청, 요청당 1,200자를 보관한다.

예시: “상품은 그대로 두고 밝은 쇼룸 배경과 부드러운 조명으로 연출해줘.” → “오른쪽은 문구를 넣을 수 있게 비워줘.” 두 요청은 순서대로 함께 보관된다. 기존 조건을 바꿀 때는 ‘이 요청 제외’ 후 새로운 요청을 남긴다. 현재 시스템은 문장의 의미를 AI로 분석하거나 답변하지 않는다.

## 현재 실제 동작

| 요청 | 동작 |
|---|---|
| 배경을 검정색으로 바꿔줘 | 변경안 제안 → 사용자가 적용 → 배경색·글자 대비 조정 |
| 제목을 “브랜드의 가치를 담다”로 바꿔줘 | 현재 선택 언어의 제목만 변경 |
| 비율을 4:5로 바꿔줘 | 출력 비율 변경, 사진 원본과 규격 값 유지 |
| 규격은 숨겨줘 | 앱의 규격 표시만 끄고 입력값 유지 |
| 밝은 쇼룸에 상품을 놓고 자연광으로 연출해줘 | 대화 이력과 생성 요청 정보 보관, 실제 생성 전 |
| 상품 인쇄 색상을 금색으로 변경해줘 | ‘상품 인쇄’ 범위·별도 시안 허용 확인 후 요청 보관, 실제 편집 전 |

빠른 편집은 한/영의 제한된 명령 패턴을 완전히 일치시켜 처리한다. 복합 문장·부정문·불명확한 요청은 자동 실행하지 않는다. 사용자가 확인하지 않은 변경안은 생성 기획 내보내기를 막는다. ‘되돌리기’는 빠른 편집 적용과 요청 추가 모두 취소할 수 있다. 생성형 API 호출·고객 이용권 차감·자동 번역은 실행하지 않는다.

## 원본과 편집 범위

원본 보존 모드에서는 사진 파일·상품 형태를 보호하는 조건을 요청 계약에 넣는다. 상품 인쇄/색상 변경은 그 원칙의 명시적 예외이며, 실제 상품과 동일하다고 주장하지 않는 별도 시안으로 지정한다. 업로드 파일 자체는 덮어쓰지 않는다. 창작 모드는 새로운 광고 시안으로 구분하고 상품 동일성을 보장하지 않는다.

대화 항목은 작성 당시 사진 SHA-256, 업종, 상품·서비스명, 언어를 보관한다. 자료가 바뀌면 미처리 요청을 그대로 재사용하지 못하게 한다. 빠른 편집은 작성 당시 해당 필드 값도 비교한다. 배경 사진을 사용하는 중에는 배경색 요청으로 사진을 조용히 삭제하지 않는다. 규격 없는 서비스에 ‘규격 표시’를 요청해도 치수를 만들어 넣지 않는다.

프로젝트 JSON 가져오기는 대화 필드·개수·길이·상태·ID 중복·상품 변경 권한 범위를 검사하고 지정 필드만 읽는다. 요청 텍스트를 HTML이나 코드로 실행하지 않는다. 기기 저장과 JSON 백업에는 대화도 포함되며 PNG에는 적용된 현재 화면만 포함된다. 보관 요청은 별도 서버로 전송하지 않는다.

## AI 연결 때 구현할 계약

`buildGenerationRequest()`는 미처리 요청을 `direction.instructions`에 순서대로 넣고, 원본 유지/인쇄/색상/마스크/별도 시안 정책을 별도 필드로 전달한다. 적용·제외된 요청은 다시 생성하지 않는다. `providerStatus: not-connected`, `execution: not-started`로 현재 상태를 명시한다. 이 JSON은 실행 가능한 서버 작업이나 결제 승인이 아니다.

다음 단계의 서버 어댑터는 자연어 대화 → 구조화한 변경안 → 기존 조건과 충돌 확인 → 사용자 적용/생성 선택 순으로 처리해야 한다. “좀 더 밝게” 같은 상대 지시도 최신 승인본을 기준으로 해석해야 하며, 모델의 응답이 상품 보호 설정·사용자 허용 범위·서버 과금 규칙을 바꾸지 못하게 한다. 인쇄/색상 변경에는 사용자 검토 가능한 영역 마스크와 새 버전 저장이 필요하다. 현재는 마스크 요구 조건만 전달하며 자동 마스크·부분 이미지 편집은 구현 전이다.

유료 생성은 가격·변경 범위 확인 후 서버에서 요청 ID당 한 번만 예약한다. 생성 실패·품질 미달 처리와 고객 승인 후 확정은 기존 이용권 원장에 연결한다. 대화 요청 저장·빠른 편집은 고객 생성 이용권을 차감하지 않는 정책으로 유지한다. 향후 자연어 분석에도 공급사 API 비용은 발생할 수 있으므로 이를 고객 이용권과 구분해 운영 예산에 포함한다.

## 검증 근거

`tests-domain/conversation.test.mjs`는 원본 보존, 단일 필드 변경, 모호한 문장 비실행, stale 요청 차단, 동의·범위, 가져오기 검증, 요청 데이터 분리를 확인한다. `tests/conversation.spec.ts`는 실제 브라우저에서 확인 후 적용·취소, 저장/불러오기/백업, 후속 요청·사진 교체, 좁은 화면을 검사한다. 실제 생성 품질·대화 모델의 이해도 검증은 AI 연결 후 별도로 수행한다.
