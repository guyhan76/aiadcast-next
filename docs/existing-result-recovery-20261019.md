# 기존 결과 조회 안정화

변경 기준: PR41 `cde928a8f6373e00b529c6f0857c571ace359457` 위의 별도 수정 브랜치. 이미지 생성 모델·설정·프롬프트·규격 생성 코드는 변경하지 않는다.

## 원인과 수정

기존 GenerationPanel은 `/api/status` 성공 후에만 기존 작업을 조회했다. 상태 요청의 오류 또는 시간 초과가 이미 완성된 결과의 조회까지 막았다. 예산 부족 응답 자체는 기존 작업 조회를 막지 않았으며, running 폴링도 예산 조건과 독립적이었다.

상태와 결과 요청을 독립된 취소·시간 제한으로 분리했다. 결과 조회는 기존 인증 API만 사용한다. 기기에 pending 기록이 없으면 현재 프로젝트 ID로 이력을 조회하며, 서버의 계정별 인증·저장소 격리를 그대로 따른다. 다른 프로젝트 결과는 적용하지 않는다. 활성 결과가 여럿이거나 이력을 확인하지 못하면 임의 선택과 새 생성을 중단한다. 새 생성은 기존 작업 조회가 성공한 뒤에만 가능하다.

기기 기록을 잃은 완성 광고는 서버의 compositionKey·sourceHash·mode가 현재 입력과 일치할 때만 복구 검수를 허용한다. 해시·규격 계약 등 기존 결과 검증을 유지한다. 원본 사진 합성처럼 서버가 완성 광고 입력 키를 제공하지 않는 결과는 임의로 호환된다고 간주하지 않는다. 입력을 복구할 수 없는 경우 미리보기 적용/확정 제한이 남는다. 서버 이력은 현재 API의 최근 30개 범위다. 프로젝트 자체가 기기에서 사라진 경우를 복원하는 기능은 아니다.

항상 표시되는 ‘기존 결과 다시 확인’으로 새 생성 없이 재조회할 수 있다. 조회는 수락·반려 요청을 보내지 않는다. 기존 이용권 결과의 사용 확정은 예약된 1개를 사용 처리하며, 저장은 AI 재생성이 아니다. 예산 차단과 이미 진행 중인 요청을 구분하는 기존 로컬 안내 변경도 유지했다.
