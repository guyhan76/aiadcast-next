# 신규 회원의 테스트 결제·생성 준비 상태

운영 기준 `ffb7b7aab761e0a298f8f918bd5e0d42fb1339d1`에서 결제 화면의 ‘결제 연결 준비 중’은 capability 조회 중·실패·미연결을 구분하지 않았다. 후속 UI는 조회 중, 10초 이내 응답을 받지 못한 경우를 포함한 조회 실패와 명시적인 서버 미연결을 나눈다. 재시도는 capability GET만 수행하며 상품 선택을 유지한다. 연결을 확인하기 전 주문 생성은 차단한다.

서버의 `real payments disabled`는 안내 로그이며 테스트 결제 차단 조건이 아니다. 서버 결제는 Toss 테스트 키와 명시적 활성화가 필요한 sandbox 연동이다. 기기 내부 offline-demo 결제는 별도의 로컬 모의 결제이며 서버 회원·이용권·이미지 API와 연결되지 않는다. 이번 검사는 대체 공급사를 사용했고 실제 Toss 요청은 하지 않았다.

일반 신규 회원은 이용권 0, API 예산 0으로 시작한다. 정상 테스트 결제는 이용권만 지급하고 예산은 늘리지 않는다. 따라서 결제 성공 후에도 `BUDGET_NOT_AVAILABLE`일 수 있다. 가입→구매→실제 생성의 일반 상용 흐름은 완성되지 않았다. 시연 지원을 판매·결제 완료나 일반 회원 자동 제공 정책으로 표시하지 않는다.

## 기존 관리 경로의 제한

- `/api/admin/grants`: 관리자 권한과 고유 요청 ID로 테스트 이용권 3개 지급 가능. 결제 영수증과 구분된 `admin-test:` 원장을 사용한다.
- `/api/admin/allocations`: 기존 배정을 늘릴 수 있으나 기본 총액과 월 승인 총액을 모두 검사한다. 관리자 월 배정액을 낮추거나 옮기는 경로는 없다.
- 현재 10월 승인 정책은 전체 5,000,000 micros와 관리자 배정 5,000,000 micros를 고정한다. 이 정책이 활성화된 경우 일반 회원에게 1,000,000 micros를 추가하면 `BETA_ALLOCATION_EXCEEDED`가 발생한다. 전체 $5 제한이 무시되는 것이 아니라 추가 배정을 거절한다.
- 따라서 ‘기존 $5 안에서 회원 $1’ 승인이 있어도 현 관리 API로 바로 실행할 수 없다. 대상 이메일도 먼저 확인해야 한다. DB 직접 편집, 총액 증액, 관리자 역할 부여로 우회하지 않는다.

가장 작은 후속 구현은 승인된 단일 회원에 대해 관리자 월 배정 일부를 이동하는 별도 감사 가능한 작업이다. 전체 $5 고정, 회원 월 최대 $1, 관리자 사용액+보류액 이하로 삭감 금지, 모든 회원 배정 합 검증, 동시 생성/중복 요청/재시작/월 만료를 포함한 원자적 처리가 필요하다. 이 문서는 구현·운영 변경 승인이 아니며 현재 UI 수정에 그 작업을 추가하지 않았다. 기존 관리자의 개인 이용으로 시연하거나 비유료 로컬 모의 흐름을 보여주는 것은 일반 회원 문제 해결과 구분해야 한다.

이번 변경은 UI와 로컬 재현 테스트만 포함한다. 운영 이용권·예산·환경·DB, 실제 결제, 이미지 API, 외주 앱을 변경하지 않았다. 기존 APK는 웹 UI를 내장하므로 UI 수정 배포 후에도 새 APK를 따로 만들어 설치하기 전에는 같은 화면을 유지한다.
