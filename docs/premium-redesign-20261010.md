# 광고 제작 흐름과 프리미엄 방향 재설계 · 2026-10-10

사용자가 기존 앱과 외주 결과 모두에 불만을 표시했다. 첨부 결과는 승인된 디자인이 아니라 문제를 비교하는 자료로 취급한다. 이 변경은 생성 품질 전체 합격이나 상품 동일성 보장으로 해석하지 않는다.

## 고객 흐름

- 홈: aiadcast 브랜드와 광고 만들기 한 가지 주 행동. 이전 외주 광고를 새 앱 성능 예시처럼 제시하던 이미지 제거.
- 제작: 상품 사진·상품 상세설명 → 광고 스타일 → 비율·선택적 연락처. 업종은 기본값으로 시작하며 세부 업종·규격은 펼쳐서 변경한다. 서비스는 사진 없이 시작할 수 있다.
- 새 제작 기본값: AI 연출, 피드 4:5. 원본 합성 모드도 선택 가능하며 기존 프로젝트의 모드는 바꾸지 않는다. 생성 연결이 없으면 원본 합성을 AI 결과처럼 표시하지 않는다.
- 결과: 미리보기·생성·저장이 먼저 보인다. 정보 편집, 대화 수정, 캡션·키워드·활용 가이드는 접어서 제공한다.
- 참조사진은 대표 1장과 추가 9장, 총 10장이다. PNG/JPEG/WebP, 전체 10 MB. 자동 재압축 없이 읽은 바이트와 해시를 보관한다. 대표 변경·삭제·중복·개수·총 용량 검증을 제공한다.
- 상품 상세설명은 최대 2,000자. 긴 설명을 그대로 작은 광고 글자 영역에 밀어 넣지 않는다. 생성 맥락 및 요청한 문구 제안에 활용한다.
- 회사명·연락처·이메일·홈페이지 각각 값과 하단 표시 선택을 저장한다. 숨긴 값은 보관하지만 광고 캔버스에는 그리지 않는다. 문구 수정에 추가 이미지 호출 없음.

## 생성 및 출력

모든 참조사진은 API에서 실제 디코딩과 해시·크기·개수·순서를 검증한다. 추가 참조 해시도 요청 지문과 기존 결과 재사용 판단에 포함한다. 바뀐 참조로 이전 결과를 사용 확정할 수 없다. 원본 합성 모드에서는 공급사에 상품 사진을 보내지 않는 계약을 유지한다.

창작 요청은 첫 사진의 상품을 중심으로 재질·실루엣·조명을 표현하고, 추가 사진은 다른 각도·세부 정보로 사용하도록 구성했다. 전체 광고 레퍼런스를 첨부해도 가격표·아이콘·작은 사진 목록을 복제하지 않도록 지시한다. 에디토리얼/시그니처/내추럴/모던 테크의 빛·재질·톤 지침을 전달한다. 지시만으로 상품 보존이 검증되는 것은 아니다.

새 프로젝트에서 검토 후 적용한 생성 이미지는 전체 캔버스 영역을 사용한다. 원본을 임의 크롭·늘림하지 않고 비율을 유지한다. 비율이 다르면 여백이 남을 수 있다. 광고 문구·연락처·규격 숫자는 실제 글꼴로 별도 합성한다. 기존 프로젝트의 이전 배치는 보존한다.

## 실제 API 시험

기존 승인 $1 원장(`release/live-test-2026-10-10/test.sqlite`)을 그대로 사용했다. 추가 이미지 요청은 1회, 자동 재시도·모델 변경 없음. 첨부 박스 광고의 검정 리본 선물박스를 참조했다.

- 모델: `gpt-image-2.5-sunburst`, high, 1024×1280, 이미지 편집 API HTTP 200.
- 입력 텍스트 969 / 입력 이미지 1,508 / 출력 이미지 1,510 토큰.
- 기록된 요율 기준 추정 비용 $0.062209. 기존 누적 $0.047986 → $0.110195. 청구서·세금·환전 비용과 구분한다.
- 실제 파일: `release/reference-review/quality-visual.png`, 별도 글자 합성: `quality-ad-review.png` (1080×1350).
- 조명·재질·상품 중심 구성은 확인했으나, 원본과 리본의 구조가 달라 **상품 동일성 미합격**. 시안을 반려하고 개발용 이용권을 복원했다. 공급사 비용은 발생한 비용으로 유지했다.
- 10장 동시 입력은 공급사 요청 직전까지 모의 검증했다. 이번 실호출은 참조 1장이다. 10장 실호출의 비용·품질·기기 성능은 미검증.

## 미완료 범위

이 APK에는 공개 AI 서버 주소·공급사 키가 없다. PC 개발 환경에서의 실제 호출 성공을 휴대폰 생성 성공으로 설명하지 않는다. 공개 API 연결, 실기기 APK 설치·파일 선택/저장, 상품 인쇄·형상 동일성, 영역 지정 AI 수정, 실제 결제·Play 출시는 별도 검증이 필요하다.

사용자가 말한 “목표를 설정하지 못했다” 오류는 APK 다운로드 또는 설치 중 발생했다고 확인했다. 앱 내부 광고 목적 선택 실패라는 진단은 하지 않는다. 파일 서명·패키징 검증은 가능하지만 원래 기기의 오류 재현·해결을 확인한 상태는 아니다.

## 검증 결과

- TypeScript/Vite/독립 HTML 빌드, 도메인 150개 통과.
- Chromium PC/모바일 104개 시나리오 통과(전체 실행 100개, 접힌 편집 패널에 맞춘 검사 수정 후 면 투영 2개 재검사, 기존 운세 프로젝트 호환성 2개 추가 검사). 320/390/768/1440 폭 확인.
- Android Java 단위 2개, 다운로드 브리지 4개, lint 오류 0개, APK 서명 검증 통과. APK 내 웹 자산 127개가 검사한 dist와 바이트 단위로 일치.
- Android 0.2.0-dev/versionCode 2. 이전 임시 개발 서명키가 유실돼 새 개발 서명으로 빌드했다. 기존 aiadcast Dev와 서명이 다르므로 기존 작업을 JSON으로 백업한 뒤 삭제·재설치가 필요하다. 외주 앱 삭제는 필요 없다. 새 개발 키는 Git에서 제외되는 release/android-signing/debug.keystore에 보관한다.
- APK 다운로드/설치 오류의 원래 원인은 아직 재현하지 못했다. 새 APK 생성과 서명 검증을 해당 휴대폰의 문제 해결로 표현하지 않는다.
