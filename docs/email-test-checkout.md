# 이메일 가입·테스트 결제 — 2026-10-11

이메일 인증, 승인된 가격표의 이용권 선택, 토스페이먼츠 테스트 승인과 이용권 반영을 코드로 연결했다. **현재 공개 서버·발송 계정·토스 테스트 키가 연결되지 않았으므로 실제 메일 발송과 공급사 테스트 결제를 완료한 상태는 아니다.** 앱 설치본 0.2.14와 기존 다운로드 페이지는 이번 변경으로 갱신하지 않았다.

## 사용자 흐름

- 이메일 입력 → 인증메일 받기 → 메일에서 직접 인증 → 요청한 앱에서 자동 로그인. 회원가입과 재로그인은 같은 흐름이며 비밀번호·아이디·전화번호를 받지 않는다.
- 이용권 선택 → 수량·금액·테스트 안내 한 번 확인 → 결제창 열기 → 토스 테스트 승인 → 이용권 반영 → 작성하던 광고로 복귀.
- 기존 확정 가격을 유지한다: 3개 6,900원, 10개 19,900원, 30개 49,900원. 기존 외주 앱 스크린샷 가격을 적용하지 않았다. USD는 비교 표시이며 현재 테스트 결제는 KRW만 지원한다.
- 사진·회사명·제작 단계·편집 중인 광고는 계정별 IndexedDB 임시 작업으로 보관한다. 이메일 가입 전 게스트 작업을 가입한 계정으로 옮긴다. 기존 계정의 진행 중 작업이 있으면 프로젝트 보관본으로 남긴다. 다른 로그인 계정의 작업은 이전하지 않는다.
- 선택한 이용권·진행 중 주문은 탭 저장소에 보관한다. 새로고침·결제 취소 후 다시 선택할 수 있고 승인 확인이 불확실하면 먼저 상태를 확인한다. 브라우저 데이터 삭제나 OS의 저장소 제거까지 복원을 보장하지 않는다.

## 서버 설정

Node 24, HTTPS origin, 단일 서버 프로세스, 영구 SQLite 디스크를 사용한다. 기존 `npm run api:beta`와 `scripts/run-beta.sh`를 유지하며 로컬 전용 `api:dev`는 이메일·결제 서버가 아니다. 발송/결제를 설정하지 않으면 기능은 비활성으로 표시된다. `npm run build` 후 베타 서버가 같은 dist를 제공해야 인증·결제 링크가 열린다.

| 설정 | 값 / 용도 |
|---|---|
| `AIADCAST_BETA_PUBLIC_ORIGIN` | 실제 HTTPS 앱 서버 origin. 경로·query·fragment 금지. |
| `AIADCAST_EMAIL_ENABLED` | 발송 계정 검증 후 `true`. 기본 비활성. |
| `AIADCAST_EMAIL_FROM` | Resend에서 검증한 발신 주소. |
| `AIADCAST_RESEND_API_KEY` | 발송용 비밀키. 서버의 보안 설정으로만 전달. |
| `AIADCAST_TOSS_TEST_ENABLED` | 테스트 상점 설정 후 `true`. 기본 비활성. |
| `AIADCAST_TOSS_TEST_CLIENT_KEY` | 표준 결제창 API 개별 연동 테스트 클라이언트 키(`test_ck_`). 결제위젯 전용 키가 아님. |
| `AIADCAST_TOSS_TEST_SECRET_KEY` | 같은 테스트 상점의 원본 시크릿 키(`test_sk_`). 서버 런타임 보안 환경변수. |
| `AIADCAST_TOSS_TEST_SECRET_KEY_FILE` | 시크릿 키 환경변수 대신 외부 보안 파일을 지정할 때 사용. 파일 설정이 우선. |

비밀키를 채팅·Git·APK·Vite 변수·로그에 넣지 않는다. 토스는 Basic 인증을 만들기 위해 원본 키를 base64로 변환하므로 **클라우드 프록시의 불투명한 비밀값 자리표시자를 원본 키처럼 변환하면 안 된다.** 토스 키는 배포 서버의 보안 환경변수 또는 보안 파일로 전달한다. Resend Bearer 키는 프록시 비밀값 바인딩을 사용할 수 있다.

환경 설정 초안에 Resend 비밀값 요구사항, 활성화 스위치, 공개 origin과 발신 주소·토스 클라이언트 키 요구사항을 추가했다. 기존 OpenAI 도메인을 유지하고 `api.resend.com`, `api.tosspayments.com`, `js.tosspayments.com`을 추가했다. 초안 저장은 실행 환경 반영이나 비밀값 생성이 아니다. 환경 설정에서 검토·저장 후 Publish해야 한다. 공개 서버에도 별도로 보안 설정을 연결해야 한다.

실제 발송은 Resend에서 검증한 발신 도메인과 수신자 제한을 확인한 후 진행한다. 외주 토스 계정 접근 가능 여부는 아직 확인되지 않았으며 새 앱에 기존 고객 데이터·운영 키를 복사하지 않았다.

## 인증·결제 경계

- 이메일 링크와 요청 기기의 교환 토큰은 각각 256비트 난수, DB에는 해시만 저장. 링크 10분, 세션 24시간. GET으로 인증하지 않으며 메일 브라우저에 세션을 발급하지 않는다.
- 이메일별 재요청 60초 간격·시간당 최대5회, 전체 인증 요청 제한, 기존 베타 최대20명 유지. 새 계정의 공급사 예산·초기 이용권은 0으로 시작한다. 가입이나 테스트 충전으로 유료 AI 호출이 자동 활성화되지 않는다.
- 서버가 이용권·금액·통화를 결정한다. 임의 사용자 ID·가격·이용권 수를 신뢰하지 않는다. 주문 소유자와 일회 주문 요청 식별자를 확인한다.
- 네이티브 앱은 HTTPS 결제 링크를 외부 브라우저로 연다. 외부 브라우저에는 앱 세션 대신 주문에 한정한 난수 티켓만 전달한다. 승인 후 원래 앱의 계정별 주문 상태 조회로 복귀한다. 토스 SDK는 결제 전용 화면에서만 로드한다.
- 공급사의 `DONE` 응답에서 주문 ID·KRW 금액·paymentKey를 확인한 다음 원장에 반영한다. 승인 응답 유실·동시 요청·원장 반영 직후 서버 중단은 주문 조회와 고유 purchase ID로 재확인한다. 동일 결제는 중복 충전하지 않는다.
- 운영 키는 거부한다. 테스트 주문·이용권이며 실제 판매·청구·환불·구독·Play Billing을 구현한 것이 아니다. 공개 판매 전 약관·개인정보·환불 정책, PG 계약, 스토어 결제 방식, 실제 기기 왕복 검증이 별도로 필요하다.
