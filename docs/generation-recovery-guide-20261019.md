# 생성 복구·사용안내 정리 — 0.2.48-demo

기준은 앱 PR51/46a85ca, 사용자 확인 운영 서버331da9d이다. 사용자 제공 화면에서 전송 결과 확인 실패→수동 재조회→결과 도착 이후에도 확인 중/복구 UI가 남았다. 운영 네트워크 로그는 조회하지 않았으며 timeout/cold start 등 실제 전송 실패 원인은 미확정이다.

코드상 전송 실패 후 자동 복구가 없고, running 폴링은 겹칠 수 있는 setInterval이며 오류를 성공 응답에서 지우지 않았다. ready도 생성·확인 중 문구를 사용했고 복구 버튼은 항상 노출됐다.

- 생성 POST는 한 번만 전송한다. 불확실하면 저장된 requestId와 projectId로 최대3회 읽기 복구(총45초 한도,1/2초 간격)를 한다. 임의 작업을 선택하지 않는다.
- jobId 확인 후에는 해당 작업 GET만 순차 조회한다. 각 조회15초 제한,2초 간격,최대60회/약3분 및 연속3회 실패 제한. 끝까지 확인되지 않으면 수동 기존 결과 확인을 제공하고 새 생성은 막는다. 인증 거절·잘못된 작업 식별자는 즉시 중단한다.
- 정상 결과 조회 시 이전 연결 오류를 정리하고 폴링을 중단한다. 완료 표시는 결과 확인 단계로 바꾸며 불필요한 복구 버튼을 숨긴다. 사람 검수·원본/규격/결과 해시 확인·사용 확정 보호는 유지한다.
- 결제 지급 알림은 작업 복귀 화면에서 짧게 표시한다.60초 후 또는 다른 페이지로 이동 시 폐기한다. 사용안내에는 표시하지 않는다.
- 사용안내의 앱 버전/지원 버전 영역을 제거하고 서버의 관리자 overview 조회가 성공한 관리자 페이지에만 표시한다. 기존 관리자 인증/권한 검사를 유지한다.

서버·AI모델·프롬프트·사진 참조 범위·결제 및 차감 로직은 변경하지 않는다. 서버 별도 배포는 필요하지 않다. APK0.2.48-demo/code50은 기존 패키지/서명으로 업데이트한다. 테스트는 대체 API 응답/로컬 provider만 사용한다. 실제 사용자 기기와 운영 네트워크에서의 최초 생성 복구는 별도 확인이 필요하다.
