# 광고 안 자동 규격 표시 — 앱 통합 후보

기준은 PR #11 `f015d0818fb9d98461f402509c733b7c25943714`이며, 운영 기준은 사용자 보고 `d6032b3efa9aff1b3f9440e7d5572474a2c89d0a`다. 이번 브랜치는 `feat/dimension-annotation-app-20261017`이다. **앱 통합 및 모의 검증과 실제 자동 인식 정확도·운영 활성화는 별개**다.

## 앱에 연결한 흐름

- 완성 광고 결과에 `표시 없음 / 본제품에 직접 표시 / 같은 제품 작은 사진에 표시` 선택을 제공한다.
- 서버가 분석 가능 상태를 알린 경우 표시 선택으로 자동 분석을 요청한다. 좌표를 먼저 수동 입력시키지 않는다.
- 자동 결과를 얻은 뒤에만 `위치 수정`을 제공한다. 원본 위의 점을 드래그하거나 방향키로 이동하고 적용/취소할 수 있다.
- 동일한 좌표·저장 치수로 미리보기와 PNG를 만든다. 작은 사진은 실제 생성 결과의 동일 상품 픽셀을 잘라 사용하며 다른 상품을 새로 생성하지 않는다.
- 표시 방식·좌표·수정 여부·원본 및 치수 스냅샷은 프로젝트에 저장한다. 새로고침 복구, 저장·백업 자료, 다시 다운로드가 이를 유지한다. 위치 수정·모드 전환·다운로드는 분석 호출을 추가하지 않는다.
- 원본/치수/치수 기준이 바뀌면 이전 좌표를 재사용하지 않는다. 지원하지 않는 형상, 문구 충돌, 불명확한 분석은 자동 성공으로 취급하지 않는다. 요청 중단 후 늦게 도착한 응답은 적용하지 않는다.
- 원래 광고 바이트와 생성 결과는 변경하지 않으며 `표시 없음` PNG는 원래 출력과 동일하다. 원본 모드/별도 사진판 등 좌표 변환이 검증되지 않은 결과는 이 기능을 활성화하지 않는다.

## 기존 서버 키 재사용과 승인 한도

Render 서버의 기존 `betaConfig().key`를 새 분석 서비스에 메모리로 전달한다. 새 키, 키 복사/출력, env 파일 저장, 신규 환경변수 설정을 요구하지 않는다. 실제 이 환경에서는 키를 읽거나 실제 분석을 호출하지 않았다.

`GET /api/dimension-analysis`는 로그인한 사용자에게 가능 여부를 알리고, `POST`는 서버 인증 관리자만 처리한다. 클라이언트의 관리자 표시를 신뢰하지 않는다. 서버에 고정한 두 첨부 광고의 SHA-256과 실제 이미지 바이트가 일치해야 한다. 일반 이용자 또는 다른 광고에는 유료 분석을 허용하지 않는다.

**기본 비활성:** 승인 참조 이미지의 다운로드/육안 확인 및 해시 확정이 아직 끝나지 않아 현재 manifest는 비어 있다. 기존 서버 키가 있어도 호출되지 않는다. 화면은 일반 광고 분석이 켜지지 않았음을 설명하며 원본 저장을 제공한다. 배포만으로 자동 분석이 사용 가능해지는 것은 아니다.

클라우드는 기존 Supabase PostgreSQL account schema의 `dimension_analysis_calls`에 공통 원장을 기록한다. 두 사진과 관리자 전체가 승인 한도를 공유하며 Render 재시작이나 배포로 초기화되지 않는다. 트랜잭션 잠금으로 동시 예약을 직렬화하고 호출 전에 3센트를 예약한다. 총 10회/30센트, 자동 재시도 없음, 비용 불명확/초과 시 후속 호출 차단을 유지한다. 새 DB 역할이나 더 넓은 보안 권한을 요구하지 않는다.

동일 승인 예산을 로컬 SQLite와 운영 PostgreSQL에서 각각 중복 사용할 수 없도록 이전 로컬 CLI의 유료 실행을 폐쇄했다. 로컬 beta 서버도 기본 비활성을 유지한다. 실제 시험이 가능해지면 기존 운영 서버의 공통 원장 한 곳에서만 수행한다.

분석 단가 예상은 고정 요청 기준 약 US$0.01/회, 보수적 입력 상한 기준 US$0.013672, 예약액 US$0.03/회다. **현재 승인은 첨부 박스·쇼핑백 두 광고의 테스트만**이다. 일반 광고마다 자동 분석을 운영하려면 적용 사용자/광고 범위, 월간 비용 한도, 재분석 정책을 정한 별도 승인이 필요하다. 기존 이미지 생성 이용권 면제를 분석 비용 승인으로 해석하지 않는다.

## 배포 범위와 차단

현재 제공 도구에 Render 배포 도구가 없고, 실행 환경에 Render CLI 또는 API 자격 증명도 없다. 배포 요청 자체는 승인됐지만 이 환경에서는 배포를 실행하지 못했다. 자동 승인 심사에서 거부된 것이 아니다.

CI 성공한 최종 PR head SHA로 **UI·저장·비활성 안전 기본값을 포함한 앱 후보**를 배포할 수 있다. 실제 자동 배치 사용 가능/정확도 완료본으로 설명하면 안 된다. 운영자는 서비스 이름 `aiadcast-next`, 연결 저장소 `guyhan76/aiadcast-next`, 기존 Supabase/키 설정이 맞는 서비스에서 **Manual Deploy → Deploy a specific commit → 최종 검증 SHA → Deploy Commit**을 실행한다. 키·유료 플랜·자동 배포 설정을 새로 추가할 필요가 없다. 이 수동 방식은 자동 배포를 비활성으로 유지한다. [Render 공식 절차](https://render.com/docs/deploys#deploying-a-specific-commit)

최종 SHA·검사 결과는 후속 draft PR 설명에 기록한다. 배포 후 Live SHA와 로그인·기존 프로젝트 복구·원본 다운로드를 확인해야 실제 배포 완료다. 되돌릴 기준은 `d6032b3efa9aff1b3f9440e7d5572474a2c89d0a`다.
