# 일반 상품의 규격 비례 비교 및 증거 저장

작성일: 2026-10-11. 개발 브랜치 구현 기록. 자동 형상 복원 또는 실물 검증 완료 보고서가 아니다.

## 해결한 문제

기존 `원본과 결과 비교`는 두 사진을 나란히 표시하고 비교 PNG를 저장했다. 실제 상품과 입력 규격의 비례가 결과에서도 유지됐는지 수치로 기록할 수 없었다. 이번 변경은 이 화면에 **선택적 정면 두 축 비교와 증거 JSON 저장**을 추가한다. 일반 광고 제작·결제·생성 횟수에는 새 필수 단계를 만들지 않는다.

## 사용 흐름

1. 실제 사진과 단위가 확인된 규격을 입력하고 광고 결과를 준비한다.
2. `원본과 결과 비교` → `상품 비례 수치 비교 · 선택`을 연다.
3. 규격의 측정 범위를 적는다. 예: 가방 본체는 손잡이를 제외했는지, 화장품 용기는 뚜껑을 포함했는지 확인한다.
4. 원본과 결과가 모두 정면에 가까운지 사용자가 확인한다. 사선은 수치 합격 판정에서 제외한다.
5. 각 사진에서 가로 시작/끝, 높이 시작/끝 총 네 점을 표시한다. 평면 상품은 가로와 세로, 원통형은 지름과 높이를 쓴다. 잘못 찍은 점은 취소할 수 있다. 키보드 방향키와 Enter도 지원한다.
6. 원본-입력 규격, 결과-입력 규격, 원본-결과 변화율을 각각 확인한다.
7. `사진·규격·비교 기록 저장`을 눌러 원본과 결과 PNG 데이터, SHA-256, mm 규격, 측정점, 판정, 한계를 JSON 한 파일로 보관한다. 다운로드 전에 사진 바이트의 해시를 다시 계산한다.

비교 화면을 열 때 프로젝트를 깊은 복사하고 최신 광고를 다시 렌더링한다. 편집 도중의 캔버스나 치수 조정 손잡이를 증거로 저장하지 않는다. 편집 후 다시 열면 새 스냅샷을 만든다. 이 기록은 프로젝트 가져오기용 백업과 다른 **비교 증거 파일**이다.

## 판정 범위

- 화소 길이 = 정규화 좌표 차이에 각 이미지의 실제 픽셀 가로·세로를 적용한 유클리드 거리. 화면 표시 배율이나 사진 종횡비가 바뀌어도 같은 길이를 계산한다.
- 입력 비례 = 가로/높이, 평면은 가로/세로, 원통형은 지름/높이.
- 규격 대비 상대 차이 = `abs(측정 비례 - 입력 비례) / 입력 비례`.
- 결과 변화율 = `abs(결과 비례 - 원본 비례) / 원본 비례`.
- 두 사진의 규격 대비 차이와 결과 변화율이 모두 10% 이내일 때만 `정면 두 축 비교 범위 내`로 표시한다. 10%는 개발 비교 정책이며 출원서의 보장 수치·제조 공차·광고 품질 보증이 아니다.
- 측정 범위 미확인, 사선, 네 점 미완성은 미검증이다. 10픽셀 미만 선, 범위 밖 좌표, 정면에서 약 90도가 아닌 축은 점검 대상으로 처리한다.
- 깊이·원근·숨은 면·로고와 색상 동일성·실물 mm 길이는 판정하지 않는다. `geometryVerified`, `identityVerified`, `automaticallyDetected`, `externallyCertified`는 항상 false다.
- 기록은 로컬에서 작성한 서명 없는 파일이다. 해시는 사진 바이트를 연결할 뿐 사용자의 측정, 원본 출처 또는 생성 진위를 공인하지 않는다.

## 검증 결과

- `npm run build`: 통과. 기존 500KB 초과 번들 경고 유지.
- `npm run test:domain`: 194개 통과. 새 비례 비교 검사 14개 포함.
- 신규 검사는 박스, 가방, 원통형 화장품 용기, 소형가전, 시계, 평면 라벨에 해당하는 **합성 규격/측정점**을 사용했다. 실제 상품 사진·공급사 생성 성능 시험이 아니다.
- 회전·균일 배율, 이미지 종횡비 보정, 늘어난 결과, 두 사진이 동일하게 틀린 경우, 각 사진은 허용 범위지만 상호 변화가 큰 경우, 사선, 미확인 범위, 잘못된 점, 10% 경계, cm/inch→mm, 스냅샷 독립성, 잘못된 메타데이터, 무규격 서비스 등을 검사했다.
- `tests/compare-review.spec.ts`에 실제 다운로드 바이트/해시, 사선 미검증, 유료 호출 없음, 모바일 너비 검사를 추가했다. 이 환경의 `/usr/bin/chromium` 부재로 브라우저 실행이 차단돼 **화면과 다운로드 통합 검사는 아직 통과로 기록하지 않는다**.
- 신규 실제 AI 호출, 운영 배포, APK 설치 또는 금융기관 제출은 하지 않았다.

## 아직 필요한 실물 검증

정면과 사선 원본, 외형 실측값, 측정 범위가 확인된 박스·가방·화장품 용기·소형가전·시계·평면 제품을 확보한다. 같은 입력의 반복 생성과 일부러 잘못된 입력을 모두 기록한다. 두 축 비교는 자동 상품 추출이나 규격 제어를 대체하지 않는다. 사용자 목표인 **사진과 규격으로 실제 상품의 형상을 제어한 생성**은 별도의 개발·실물 검증이 계속 필요하다.

출원서의 사진 영역과 규격 비율 비교 취지를 검토하는 개발 기능이다. 자동 영역 추출을 구현했거나 청구항 전체를 완성했다고 설명하지 않는다. [출원 대응표](patent-implementation-map.md), [규격 우선순위](dimension-product-priority.md)를 함께 읽는다.
