# aiadcast 상용 앱 설계 — 소비자 보호·범용 상품·모델 진화

작성: 2026-10-09. 사용자는 Google Play Console과 OpenAI 프로젝트를 직접 관리할 수 있다고 확인했다. 기존 앱·서버 소스는 없으며 결제는 사용자 설명상 테스트 단계다. OpenAI 결제 약 5달러·잔액 약 2달러는 사용자 제공 정보이고 계정에서 직접 조회하지 않았다.

출시 제안 요금·KRW/USD 안내·재시도 포함 원가 가정은 [가격 검토](pricing-strategy.md)를 참고한다. 제안 요금은 실제 판매/스토어 등록 가격이 아니며 공급사 최신 단가를 재확인해야 한다.

## 1. 목표와 현재 상태

목표는 모든 실물 상품의 실제 모습을 보존하면서 광고 이미지와 영상을 제작·수정하는 모바일 앱이다. 포장재는 첫 검증 품목이며 고정된 사업 범위가 아니다.

현재 실행되는 것은 웹 편집 검증판이다. 이번에 상품 분류·규격 형식을 확장했고, 서버용 이용권 원장과 비용 제어·모델 선택의 **로컬 참조 구현**을 추가했다. 이 코드는 실제 카드결제·Google Play 결제·OpenAI API와 연결되지 않았으며 상용 결제 서버도 아니다. 고객이나 OpenAI 잔액에서 돈을 차감하지 않는다.

## 2. 고객 이용권과 AI 사용료는 서로 다른 돈이다

- 고객 결제: 앱 이용권 구매. 결제사/스토어의 검증된 승인 결과를 받은 뒤 서버에서 이용권을 지급한다.
- 고객 이용권: 생성 작업에 잠시 예약했다가, 정상 결과를 확인하고 사용하기로 선택했을 때 확정 차감한다.
- 서비스의 AI 사용료: OpenAI 등 공급사에 지급하는 비용이다. 고객이 결과를 거절하거나 이용권을 복원해도 공급사 사용료가 자동으로 취소된다고 가정하지 않는다.
- 카드 결제 취소/현금 환불: 이용권 복원과 별개다. 원결제·사용 이력·관계 정책을 확인하고 실제 결제 경로로 처리한다.

현재의 약 2달러 잔액은 제한된 기술 시험에 사용하고, 정해진 상품 샘플과 지출 상한으로 비용을 측정한다. 모델·해상도·입출력·재시도에 따라 단가가 달라지므로 아직 생성 가능 횟수나 영상 단가를 단정하지 않는다. 편집·저장·비율 변경·치수선 이동에는 이미지 생성 API를 다시 호출하지 않는다.

## 3. 제안하는 과금 흐름

1. **요청 전 검토**: 실제 상품 사진, 문구, 가격·규격·언어·출력 형식을 확인한다.
2. **견적 표시**: 어떤 작업이 몇 회/크레딧을 쓰는지 먼저 보여준다. 이미지와 영상 견적을 구분한다. 서버가 확정한 견적에 버전과 만료 시간을 붙인다.
3. **이용권 예약**: 사용 가능/예약 중을 나눠 표시한다. 예약은 확정 차감이 아니다. 잔액보다 많은 동시 요청은 막는다.
4. **생성 및 검사**: 실제 작업 상태를 표시하고, 원본 사진·문구·치수·파일 저장 여부를 검사한다.
5. **검토용 미리보기**: 고객이 ‘이 결과 사용하기 · 1회 차감’처럼 금액이 분명한 버튼을 누를 때 확정한다. 정상 고해상도 결과의 접근 권한을 함께 부여한다.
6. **수정·보관**: 확정한 프로젝트의 문구·규격·배치·언어별 직접 입력과 같은 로컬 편집은 추가 이미지 생성 과금 없이 제공한다.

미확인 미리보기는 일정 시간 뒤 예약을 해제한다. 예: 24시간은 출시 전 확정할 운영값이며 현재 자동으로 고객에게 적용한 정책은 아니다. 자동으로 고객 동의를 간주하여 차감하지 않는다. 미리보기는 서버에서 제한된 해상도/워터마크로 제공하고, 원본 결과의 무제한 사전 다운로드는 허용하지 않는다.

| 상황 | 고객 이용권 처리 | 서비스 처리 |
|---|---|---|
| 생성 실패, 시스템 오류, 저장 실패 | 확정 차감하지 않고 예약 해제 | 입력값 보존, 재시도 또는 이용권 복원 안내 |
| 원본과 다른 상품·잘못된 인쇄·누락된 필수 규격 | 검사에서 막으면 예약 해제, 확정 후 확인되면 복원 | 원본/입력/결과 증거로 결함 판정, 제품 보존 경로 수정 |
| 홍보 문구 오타 | 해당 문구를 무료 직접 수정. 서비스 결함으로 결과 사용이 불가능하면 복원 | 상품과 배경을 다시 생성하지 않고 텍스트만 재출력 |
| 통신 끊김·중복 클릭·결제 통지 재전송 | 같은 작업/영수증은 한 번만 처리 | 작업 ID·영수증 ID·DB 트랜잭션으로 중복 방지 |
| AI 요청이 시간 초과되어 성공 여부 불명 | 고객에게 재결제를 요구하지 않음 | 공급사 작업 ID/요청 로그부터 조회. 무작정 동일 요청 재생성 금지 |
| 취향과 다른 미리보기 | 사용 확정 전이면 예약 해제 | 요청 조정 후 새 미리보기는 사전 안내된 체험/사용 제한 적용 |
| 확정 후 고해상도 다운로드 실패 | 같은 결과 재다운로드에 재차감하지 않음 | 저장소 복구, 결과 유실 시 이용권 복원 |
| 카드/스토어 환불 요청 | 이용권 복원과 별도로 처리 | 원결제 취소·환불 처리와 이용권 조정 일관성 보장 |

‘환불 및 취소 불가능’ 같은 기존 화면 문구를 그대로 복제하지 않는다. 실제 상품·지역·결제 방식에 맞는 고지와 환불 절차를 정한다. 이용권 복원을 카드 환불로 표시하지 않는다.

## 4. 품질 판정은 단계별로 한다

- 원본 보존: 이미지 파일 체크섬·원본 참조·마스크 버전·변환을 기록한다. 상품을 생성형 모델로 다시 그리지 않는 합성 모드를 기본으로 한다.
- 문자: 사용자가 확정한 문자열을 글꼴로 출력한다. 입력 원문/번역의 문법 오류와 이미지 생성기의 글자 깨짐은 다른 문제이므로 둘 다 점검한다.
- 치수: 요약과 치수선은 같은 구조화 값에서 그린다. 필수 값과 단위를 검사한다. 사진 위 선의 의미와 실제 형상 정확성은 별도 검토한다.
- 파일: 출력 파일 생성, 저장, 재접근 확인 후에만 미리보기 준비 상태로 바꾼다.
- 자동으로 판정하지 못하는 상품 왜곡·가독성·주관적 품질은 고객의 미리보기 거절 또는 결함 신고를 받는다. 모든 결함을 AI가 100% 자동 판정한다고 약속하지 않는다.
- 고객의 신고가 있으면 입력·원본·결과·사용자 확정 문구·모델 버전을 비교할 수 있도록 보관한다. 신고만으로 무제한 새 생성 요청을 실행하지 않는다.

## 5. 비용이 폭증하지 않게 하는 구조

예약 중인 공급사 비용까지 합산한 프로젝트/기간 한도, 사용자별 요청 제한, 동시 작업 제한을 둔다. 한도에 이르면 추가 호출을 중지하고 고객 예약을 해제하거나 상태 확인 후 안내한다. 고장 난 기능에 고객이 계속 돈을 내게 하지 않는다.

- 무료 직접 수정은 이미지 API 호출 없음.
- 새 배경 생성·영상 생성처럼 실제 새 연산이 필요한 작업만 별도 견적.
- 공급사에 제출할 원본은 필요한 것만 전송. 개인정보·연락처가 필요 없는 작업에 전체 프로젝트를 보내지 않는다.
- 같은 입력의 캐시는 사용자 권한·버전·수정 범위를 확인한 뒤 재사용하고 사용자 간 비공개 자산을 섞지 않는다.
- 재시도는 상한을 두고, 한도 초과 시 실패 처리·예약 해제. 고객에게 서비스 오류 수정 비용을 자동 전가하지 않는다.
- 공급사 가격/실제 사용량은 별도 원장에 기록한다. 내부 예상 비용 한도는 공급사의 강제 청구 상한과 다르므로, 추정 초과분도 숨기지 않고 기록하고 다음 호출을 차단한다.

## 6. 모든 실물 상품을 위한 제품 구조

카테고리는 편집 엔진의 제한 조건이 아니라 문구·규격·촬영 검증 기준을 고르는 정보다.

- 포장재, 식품·음료, 뷰티·생활용품, 전자제품, 의류·패션잡화, 가구·인테리어, 산업용품, 기타 실물 상품.
- 공통 데이터: 상품 ID, 원본/추가 사진, 마스크, 브랜드, 상품명, 소재, 사용자 확인 장점, 언어별 문구, 출력 설정.
- 규격 표시 방식은 소비자가 ‘표시 안 함 / 규격 요약만 / 요약과 치수선’ 중 선택한다. 치수를 숨겨도 원래 입력값과 상품 사진을 보관하며, 프로젝트 재열기와 출력에서도 같은 선택을 유지한다. 표시 변경에 이미지 생성 API를 호출하지 않는다. 원본 사진·홍보 문구에 이미 들어 있는 숫자를 지우는 기능과는 구분한다.
- 이번 편집기에서 선택 가능: 직육면체(가로·세로·높이), 평면(가로·세로), 원통형(지름·높이), 치수 없음. 모두 원본 사진을 유지한다.
- 후속 속성 구조: 무게·용량·사이즈·모델번호·재료/성분 등 값·단위·출처·사용자 확인 상태를 별도 필드로 저장. 사용자가 주지 않은 효능·인증·강도·방수·가격·배송 사실을 임의로 만들어내지 않는다.
- 카테고리 선택만으로 모든 상품의 배경 제거·금속 반사·투명 유리·의류 주름·복잡한 형태가 완벽히 처리되는 것은 아니다. 품목별 실제 자료로 검증하고 지원 수준을 공개한다.
- 3차원 형상 재구성이 필요하면 도면·다각도 사진과 품목별 형상 모델을 별도 사용한다. ‘원본 유지 합성’과 ‘새 형상 재구성’을 섞지 않는다.

## 7. 모델이 바뀌어도 계속 발전하는 방식

모바일 앱 → 자체 서버 → 작업별 제공사 어댑터 → 검증 → 원본/텍스트/치수 합성 → 편집 가능한 프로젝트 순으로 분리한다.

이미지 생성, 배경 제거, 번역, 영상 생성에 같은 모델 하나를 억지로 사용하지 않는다. 작업별 기능·가격·지연·해상도·지역/계정 지원 상태를 모델 등록부에 기록한다. 실행한 작업에는 공급사, 정확한 모델 ID/리비전, 어댑터 버전, 프롬프트/템플릿 버전, 비용, 품질 검사 결과를 남긴다.

새 모델은 기존 모델과 고정된 실제 상품 테스트 세트로 비교한 뒤 단계적으로 적용한다. 상품 보존, 문자·규격, 속도, 성공률, 단가, 영상 흔들림을 평가한다. 기본값을 무조건 ‘최신’으로 자동 교체하지 않는다. 품질이 나빠지면 이전 경로로 되돌릴 수 있게 한다. 서버 설정 교체로 가능한 변경과, 새 편집 기능 때문에 앱 업데이트가 필요한 변경을 구분한다.

API 키는 서버의 비밀 설정에만 보관한다. 앱 소스나 HTML·모바일 번들에 키를 넣지 않는다. 현재 프로젝트는 비밀키나 실서비스 연결을 요구하지 않는 검증판이다.

## 8. 광고 영상은 두 단계

1. **원본 보존형 상품 영상**: 실제 상품 사진에 이동·확대/축소·컷 전환·자막·로고·배경음악을 합성. 사진에 없는 상품 면을 새로 만들지 않아 첫 검증에 적합하다. 편집 가능한 시간축과 이미지 프로젝트를 연결한다.
2. **생성형 광고 영상**: 생성 모델에 배경·장면 움직임을 맡기고 프레임별 상품/로고/문자 일관성을 검사한다. 모델에 따라 상품이 변형될 수 있어 동일성 보장을 별도 검증한다. 제공사 영상 API의 계정 접근·해상도·길이·정책·단가를 확인한 뒤 연결한다.

정지 이미지의 7가지 비율(1:1·4:5·3:4·9:16·2:3·16:9·1.91:1)은 편집 검증판에 구현했다. 후속 영상은 9:16 릴스/쇼츠, 1:1, 16:9 등을 별도의 영상 템플릿으로 확장한다. 영상 길이·해상도·생성 횟수에 따라 이미지와 다른 사전 견적을 보여준다. 영상 기능은 이번 코드에서 실제 생성·내보내기까지 구현된 상태가 아니다.

## 9. 별도 Google Play 앱으로 출시하기 — 사용자 결정 반영

2026-10-09 사용자가 외주업체의 MVP와 분리한 신규 앱 출시를 선택했다. 기존 앱을 업데이트하는 이전 계획은 이 결정으로 대체한다. 기존 MVP는 사용자가 기술보증기금 대출용으로 제작했다고 설명했으며, 이번 개발에서 기존 앱·홈페이지·서버를 변경하거나 그 등록을 사용하지 않는다.

1. guyhan76의 비공개 `aiadcast-next` 저장소로 신규 소스·변경 이력·검증 결과를 직접 관리한다. 로컬 Git 저장소를 준비했으며 원격 생성/권한 연결은 아직 미완료다.
2. 신규 앱 ID와 서명, 별도 회원·저장소·AI 프로젝트·이용권 원장을 사용한다. 개발/시험/운영 환경을 분리하고 외주 MVP의 API 키·DB·서명키를 재사용하지 않는다.
3. 실제 원본으로 AI 생성·배경 분리·영역 편집·다국어를 검증하고 서버 저장/인증/작업 복구를 연결한다.
4. 새 앱의 디지털 상품 결제 정책을 확인해 적절한 결제 경로와 서버 영수증 검증·환불·중복 통지 처리를 구현한다. 기존 카드 결제 테스트 화면만으로 새 앱 출시 결제를 충족한다고 보지 않는다.
5. 신규 앱의 서명된 AAB로 내부/비공개 테스트를 진행하고 실제 기기·데이터 보안 고지·개인정보 처리·장애 복구를 검증한다.
6. 계정에 적용되는 테스트 요건과 Play 심사, 대표자의 출시 결정을 거쳐 별도로 공개한다. 기존 앱 승인이 새 앱의 승인으로 이어지는 것은 아니다.

신규 앱의 제안 식별자는 `com.selluplabs.aiadcast.next`다. 실제 등록/서명/AAB는 아직 생성하지 않았다. 세부 소유권·계정·출시·백업 절차는 [독립 관리 계획](independent-app.md)을 따른다. 기존 회원·이용권은 자동 이전하지 않는다.

## 10. 이번 코드와 운영 단계의 경계

- `server/billing.mjs` + SQLite: 이용권 예약/확정/해제/결함 복원, 중복 방지, DB 트랜잭션, 공급사 비용 예약/기록, 제한된 재시도, 불확실 요청 정지.
- `server/model-router.mjs`: 명시된 모델 버전·기능·평가 승인 상태 선택. 실제 모델 등록과 API 어댑터는 비어 있다. 테스트용 모델 이름을 실제 서비스 이름처럼 사용하지 않는다.
- `src/product.ts`: 카테고리와 규격 유형, 기존 프로젝트 파일 호환.
- 프로덕션에 필요한 추가 작업: 인증/권한, 서버 서명 견적, 결제사·스토어 영수증/웹훅 서명 검증, 실제 품질 검사, 결과 접근 권한, 작업 큐·outbox, 주기적인 만료/대사, 모니터링, 백업·복원, 환불/차지백 처리, 고객 문의 절차.
- 원장 메서드는 신뢰된 내부 서버 코드 전용이다. 클라이언트가 요청 금액·품질 통과·구매 검증·결함 승인 값을 직접 지정하도록 HTTP에 연결하면 안 된다.
- `shouldDispatch:false`는 같은 시도 재실행을 막는 계약이다. DB와 공급사 요청 사이의 장애는 요청 ID와 공급사 상태 조회로 조정해야 한다. 이것만으로 외부 API의 정확히 한 번 실행을 보장하지 않는다.
- 내부 테스트 결제는 실제 카드 결제나 현금 환불을 발생시키지 않는다.

## 추가: 소비자가 고르는 이미지 제작 방식

사진 업로드 단계에서 `original`(기본)과 `creative`를 고른다. 원본 보존은 원본 자산을 상품 레이어로 합성하고, 창작은 첨부 사진을 시각적 참고 자료로 사용해 새로운 상품 콘셉트를 만드는 별도 작업이다. 창작 결과를 원본과 동일한 상품이라고 표시하지 않는다. 원본 파일은 두 모드 모두 보관하며 생성 자산은 후속 구현에서 별도 자산/버전으로 저장한다.

`src/generation.ts`에 제작 의도 검증과 요청 계약을 추가했다. 모드, 보호 여부, 원본 체크섬/역할, 창작 요청 문구, 상품 분류, 규격 값/단위, 규격 표시 여부를 분리한다. 규격 표시가 꺼져 있어도 창작 요청의 치수는 검증·보존한다. 치수 기반 창작은 형상·치수를 정확히 재현하는 설계 기능이 아니다.

모델 등록부의 `image-product-concept` 기능은 상품 보존을 약속하는 요청에서는 선택할 수 없게 했다. 실제 모델/어댑터는 아직 없으며, 현재 검증판은 모드·요청 내용 저장만 지원한다. 참고 사진을 생성 결과로 표시하거나 원본 PNG를 새로 생성한 결과처럼 내보내지 않는다.

실제 API를 연결할 때 서버는 제작 모드까지 포함한 입력 해시와 견적을 고정하고, 고객이 제작 방식을 바꾸면 새 작업 견적을 확인하도록 한다. 라디오 선택 자체는 유료 생성 요청이 아니다. 규격 표시만 바꾸는 작업은 기존대로 재생성하지 않는다.

## 광고 출력 비율 연결

- `src/formats.ts`가 비율·최종 픽셀·활용 예시의 공통 정의다. `src/layout.ts`는 정사각/세로/가로 배치를 담당하고 원본은 균등 배율로 전체를 맞춘다.
- `buildGenerationRequest`는 원본/창작 모두 output.format, width, height를 포함한다. 서버의 요청 해시와 견적에는 이 출력 설정도 포함해야 한다.
- 모델의 지원 크기와 최종 광고 크기를 구분한다. 공급사가 지원하는 생성 크기로 배경 또는 참고 결과를 만든 뒤 최종 캔버스에 합성한다. 원본 보존 모드에서 상품을 목표 비율에 맞춰 늘이거나 잘라서는 안 된다.
- 이미지 크기 변경·로컬 재배치는 AI 호출이 필요 없다. 추가 생성이 필요한 배경 확장 등은 별도 견적·확인 흐름으로 연결한다.
- 현재 비율 선택·재배치·PNG 출력은 구현되었으며 유료 AI 호출, 자동 매체 게시, 영상 출력은 연결하지 않았다.

## 규격 없는 업종 광고 확장

- 자동차·교육·보험·서비스 분류는 규격 없음(specType=none)이 기본이다. 다른 카테고리도 명시적으로 끌 수 있다. 기존 치수는 로컬 편집 이력/백업에만 남고 생성 요청의 specifications는 비운다. 치수선·규격 요약 표시 플래그도 false로 만든다.
- 규격을 쓰지만 숨긴 경우와 규격을 아예 쓰지 않는 경우를 구분한다. 사용 중인 치수는 계속 검증하지만 규격 없는 광고는 오래된/빈 치수 값으로 차단하지 않는다.
- 교육·보험·서비스의 직접 구성은 문구·배경만으로 내보낼 수 있다. 사진이 없을 때 상품 자리 안내를 출력하지 않고 문구 중심으로 배치한다. 사진을 넣으면 원본을 그대로 합성한다.
- 생성 요청은 service / physical-product를 구분한다. 서비스는 compose-ad 또는 image-ad-creative 작업을 사용하며 source=null을 허용한다. 사진 없는 창작에는 광고 설명이 필요하다. 서비스 광고에 ‘동일 실물 상품’이라는 주장을 붙이지 않는다.
- 실제 차량/상품의 보존 작업은 원본 사진을 계속 요구한다. 서비스 업종을 추가한다고 자동차 원본 사진 없이 동일 차량을 재현할 수 있다고 주장하지 않는다.
- 일반 광고 요청은 이미지·문구·업종 정보를 저장하는 단계다. 생성 API, 자동 번역·보험 조건 검증, 실제 광고 매체 전송은 아직 연결하지 않았다.
