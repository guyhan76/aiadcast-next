# aiadcast 신규 상용 앱 — 셀업랩스 독립 관리

결정일: 2026-10-09. 사용자는 외주 MVP와 분리해 새 앱을 운영하고 검증 후 Google Play에 별도로 등록하기로 했다. 저장소 소유자는 회사 조직이 아니라 **guyhan76 개인 계정**으로 최종 정정했다.

## 이번에 분리한 것

- 신규 코드: `/workspace/aiadcast-next`의 독립 Git 저장소. 회사 홈페이지 저장소 및 외주 MVP 코드를 포함하거나 수정하지 않는다.
- 원격 저장소 목표: `guyhan76/aiadcast-next`, **비공개**. CODEOWNERS는 guyhan76을 지정한다. GitHub 접근 권한과 보호 규칙은 원격에서 따로 확인해야 하며 이 파일만으로 강제되지는 않는다.
- 기존 Play 앱: `kr.co.beehivecorp.aiadcast`. 회사 홈페이지의 앱 링크에서 확인한 값이며 Play Console 직접 검증은 아직 하지 않았다.
- 신규 Play 등록용 식별자 제안: `com.selluplabs.aiadcast.next`. 기존 앱과 다르다. 아직 Android 프로젝트/AAB 생성이나 스토어 식별자 등록은 완료하지 않았다. 최초 업로드 전에 이름·식별자·소유자를 확정한다.
- 개발·별도 시험 설치는 `.dev`, `.staging` 식별자로 구분한다. **새 Play 앱의 내부/비공개/프로덕션 트랙은 모두 같은 등록용 식별자를 사용**한다. `.staging` 앱을 올려 나중에 정식 앱 식별자로 바꾸는 흐름이 아니다.
- 원본 MVP 회원·이용권·결제 이력은 신규 앱에 자동 연결하거나 옮기지 않는다. 신규 회원·프로젝트·이용권 원장을 별도로 시작한다. 기존 데이터 이전을 원하면 별도 요청과 데이터 접근 검증으로 다룬다.

외주업체의 접근 권한을 실제로 제거했거나 클라우드 리소스를 생성한 것은 아니다. 현재 적용 범위는 코드 저장소, 분리 설정, 점검 도구와 운영 계획이다.

## 셀업랩스가 직접 보유할 항목

| 항목 | 관리 방법 | 현재 상태 |
|---|---|---|
| 소스·변경 이력 | guyhan76의 비공개 저장소, 독립 Git 백업 | 로컬 저장소 준비; 원격 연결 미완료 |
| Play 등록·서명 | 대표자 관리 계정에서 별도 앱, 신규 서명/업로드 키 | 계정 직접 관리 가능은 사용자 확인; 신규 앱 미등록 |
| 서버·회원·DB·이미지 저장 | 새 프로젝트, 시험/운영 데이터 분리 | 미연결 |
| OpenAI | 신규 프로젝트·서비스용 자격 증명, 비용 기록 | 미연결; 기존 MVP 키/프로젝트 재사용 안 함 |
| 결제·이용권 | 새 앱 상품 ID, 서버 검증, 별도 원장 | 로컬 참조 원장만 구현 |
| 도메인·메일·복구 수단 | 대표자 또는 회사 관리 계정, 복구 코드 별도 보관 | 소유권/복구 접근 점검 필요 |
| 모니터링·백업·모델 설정 | 셀업랩스 관리 서버에서 버전·비용·오류 기록 | 설계 단계 |

같은 Play 개발자 계정에서도 별도 앱을 만들 수 있으나, 외주업체에 계정 전체 관리자 권한이 있다면 새 앱에도 접근할 수 있다. 새 앱을 만들기 전에 권한 범위를 확인한다. OpenAI·클라우드에서도 프로젝트를 나누는 것과 조직 관리자 권한을 분리하는 것은 다르다. 기존 MVP 업무에 영향을 주는 권한 변경은 대상과 영향을 확인해 별도로 진행한다.

개인 계정을 사용하더라도 대표자가 복구 이메일·2단계 인증·결제 정보·서비스 계정의 관리권을 보유해야 한다. 협업자는 필요한 저장소/프로젝트 권한만 부여하고, 개발업체 개인 계정만으로 빌드·배포가 가능한 구조를 피한다. 비밀번호·API 키·서명 파일은 채팅/소스/다운로드 ZIP에 넣지 않는다.

## 실행 가능한 분리 점검

`config/independence.json`에 새 앱 ID와 local/staging/production 환경을 정의했다. 미생성 리소스는 `null`, 소유권 확인은 `false`로 남겼다. 확인하지 않은 작업을 완료 처리하지 않는다.

```bash
npm run check:isolation
npm run release:status -- internal
npm run release:status -- production --strict
```

- 첫 명령은 앱 ID 충돌, 기존 MVP 연결 허용, 환경 간 DB/저장소/AI 프로젝트 재사용, 시험 환경의 실제 결제 설정 등을 검사한다.
- 새 서버의 키는 `AIADCAST_NEXT_<환경>_OPENAI_API_KEY`만 사용하도록 바인딩을 분리했다. 일반 `OPENAI_API_KEY`나 MVP 키로 대체하지 않는다. 실제 API 어댑터 연결 시 시작 경로에서 이 검사를 호출해야 한다.
- 출시 보고서는 필요한 증거가 없으면 미준비 상태와 남은 항목을 출력한다. `--strict`는 미준비 상태에서 종료 코드 1을 반환한다. 실제 배포를 실행하거나 Google Play 승인을 보장하는 도구가 아니다.
- `config/release-evidence.json`에는 완료한 검사의 산출물, 검토자, 날짜를 기록한다. 테스트와 실기기 확인 없이 상태만 바꾸지 않는다.

## 원격 저장소 연결

기존 회사 홈페이지 저장소의 Git 읽기는 성공했다. 신규 저장소 주소의 Git 읽기는 `Repository not found`, GitHub 계정 API는 `Forbidden`을 반환했다. 저장소가 없거나 현재 인증에서 보이지 않는 상태이며 이 환경에서 새 저장소 생성/비공개 권한 설정을 완료할 수 없었다. 이를 GitHub 전체 접속 실패나 비밀번호 필요로 해석하지 않는다.

1. guyhan76으로 GitHub에 로그인한다.
2. `aiadcast-next` 저장소를 **Private**으로 만든다. README·라이선스 자동 생성 없이 빈 저장소로 만든다. 이미 존재하면 새로 만들지 않고 연결 권한을 확인한다.
3. Codex의 GitHub 연결에서 해당 저장소 접근을 허용한다. 원격 주소와 소유권을 확인한 뒤 이 로컬 저장소의 main을 업로드한다.

새 저장소를 비공개로 만든 후에도 협업자·설치된 GitHub 앱·배포 자격 증명 범위를 확인해야 한다. 외주업체를 새 저장소에 초대하지 않는다.

## 회사가 계속 개선할 수 있는 구조

모바일 편집기, 프로젝트 데이터, AI 작업 서버, 결제 원장, 저장소를 분리한다. 상품·문구·배경·규격의 편집 모델은 특정 AI 모델에 묶지 않는다. 이미지/번역/배경 제거/영상은 각각 교체 가능한 어댑터로 연결한다. 모델 ID·가격·버전·평가 결과를 서버에서 관리해 모바일 앱의 모든 배포 없이도 검증된 모델을 교체할 수 있게 한다. 새로운 사용자 기능은 앱 업데이트가 필요할 수 있다.

모바일 기술은 현재 React/Canvas 편집 엔진을 활용하는 Android 클라이언트를 우선 검증한다. WebView 기반 패키징을 선택하더라도 카메라·파일 저장·공유·로그인 복귀·접근성·앱 종료 후 작업 복구를 실제 기기로 확인해야 한다. 현재 HTML을 포장한 것만으로 상용 앱이 완성됐다고 보지 않는다. 아직 Android 빌드 환경과 네이티브 프로젝트는 추가하지 않았다.

사용자가 말한 ‘가장 진보한 모델’은 후보 모델의 최신 공식 지원 범위와 실제 품질·비용을 비교해 선정한다. 현재 어떤 모델이 최고인지 검증하지 않았고 실제 모델 등록부는 비어 있다. 새 모델을 이름만 바꿔 자동 도입하지 않고 [모델 평가 기준](model-evaluation.md)을 통과시켜 적용한다.

## 출시 순서와 판단 기준

1. **독립 기반:** 비공개 원격 저장소·계정·시험 서버·자산 저장소·비용 한도 연결.
2. **실제 AI 품질 검증:** 실제 상품 사진/규격으로 원본 보존, 배경 분리·부분 수정, 다국어 문구를 검증. 현재 편집 검증판의 미연결 기능부터 완성.
3. **서비스 기능:** 로그인·회원탈퇴·서버 저장·작업 복구·결제 영수증 검증·실패 시 복원을 구현.
4. **Android 내부 테스트:** 새 앱의 서명된 AAB, 실제 기기와 테스트 구매·오류 상황 확인.
5. **외부 베타:** 대상 고객이 실제 업무에서 사용. 중대 결함이 남으면 출시하지 않는다. 성공률·처리 시간·생성당 비용 기준은 실제 측정 후 정하고 증거와 함께 기록한다.
6. **별도 Google Play 등록/공개:** 계정에 적용되는 테스트·데이터 보안·결제·AI 콘텐츠 정책과 심사를 확인한 뒤 대표자가 출시 결정. 기존 MVP 승인이 신규 앱으로 승계되지는 않는다.
7. **영상 확장:** 이미지와 과금 안정화 후 원본 사진 기반 영상, 이후 생성형 영상으로 확대.

모든 오류가 영원히 없다는 보증은 할 수 없다. 대신 출시 전 통과 조건, 장애 복구, 모델 되돌리기, 고객 이용권 보호를 운영 가능한 수준으로 검증한다. 외주 업데이트 비용과 별개로 AI·서버·저장소·스토어 관련 운영비는 남으며 월별 한도와 실제 비용을 관리한다.

## 재현 가능한 백업

`npm run release:package`는 깨끗한 Git 상태를 확인하고 빌드한 후, 커밋된 소스·설치 없는 편집 검증판·Git 이력 번들을 ZIP으로 묶는다. Node/npm/Git/Python 3가 필요하다. `.env`, 결제 DB, API 키, Android 서명키는 포함하지 않는다. Git 번들의 무결성은 `git bundle verify`로 확인한다. ZIP은 공개 배포물이나 APK가 아닌 소스 및 검증판 전달 파일이다.

Git 이력 복원 예시:

```bash
git clone aiadcast-next-source.bundle aiadcast-next
cd aiadcast-next
npm ci --no-audit --no-fund
npm run build
```

API·서버 저장·결제는 실제 서비스가 연결된 이후 별도의 백업/복원 절차가 필요하다. 소스 ZIP만으로 고객 DB와 서버 비밀 설정이 복원되는 것은 아니다.
