# 부분수정 실물 참조 연결과 신발 시안 검수 — 2026-11-08

검토용 PR: https://github.com/guyhan76/aiadcast-next/pull/61

## 발견한 문제와 변경

기존 부분수정은 완성 광고와 마스크만 공급사에 전달했다. 최초 생성에 사용했던 실제 상품 사진이 빠져 있어, 잘못 그려진 제품을 광고 자체만 보고 수정해야 했다.

이번 변경은 기존 저장 작업에서 실제 상품 용도의 사진을 찾아 부분수정 요청에 함께 전달한다. 첫 번째 이미지는 마스크가 적용되는 광고이며 이후 이미지는 제품 근거다. 디자인 참고 사진은 제외한다. 실제 사진 최대 10장을 유지하고, 수정본을 다시 수정할 때도 최초 사진을 이어 쓴다. 이전 형식의 수정 작업은 같은 계정의 원본 작업 이력을 따라 사진을 복구한다. 사용자가 채팅에 올린 사진을 운영 프로젝트에 자동 등록한 것은 아니다.

참조사진의 순서·해시·형식·크기·바이트를 사전 처리에 묶었다. 호출 직전에 다시 검증하고 전송 중 변경할 수 없는 사본을 사용한다. 사진 누락·변조·계정 밖 작업·임의 참조 교체는 호출 전에 거절한다. 추가 고객 입력 화면이나 별도 분석 호출은 없다. 기존 비용 예약, 누적 US$100 정책, 사용량 불확실 시 보류와 중복 호출 방지를 유지한다.

추가 사진은 입력 토큰 비용을 늘릴 수 있다. 기존 500,000 microUSD 예약은 공급사가 보장하는 최대 비용이 아니다. 따라서 `selectiveEditingEnabled`와 `selectiveEditReady`는 계속 false다. 실제 모델의 다중 참조+마스크 호출, 최악 비용 경계, 운영 동시 처리 검증 후에만 활성화 여부를 판단한다.

공식 API 계약 확인: [Create image edit](https://developers.openai.com/api/reference/python/resources/images/methods/edit). 여러 이미지를 전달할 때 마스크는 첫 이미지에 적용된다. 이 문서 확인은 계정별 모델 접근이나 실제 품질의 검증이 아니다.

## 제공된 실제 제품 사진

사진 7장을 육안으로 확인했다. 이 제품에 한정된 기준이며 모든 나이키 신발에 적용되는 규칙이 아니다.

| 항목 | 사진에서 확인한 기준 |
| --- | --- |
| 외측 가죽면 | 큰 검정 스우시, 흰색 패널과 봉제선 |
| 내측 가죽면 | 큰 검정 스우시 없음 |
| 내측 밑창 | 작은 흰색 음각 스우시가 존재하므로 내측 마크를 일괄 삭제하면 안 됨 |
| 혀·뒤축 | 사진에 있는 작은 검정 브랜드 표시 보존 |
| 제품 형태 | 흰색 낮은 갑피, 평평한 흰색 밑창, 흰색 납작 끈, 측면 통풍구 4개 |
| 착용 사진의 역할 | 제품 상세 근거. 사람 없는 광고에 사람·양말·다리를 추가하는 지시가 아님 |

일반 생성 지침에는 특정 브랜드의 로고 위치를 하드코딩하지 않았다. 추가 실물 사진은 사진별 표면·봉제선·마크의 차이를 판단하는 근거로만 사용한다.

## 실제 이미지 검수 결과

대화의 이미지 생성 기능으로 사람 없는 광고 수정 후보 2개를 만들었다. 운영 앱의 유료 마스크 API 호출 결과가 아니다. 기존 문구와 62,760원 가격, 도시 배경을 유지하도록 요청했다.

- 첫 후보 `exec-e71eb260-4f5f-499d-b1ec-076acdfefae2.png`: 통풍구 4개는 보이나 실제 측면 사진보다 높이와 시점에 차이가 남아 추가 수정했다.
- 마지막 후보 `exec-208ef3f3-94d7-4cb3-a61b-830c38ad7059.png`: 실물의 측면 각도와 낮은 형상으로 다시 맞췄다. 사람·양말·두 번째 신발이 없고 외측 검정 마크와 통풍구 4개가 보인다. 주요 문구, 가격, 연락처는 육안으로 대조했다. 정확한 제품 동일성의 최종 합격으로 처리하지 않는다.
- 마지막 후보에는 내측이 보이지 않으므로 **생성 결과의 내측 디자인 보존은 미검증**이다. 사람 없는 이미지이므로 신체·발목 연결도 검증 대상이 아니다.
- 생성된 후보 자체는 선택 밖 픽셀이 변경되어 **엄격한 원본 보존 기준에서 불합격**이다. 눈으로 문구가 같아 보여도 바이트 보존과 같지 않다.

같은 실제 파일과 사진 7장으로 현재 앱의 입력 준비·multipart 구성·최종 합성 함수를 오프라인에서 실행했다. [측정 결과](evidence/selective-product-reference-fixture-20261108.json):

- 첫 입력 광고 + 실제 사진 7장 = 8개 이미지. 첫 이미지/마스크 순서와 참조사진 7장 바이트 모두 일치.
- 941×1672 광고, 검토용 마스크 선택 239,197픽셀.
- 생성 후보 원본은 선택 밖 1,290,667픽셀에서 변경 확인.
- 앱 합성 후 선택 밖 **1,334,155픽셀 중 변경 0**, 선택 안 변경 239,012픽셀, 원본 파일 불변.
- 합성 결과는 메모리에서 검사했으며 광고 파일로 내보내거나 최종 승인하지 않았다. 마스크는 이 사례를 위해 지정했고 자동 제품 분할이 아니다. 픽셀 보존은 제품 비례·합성 경계의 자연스러움에 대한 합격 판정이 아니다.

재현 스크립트: `scripts/check-selective-reference-fixture.mjs`. 실제 원본·후보·참조사진 경로를 인수로 전달한다. 파일 해시와 판정은 JSON에 기록하며 API 호출이나 이미지 파일 수정은 하지 않는다.

## 자동 검사와 남은 검증

새 참조사진 검사 13개: 실제 사진 전달·디자인 참고 제외, 10장 유지·연속 수정, 이전 작업 복구, 누락·손상 차단, 고객 임의 사진 교체 차단, 중복 요청 한 번 처리, 비용 한도·불확실 사용량 보호, multipart 순서와 PNG/JPEG/WebP 원본, 변조·전송 중 변경 차단, 비동기 Cloud 조회.

기존 부분수정 집중 검사 61개도 통과했다. 최종 로컬 도메인 검사에서는 191개 중 132개 통과, 실패 0, 환경 조건으로 59개 건너뜀이었다. 로컬 체크아웃에 있는 검사 범위이며 전체 원격 저장소 검사를 뜻하지 않는다. Cloud 생성 코드 일치, 독립 설정, TypeScript와 웹 빌드도 통과했다. 이 기록은 실제 PostgreSQL 연동·Android 실기기·유료 편집 API·광고 품질 합격을 대체하지 않는다. 전체 원격 검사 결과는 PR의 해당 커밋 검사에서 별도 확인한다.

이전 커밋 `12f9f306`의 집중 브라우저 58개는 통과했으나 GitHub Artifact 저장 용량 초과로 증거 업로드 단계가 실패했다. 해당 작업 전체는 실패 상태이며 스크린샷을 전달할 수 없다. 이 결과를 새 커밋의 검사 완료로 바꿔 말하지 않는다.

운영 병합·배포·DB·키·예산 설정 변경 없음. 검토 후보의 제품 동일성, 선택 경계의 육안 검수, 내측 노출 사례와 실제 공급사 비용 검증이 남아 있다.
