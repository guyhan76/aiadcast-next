# 관리자 상태 조회와 이동 개선 — 2026-10-18

현재 운영 기준은 `860aef4e36a1206267abcbe6e3f3df07c57d553b`이며, 사용자 화면에서 10월 총예산/본인 배정 $5 적용과 사용 $0.5273·보류 0이 확인됐다. 이 수정은 예산·원장·인증·분석 서버를 변경하지 않는다.

## 확인한 원인과 수정

참조 분석의 `상태를 재확인`은 GET을 실행했으나 별도의 진행 상태, 마지막 확인 시각, 값이 같을 때 완료 안내가 없었다. GET 중 잠금을 잡지 않아 연속 클릭도 중복 조회를 만들었다. 상단 운영 정보 새로고침은 별도 요청이므로 상단만 회색인 상태에서도 참조 조회 버튼은 그대로였다. 기존 API 클라이언트의 기본 대기 제한은 30초였으며, 관리자 화면은 이동 시 조회를 취소하지 않았다. 화면만으로 실제 서버 장애를 확정하지 않는다.

- 두 GET에 각각 진행·완료·변경 없음·확인 시각·실패 안내를 제공한다. 실패하면 마지막 성공한 정보를 명확히 구분한다.
- 진행 중 클릭은 동일 요청으로 합치고 버튼을 비활성화한다. 15초 안에 응답이 없으면 해당 조회를 취소하고 재시도를 허용한다. 화면을 떠나면 조회를 취소하고, 늦은 결과는 새 화면 상태를 덮어쓰지 못한다.
- 운영 정보 조회와 참조 조회는 독립된 표시를 사용한다. 조회는 분석 POST나 원장 초기화·배정 변경을 실행하지 않는다. 기존 분석 POST의 저장된 요청 ID와 미확인 결과 복구 정책은 유지한다.
- 관리자 로그인 메뉴가 모바일에서 두 줄로 접힐 때 기존 67px 고정 헤더 밖으로 흘러나오는 문제를 확인했다. 모바일 헤더가 내용 높이만큼 늘어나도록 수정하고 뒤로가기 영역과 겹치지 않는지 검사한다.
- 상단에 뒤로가기·홈으로 링크를 추가한다. 뒤로가기는 직전 앱 화면으로 이동하며, 직접 진입·새로고침 시 홈으로 안전하게 돌아간다. 외부 브라우저 이력으로 이탈하지 않는다. 기존 하단 메뉴도 유지한다.

참조 분석 서버 GET은 `statusReader`만 호출하며 `ledgerFactory`와 분석은 POST 경로에 남는다. 일반 분석 OFF, 별도 참조 승인 10회/$0.30, 10월 일반 생성 $5, 11월 기본값 복귀를 변경하지 않았다.
