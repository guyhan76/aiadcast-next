# aiadcast 한국어·영어 글로벌 출시 계획

작성: 2026-10-09. 사용자는 반복 테스트와 업데이트를 거쳐 기존 외주 MVP와 별개로 Google Play에 출시하고, 글로벌 시장을 목표로 하고 싶다고 밝혔다. 아래는 그 방향을 위한 실행 계획이며 출시·결제·영어 UI 구현 완료를 뜻하지 않는다.

## 권고 방향

한국어와 영어를 지원하는 **하나의 앱**으로 개발한다. 한국 전용 앱을 완성한 다음 글로벌 앱을 별도로 만드는 방식보다 공통 기능·결제·고객 지원을 일관되게 관리할 수 있다. 우선 한국과 영어권 사용자가 참여하는 소규모 비공개 테스트를 진행하고, 출시 기준을 통과한 뒤 한국과 영어권 한 국가부터 공개하는 것을 권한다. 영어권 첫 국가로 미국을 검토하되, 국가별 판매·지원·정책 준비를 확인한 후 확정한다. 현재 배포 국가나 실판매를 활성화하지 않았다.

처음부터 모든 국가·언어·광고 영상까지 동시에 출시하지 않는다. 첫 유료 버전은 실제 사용할 수 있는 정지 광고 이미지 제작·수정·저장에 집중하고, 검증된 운영 기반 위에 국가·언어·영상을 추가한다. 포장재뿐 아니라 실물 상품과 사진·규격이 없는 서비스 광고 경로를 처음부터 유지한다.

## 언어와 결제 통화를 분리한다

| 구분 | 첫 출시 목표 | 동작 원칙 |
|---|---|---|
| 앱 사용 언어 | 한국어 / English | 단말 언어로 초기 설정하고 사용자가 변경한다. 화면·오류·안내·이용권 설명을 함께 번역한다. |
| 광고 문구 언어 | 한국어 / English | 앱 언어와 별도로 선택한다. 번역 초안을 검토·수정할 수 있고 원문과 확정 문구를 보관한다. |
| 결제 가격과 통화 | 출시 국가별 스토어 가격 | Google Play가 제공한 상품 정보와 표시 가격을 사용한다. 앱 언어를 바꿔 실제 결제 국가·통화를 변경하지 않는다. |

예를 들어 한국 Play 스토어 고객은 영어 화면에서도 원화로 결제할 수 있다. USD 안내 가격은 미국 스토어의 실제 등록·조회 가격과 구분한다. 영문을 이미지에 다시 그리는 대신 문구 레이어에 표시하여 번역·오타 수정만으로 상품 사진을 재생성하지 않게 한다.

앱 UI, 광고 문구, 도움말·개인정보·환불 안내, 스토어 소개·스크린샷까지 각각 영어 검수가 필요하다. 글꼴·줄바꿈·긴 영문·통화 표기·상품 단위도 양쪽 언어에서 검증한다. 현재 검증판의 한/영 문구 입력과 요금 안내 전환은 전체 앱 현지화나 자동 번역이 아니다.

## 카드 결제 구현 방향

첫 Android 출시에서는 **Google Play Billing으로 생성 크레딧을 구매하는 흐름**을 기본 설계로 삼는다. 고객은 해당 국가·계정에서 지원되는 등록 카드 등 Play 결제 수단을 사용한다. 앱이 카드 번호를 직접 보관할 필요는 없다.

AI 생성 이용권은 앱 내 디지털 기능 구매에 해당하므로 Play 결제 정책을 기준으로 설계한다. 국가별 대체 결제 프로그램·외부 결제 허용 범위는 별도 조건이 있을 수 있어, 임의의 카드 PG나 웹 결제 링크로 대체하지 않는다. 웹 판매는 추후 별도 결제·환불·세금·정책 검토와 서버 연결을 거쳐 추가한다.

초기는 크레딧 충전형 상품으로 시작하는 것을 권한다. 구독·무제한 상품은 실제 원가와 반복 사용량을 확인한 다음 판단한다. [기존 제안 요금](pricing-strategy.md)은 판매 확정가가 아니며 재시도·오류 복원·스토어 수수료를 포함한 실측으로 확정한다.

구현할 결제 흐름:

1. 앱은 Play 상품 정보로 실제 가격을 표시하고 구매를 요청한다.
2. 서버는 구매 토큰·상품·앱·사용자·구매 상태를 검증한다. 결제 대기·취소·실패 상태에서 크레딧을 지급하지 않는다.
3. 검증된 구매를 원장에 한 번만 지급하고, 선택한 소비형 상품의 승인·소비 처리를 Google 요구에 맞게 완료한다. 클라이언트 성공 화면만으로 잔액을 늘리지 않는다.
4. 재전송·앱 종료·재설치·지연 통지에도 중복 지급되지 않도록 서버 기록과 대사한다. 소비한 크레딧의 잔액은 로그인한 서버 계정에서 복원한다.
5. 환불·취소·차지백 통지를 검증해 원장과 맞춘다. 이미 사용한 잔액까지 포함한 처리 정책과 고객 안내를 마련한다.

이용권 구매와 광고 생성 차감은 별개다. 생성 전 이용권을 예약하고, 검토 가능한 결과를 준비한 뒤 사용자의 승인에 따라 확정 차감한다. 시스템 오류·품질 검사 실패는 예약을 해제하며, 확정 후 확인된 오타·상품 불일치에는 결함 수정/이용권 복원 절차를 둔다. 단순 문구·규격 표시·동일 결과의 재다운로드는 이미지 재생성으로 과금하지 않는다. 이용권 복원은 현금 환불과 다르고, 이미 발생한 AI 공급사 비용은 회사 비용으로 측정한다.

## 개발과 검증 순서

| 단계 | 실제로 완료할 결과 | 통과 근거 |
|---|---|---|
| 1. 한/영 제작 흐름과 실제 AI | 공통 언어 체계, 별도 테스트 서버·사용자 인증·저장, 원본 사진 합성/창작 요청, 문구·배경 편집 | 실물·서비스 양쪽에서 결과를 생성·검토·다시 열기. 원본/문구/규격 보존, 실패 처리, 작업별 비용 기록 |
| 2. Android 내부 테스트 | 새 패키지의 서명된 AAB와 실기기 설치, 촬영·파일 선택·저장/공유 | 앱 종료·네트워크 단절 후 작업 복구, 여러 화면 크기, 파일 접근과 권한 검증 |
| 3. Play 테스트 결제 | 테스트 상품·구매 검증 서버·이용권 원장 연동 | 구매 성공/대기/취소/중복/환불, 잔액 복원, 생성 실패 시 차감 보호 검증 |
| 4. 국내·영어권 비공개 베타 | 마케팅/AI 비전문가가 안내 없이 광고 제작을 완료 | 실제 요청의 품질·원가·완료 시간·수정 성공·사용자 불만 기록, 중대한 데이터/과금 결함 해결 |
| 5. 제한된 국가의 유료 공개 | 실판매 설정, 개인정보·지원·환불·모니터링·복구 준비, Play 제출 | 해당 계정·국가의 최신 정책 확인, 출시 증거와 대표자 검토, Play 심사 |
| 6. 국가·기능 확대 | 검증된 국가/언어 추가, 영상 단계적 제공 | 원가·고객 지원 여력·모델 품질을 다시 검증한 뒤 확대 |

공개 전 기준은 ‘오류가 전혀 없을 것’이라는 보증이 아니라, 정의된 기능과 복구 시나리오의 통과 증거다. 중복 과금·결제 실패 후 지급·원본 소실·다른 사용자의 파일 접근 같은 중대 결함이 남으면 출시하지 않는다. 테스트 인원·기간의 Play 필수 요건은 실제 개발자 계정에 적용되는 최신 조건으로 확인하며 임의의 수치를 필수 기준으로 선언하지 않는다.

새 모델은 등록 즉시 무조건 운영에 적용하지 않는다. 동일 평가 자료로 원본 보존·문구·비용·지연을 검증하고 일부 작업부터 적용하며, 문제가 생기면 이전 모델로 되돌리는 기존 [모델 평가 계획](model-evaluation.md)을 따른다.

## 현재 상태와 이번 확인

- 현재는 직접 사진·문구·배경 편집, 선택적 규격, 업종 선택, 로컬 저장과 PNG/프로젝트 내보내기가 가능한 웹 검증판이다.
- 직전 구현 검증은 도메인 76개, PC/모바일 브라우저 56개 통과였다. 이번 계획 정리에서 같은 검사를 반복 실행하지 않았다. 이는 실제 AI 품질·카드 청구·실기기·Play 승인을 검증한 결과가 아니다.
- `npm run release:status -- production --strict`를 이번에 실행했으며 `readyForSubmission: false`, 종료 코드 1로 제출 준비 미완료를 확인했다. 실제 AI/인증/저장 연결, Android AAB, 영수증 검증, 실기기·비공개 베타·운영 증거 등이 아직 필요하다. 준비되지 않은 항목을 완료로 바꾸지 않았다.
- `server/billing.mjs`는 로컬 원장 참조 구현이다. 고객 카드에 청구하거나 Google 구매 토큰을 검증하는 서버는 아직 아니다.
- 기존 MVP의 Play 승인·테스트 결제와 이번 독립 앱의 준비 상태를 구분한다. 기존 앱·고객 이용권을 자동 이전하거나 기존 공급사 키를 재사용하지 않는다. 원격 저장소 소유자 목표는 사용자가 정정한 `guyhan76`을 유지한다.

## 정책 확인 출처와 한계

2026-10-09에 아래 공식 페이지를 조회했으나 이 환경의 프록시 CONNECT 403으로 본문을 가져오지 못했다. 결제 설계는 일반적인 Play Billing 원칙에 따른 권고이며 최신 지역별 예외·수수료·계정 조건 확인을 완료했다는 뜻이 아니다. 출시 연결 전에 Play Console과 공식 문서에서 재확인한다.

- [Google Play 결제 정책](https://support.google.com/googleplay/android-developer/answer/9858738?hl=ko)
- [Google Play Billing 연동](https://developer.android.com/google/play/billing/integrate)

다음 구현 목표는 **한국어·영어로 실제 광고 한 건을 만들고 저장·수정할 수 있는 테스트 경로**다. 이어 Android 실기기와 Play 테스트 결제를 연결한다. 유료 AI 사용·실판매·공개 출시의 실행 범위와 비용은 연결 단계에서 구체적으로 확인한다.
