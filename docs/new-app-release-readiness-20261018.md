# 신규 앱 별도 등록 준비 — 2026-10-18 코드 점검

외주 앱을 보존하고 신규 앱을 별도 등록한다. 외주 패키지·서명·데이터·결제를 교체하거나 자동 이관하지 않는다. 현재 광고 품질은 실제 동일 입력 비교로 승인되지 않았고 로컬 대체 공급사 성공을 품질 검증으로 대체하지 않는다.

## 실제 구현된 계정·웹 테스트 결제

- `server/email-auth.mjs`: 이메일 인증 요청·명시적 확인·요청 기기의 토큰 교환·세션. SQLite와 PostgreSQL 흐름이 있다. Resend 또는 cloud 메일 연결의 실제 수신 시험은 이번 작업에서 하지 않았다.
- `server/password-auth.mjs`: 서버 세션·암호 해시·권한·시도 제한이 있는 베타 테스트 계정이다. 이메일 소유권 확인은 건너뛰므로 검증된 이메일 가입으로 설명하지 않는다. 기존 베타 회원 수 제한 20명과 신규 계정의 공급사 예산/이용권 정책도 공개 가입 전 검토 대상이며 이 작업에서 확대하지 않았다.
- `server/test-checkout.mjs`, `server/account-providers.mjs`: Toss 테스트 키만 허용하고 서버가 가격·수량을 정한다. 공급사 DONE 응답의 주문·금액·통화·키를 확인한 뒤 고유 구매 ID로 이용권을 지급한다. 승인 응답 유실·중복·원장 장애·재시작·소유권은 대체 공급사 검사 대상이다.
- 현재 신규 앱 테스트 가격은 3개 6,900원 / 10개 19,900원 / 30개 49,900원이다. 외주 화면의 1/3/5개 가격이나 환불 문구를 복사하지 않았다. 이 기록은 새 가격 또는 실제 판매 승인 요청이 아니다.
- 실제 이메일·Toss sandbox·Google Play 구매는 실행하지 않았다. 웹 테스트 결제 성공은 Android Play 결제 완료가 아니다.

## Android 코드에서 확인한 미완료 사항

`android/app/build.gradle`: 기존 후보 applicationId는 `com.selluplabs.aiadcast.next`, 개발판은 `.dev`, 미리보기는 `.preview`다. compileSdk/targetSdk는 36, build-tools는 36.0.0이다. 사용자는 개인 Play Console 개발자 계정 보유를 확인했다. 계정 생성일과 신규 앱 프로덕션 접근 상태는 미확인이다. 최종 등록 ID는 소유자 확인 전 바꾸거나 등록하지 않는다. release 서명은 설정되지 않았고 preview는 debug 서명을 사용하므로 배포용 서명으로 간주하지 않는다.

현재 의존성과 네이티브 코드에는 Play Billing Client, 상품 조회·구매·pending 처리·구매 토큰 전달·consume 흐름이 없다. 서버에도 Play 구매 토큰 검증/상품 매핑/사용자 귀속/중복 지급/consume 재시도 경로가 없다. 기존 외부 브라우저 Toss 테스트 링크를 새 Play 앱의 기본 유료 결제로 연결하지 않는다.

이 환경에는 Android SDK 환경 변수 설정이 없어 APK/AAB 빌드를 실행하지 않았다. 새 서명 키나 외부 계정·스토어 상품도 만들지 않았다. 앱 내 회원 계정 삭제 요청 및 외부 삭제 안내 웹 경로는 코드 검색에서 확인되지 않았다. 실제 사용자 데이터를 삭제하는 검사는 하지 않았다.

## 다음 구현 순서와 필요한 입력

1. **안전한 로컬 구현:** Play 구매 입력 계약·구매 토큰 해시의 고유 원장·서버 상품/이용권 매핑·지급 후 consume 상태를 분리한 서비스와 대체 검증기. 중복 통지, 다른 계정 토큰, pending/취소/거절, 검증 후 장애·지급 후 consume 실패·재접속을 검사한다. 실제 상품 ID·권한 연결 전에는 기능 비활성 상태로 둔다.
2. **소유자 입력:** 별도 등록할 applicationId 최종 확인, Play Console 앱/조직·개인 계정 상태, 승인된 상품 ID와 이용권 수·가격, 라이선스 테스트 계정, 업로드 서명 소유·Play App Signing 방침. 비밀키는 채팅이나 Git이 아니라 승인된 서버/빌드의 보안 연결로 전달한다.
3. **실제 인증:** 신규 앱이 사용할 검증된 메일 발신 주소/도메인, 콜백 공개 URL, 신규 앱 전용 데이터 소유권 확인과 보안 연결이 필요하다. 기존 외주 자격 증명을 복사하지 않는다.
4. **계정 삭제:** 개인정보 보관/삭제 범위·법적 보관 항목·처리 담당자·공개 안내 URL을 정한 뒤 인증된 요청 접수·본인 확인·처리 상태·관련 데이터 삭제 흐름을 구현한다. 요청 버튼만으로 삭제 완료라고 표시하지 않는다.
5. **실제 sandbox/기기 검사:** 승인된 Play 라이선스 테스터와 테스트 상품을 연결한 후 서버 검증·정확히 1회 지급·consume·복원, 새 AAB/실기기 왕복을 확인한다. 트랙 참가만으로 무료 구매라고 가정하지 않는다. 이후 내부 테스트와 별도 승인된 공개 등록을 진행하며 10월 21일 이전 심사 완료를 보장하지 않는다.

이 문서는 코드 현황과 다음 구현 계획이다. 운영 서비스·환경 설정, 실제 결제, Play 제출, 계정/키 생성은 수행하지 않았다. 정책·계약 적합성 및 실제 공개 등록은 별도 확인한다.
