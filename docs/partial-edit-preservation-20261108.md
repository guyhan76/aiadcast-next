# 부분수정 원본 보존 검사 — 후속 개발 2026-11-08

이 문서는 앞선 [광고별 선택 개발](partial-edit-followup-20261108.md)에 이어진 변경과 이번 실행 결과다. 기준 원격 커밋은 동일하게 `f456f84bc874898d37fdcca98a6a6945461a2a34`다. 운영 배포·기능 활성화·새 유료 이미지 호출은 하지 않았다.

## 문제와 변경

실제 광고를 반복 수정하면서 로고 수정에 신발 위치까지 달라지는 문제, 신체·신발의 연결과 원근 오류를 확인했다. 대화의 전체 이미지 편집 결과를 앱의 엄격한 마스크 합성 결과처럼 취급하면 안 된다. 기존 앱 서버에는 선택 밖 원본 픽셀을 유지하는 합성이 이미 있었으므로 재구현하지 않고, 다음 검증과 표시를 추가했다.

1. **결과 파일을 다시 해독하여 검사한다.** 선택 밖 RGBA가 한 픽셀이라도 바뀌면 결과를 통과시키지 않는다. 투명 픽셀에 들어 있는 RGB도 검사한다. 원본·마스크·결과 해시, 크기, 선택 범위, 선택/변경 픽셀 수를 결과 기록에 결합한다.
2. **검사 근거가 없는 결과는 사용확정할 수 없다.** 클라이언트와 서버 양쪽에서 원본/마스크/결과 식별자와 검사 보고서를 확인한다. 원본 보존 검사 기능을 제공하지 않는 구서버에서는 새 부분수정 진입을 막아, 먼저 호출 비용을 낸 뒤 검증 불가를 발견하지 않도록 한다.
3. **아무것도 수정되지 않은 결과는 완료로 제공하지 않는다.** 실제 공급사 사용량이 확인됐을 때 해당 비용은 정상 기록하되, 고객 이용권 예약을 해제하고 `EDIT_NO_CHANGE`로 종료한다. 기존 이용권과 신규 크레딧 모두 검사했다. 공급사 사용량이 불확실하면 기존 비용 보류를 유지하며 자동 재호출하지 않는다. 변경된 픽셀이 존재한다는 사실이 의미 있는 수정 성공을 보증하지는 않는다.
4. **같은 좌표에서 원본과 수정본을 겹쳐 비교한다.** 슬라이더와 수정 범위 확대를 추가했다. 두 이미지는 동일한 좌표 변환을 적용하며 비교·확대에는 생성/확정 호출이 없다.
5. **로고 수정과 자세 변경을 구분하는 생성 지침을 보완했다.** 로고·색상·잡티 수정 시 제품 위치와 신체 자세를 바꾸지 않고, 제품별 안쪽/바깥쪽 디자인을 임의로 복제하지 않도록 했다. 제품 단독 요청에는 몸·양말·마네킹을 추가하지 않으며, 실제 착용 참조가 있으면 자세·접지·원근과 제품 배치를 유지하도록 했다. 이는 프롬프트 지침이며 시각적 정확성 보증이나 새로운 인체 분석 모델 구현이 아니다.

사용자 화면에서는 `선택 밖 원본 보존 확인`과 `신체 구조와 제품 형태는 비교해서 확인`을 함께 표시한다. 검사 기록의 의미 품질 필드는 항상 `not-assessed`이며 인체·제품의 자동 합격으로 변경하지 않는다. 원본 선택·새 사본 저장·선택하지 않은 결과 보존, 누적 100달러 예산, 요청 중복 방지 정책을 유지한다.

## 실제 광고 파일을 사용한 보존 검사

이전 대화에서 생성한 광고와 로고 수정 후보를 **앱의 실제 합성 함수에 입력**했다. 새 모델 호출 없이 941×1672 원본의 작은 사각 영역만 대상으로 검사했다.

- 선택 영역: x=835, y=780, 가로 91, 세로 55. 선택 5,005픽셀 중 실제 변경 4,951픽셀.
- **선택 밖 1,568,347픽셀의 변경: 0개. 원본 파일 해시도 동일하게 유지.**
- 원본 해시: `94aa4543729822d731bda9ad23f662aae8641f9bfcd67f3cb09cf8b806918cbf`.
- 결과 해시: `83b94f3c15e55c60059ed638b3c072cd1788d1ccb56c8f4d31f08e2318694e20`.
- 입력은 이미 있던 이미지 생성 결과다. 실제 앱의 유료 편집 호출, 현재 원장의 실제 비용 조회, 해당 광고의 인체/제품 품질 승인 증거가 아니다. 합격 광고나 새 운영 결과로 제공하지 않았다.

이 검사는 “칠하지 않은 신발의 위치가 함께 바뀌는가”를 픽셀 수준에서 확인한다. 선택 영역 안의 발목 연결, 좌우 제품 구조, 원근의 자연스러움, 합성 경계 품질은 별도 육안 검사 대상이다.

## 남은 사항

- 브라우저가 실행되는 환경에서 입력→생성→선택→부분수정→비교→확정/반려→재다운로드를 확인해야 한다. 구서버 기능 협상과 계정 전환도 포함한다.
- 실제 착용 참조사진을 사용하는 모델 출력에서 신체 연결·좌우 제품 디자인·접지·경계까지 검수해야 한다. 이번 코드 테스트는 이 품질을 통과시킨 것이 아니다.
- 기존 최대 공급사 비용 경계, 큰 이미지 동시 처리/메모리, 운영 DB·실기기 검증은 남아 있다. 새 검사는 최종 PNG를 한 번 더 해독하므로 활성화 전 부하 측정이 필요하다.
- `selectiveEditingEnabled`와 `selectiveEditReady`는 여전히 비활성 기본값이다. 운영 서버·DB·키·배포 설정을 변경하지 않았다.
- 초기 GitHub 반영은 저장소 소유/전송 승인 확인 부족으로 자동 승인 검토에서 차단됐다. 2026-11-08 사용자가 `guyhan76/aiadcast-next` 개발 브랜치 업로드와 검토용 PR 생성을 명시적으로 승인했다. 이 개발본의 제출 범위는 해당 브랜치와 초안 PR이며, 운영 병합·배포·기능 활성화는 포함하지 않는다.
