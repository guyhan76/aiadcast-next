# 규격 상품 1차 검증 기준

사용자 우선순위 확정: 2026-10-10. 이 문서는 개발 목표와 소스 점검 결과이며 기능 구현 완료나 특허 권리범위에 관한 판단이 아니다.

## 첫 번째 목표

실제 상품 사진 + 상품 규격 → 같은 상품의 특징과 규격에 맞는 비례를 반영한 광고 → 대응하는 변에 정확한 치수 표시.

## 첫 실물 시험 자료 확인 — 2026-10-10

- 사용자는 기존 화면의 택배박스 `300 × 200 × 100 mm`가 실측값이 아니라 예시 입력이었다고 확인했다. 해당 값을 실물 검증 정답으로 사용하지 않는다.
- 현재 첨부 경로의 ZIP 10개는 사용자가 생성 사례로 제공한 자료다. 실물 촬영 원본과 확인된 실측값이 짝지어진 시험 자료는 확보하지 못했다. 기존 업로드 화면에 표시된 `18606.jpg` 원본도 현재 작업 공간에서 발견하지 못했다.
- 필요한 자료: 동일 상품의 실제 촬영 사진(정면과 위·옆면이 보이는 사진 권장), 가로·세로·높이와 단위, 내경/외경 여부, 반드시 보존할 로고·인쇄·특징. 박스는 광고 외형과 비교할 외경 치수부터 확인한다.
- 실제 상품과 측정값을 받기 전에는 실물 검증 완료, 원본 동일성 통과, 규격 일치 통과를 기록하지 않는다. 이번 자료 확인 과정에서는 추가 유료 API 호출을 하지 않았다.
- 일반 코드/문서 수정과 테스트에는 개발 환경 재게시를 요구하지 않는다. 네트워크·시크릿·설치/시작 설정이 실제로 바뀌어 적용이 필요한 경우에만 그 변경을 설명한다.

### 후속 자료: 우체국 3호 참조 선정

사용자가 이후 규격표·0호 설명 사진·호수별 조립 박스 사진·③ 표기가 있는 펼친 사진을 제공했다. 첫 대상은 표의 3호 `340 × 250 × 210 mm`와 ③ 펼친 사진으로 선정했다. 내경/외경, 최신 공식 규격, 실제 측정 여부는 미확인이다. 0호 사진을 3호 형상 증거로 섞지 않는다. 가격표의 가격도 최신 판매가로 공표하지 않는다.

`src/box-geometry.ts`와 규격 탭의 `BoxGeometryPreview`에 단일 배율의 등각 투영으로 치수에 따른 직육면체 기준을 구현했다. 이 기준은 사진 재구성/인쇄 매핑 결과가 아니며, 광고 PNG나 원본 사진을 바꾸지 않는다. 모든 변은 입력한 세 수치에서 계산하고 같은 수치로 표기한다. 이 기능의 기하 검사 통과를 실제 상품 사진 검증 통과로 취급하지 않는다.

검증: 도메인 135개 통과(새 기하 검사 4개 포함), 기존 편집 브라우저 26개 통과, 새 기준 미리보기 PC/모바일 2개 통과. 빌드와 diff 검사 통과. 새 브라우저 테스트의 영문 컨트롤 선택자를 실제 접근성 이름에 맞춰 수정한 뒤 재검증했다. 결과 화면: `release/dimension-study/postbox-3-mobile.png`. 추가 유료 API 호출 없음.

남은 입력 연결: 이번 채팅의 인라인 이미지에는 로컬 경로/다운로드 ID가 제공되지 않았고 현재 작업 공간에서도 해당 파일을 찾지 못했다. 보이는 사진의 내용은 분석했지만 원본 픽셀을 앱에 넣을 수는 없다. ③ 펼친 사진과 조립된 3호 사진을 파일 첨부로 받아 원본 데이터와 출처를 연결한 뒤 면별 인쇄 매핑과 비교 검증을 진행한다.

출원서 10-2026-0158120의 [0036]은 규격의 독립 입력과 비율 연산, [0041]은 상품 영역과 규격 비율의 비교, [0047]–[0048]은 사진과 규격을 하나의 생성 요청에 결합하는 방식을 설명한다. 원문을 다시 확인했다. 출원서에 자동 3D 복원의 정확도가 입증되었다고 해석하지 않는다.

## 현재 구현과 차이

- `src/specification.ts`: 정면 사진의 사용자가 지정한 두 변만 비교한다. 10% 허용 오차는 기존 개발 정책이며 이번 목표의 확정 합격 오차가 아니다. 사선 사진과 입체 형상은 검증하지 않는다.
- `src/render.ts`: 입력 데이터로 치수·단위를 그린다. 치수선을 표시하는 것 자체가 형상 교정을 의미하지 않는다.
- `server/openai-image-adapter.mjs`: 현재 원본 모드는 상품 사진을 OpenAI에 보내지 않고 규격도 배경 생성 문맥에서 제외한다. 별도 원본 레이어 합성으로 사진을 보존한다. 상품 사진과 규격을 함께 사용해 형상을 맞추는 이번 목표를 충족하지 않는다.
- 현재 창작 모드는 참조 사진과 규격을 모델에 전달할 수 있으나 새로운 시안을 허용한다. 동일 상품·정확한 비례를 보장하는 경로로 전환 표기해서는 안 된다.
- 실제 유료 시험은 사진 없는 카페 광고였다. 참조 상품과 규격의 결합 기능에 대한 합격 증거가 아니다.

## 구현 순서

1. 치수 축을 명확히 정의한 실물 사진과 실제 규격을 시험 자료로 지정한다. 단순 형상의 상품부터 시작하고, 이후 다른 상품 형상으로 확장한다.
2. 상품 영역·촬영면·원근과 입력 규격의 관계를 확인한다. 사선 사진의 화소 길이 비율을 실물 변 길이 비율로 직접 비교하지 않는다.
3. 원본의 윤곽·로고·인쇄·색상을 보존하면서 규격을 반영할 방법을 구현한다. 단순 사진 늘이기로 로고와 인쇄를 왜곡하거나, 다른 상품을 생성해 성공 처리하지 않는다. 사진과 규격이 충돌하면 임의로 바꾸지 않고 확인을 요청한다.
4. 치수 값·단위·축은 확인된 구조화 데이터로 렌더링한다. 생성 모델이 숫자와 한글을 직접 그리는 방식에 의존하지 않는다. 대응하는 실제 변에 치수선을 배치한다.
5. 원본과 결과를 나란히 비교하고, 동일성·비례·치수 표기·처리 비용을 각각 기록한다. 원본/규격/결과를 함께 저장해 재검증할 수 있어야 한다.

한 장의 사진으로 확인할 수 없는 깊이·숨은 면·곡면은 미검증으로 남긴다. 필요하면 추가 사진·도면·형상 정보를 받아 검증한다. 형상 제어/원근 보정/입체 모델 중 어떤 방식이 적합한지는 실제 시험 자료로 결정하며, 프롬프트 개선만으로 해결했다고 선언하지 않는다.

## 1차 합격 기록

| 항목 | 필요한 증거 |
| --- | --- |
| 상품 동일성 | 원본/결과에서 윤곽, 로고, 인쇄, 색상 등 보존 항목 비교 |
| 규격 반영 | 촬영면·원근을 고려한 비례 검증과 그 방법, 오차, 미검증 축 기록 |
| 치수 표시 | 입력값과 일치하는 숫자·단위, 올바른 변에 연결된 치수선 |
| 일관성 | 같은 입력으로 반복 시험한 결과와 실패 사례 기록 |
| 비용 | 성공뿐 아니라 실패·재시도까지 포함한 공급사 사용량 기록 |

평면 확인만으로 전체 3D 규격 검증을 통과 처리하지 않는다. 자동 시험과 실물 검증을 구분하고, 기금 설명 자료에는 실제 확인된 범위만 제시한다. 규격 없는 서비스 기능과 소비자의 규격 표시 선택권은 그대로 유지한다.
