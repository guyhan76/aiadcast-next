# aiadcast 제품·생성 엔진 설계 초안

상용화·소비자 보호·범용 상품·모델 및 영상 확장에 대한 계획은 [service-roadmap.md](service-roadmap.md)를 따른다. 2026-10-09 특허 전체 24쪽을 수령해 분석했고, 최신 구현 범위는 [출원서 대응표](patent-implementation-map.md)와 [제품 검토](product-review.md)에 기록했다. 아래 초기 설계의 ‘미수령/대조 전’ 설명은 이 기록으로 갱신된다.

## 확인된 출발점

- 사용자 확인: 기존 앱·서버 소스코드가 없으므로 신규 개발.
- 1차 화면: 홈, 사용 방법, 상품·기업 정보 입력, 규격·설명 입력, 카테고리 선택.
- 2차 자료: 업로드 최대 10개 표시, PDF/JPG/JPEG/PNG 허용 안내, 3 MB 제한 안내, 9:16 카드뉴스·2:3 포스터 선택, 대기·완료 화면, 최종 박스 홍보 이미지. 3 MB 제한이 파일별인지 전체인지와 실제 서버 동작은 화면만으로 확인되지 않음.
- 3차 자료: 결과 상세·다운로드, 잔여 이용권·가격, 성공/실패 결제 이력, 마이페이지 v1.9.32, Google Play 설치 화면. 전체 15개 자료 확인 완료.
- 홈페이지에 보관된 실제 결과: 71장, 6개 카테고리. 완성 결과만으로 원본 상품과의 일치도를 측정할 수는 없음.
- 확인된 사업계획서는 규격·실물 사진 결합을 사업의 핵심으로 설명함. 이번에 특허 전체 명세서·청구항 1과 구현 항목의 대조를 수행함. 전체 청구항의 상용 구현이 완료된 것은 아님.
- 현재 앱의 모델·서버·프롬프트 구조는 미확인. 기존 오류의 구현상 원인을 단정하지 않음.

## 여섯 가지 문제를 해결할 기준

| 문제 | 새 앱의 구현 원칙 | 완료 판정 |
|---|---|---|
| 다른 상품으로 바뀜 | 원본 파일을 보존하고 상품을 별도 이미지 레이어로 합성. 상품 보호를 기본값으로 설정 | 배경·언어 변경 후에도 같은 원본 자산과 마스크를 사용. 로고·인쇄·구조를 원본과 비교 |
| 언어 변경 불가 | 앱 메뉴 언어와 콘텐츠 언어를 분리. 문구를 문자열로 저장하고 언어별 편집본 보관 | 한국어↔영어 전환 후 같은 상품·치수·가격·연락처 유지. 문구 직접 수정 가능 |
| 수정 때 전체 재생성 | 배경·상품·그림자·문구·로고·치수선을 별도 레이어로 저장. 변경 이력 보관 | 배경만 변경하고 저장·재열기해도 나머지 레이어 유지. 되돌리기 가능 |
| 실제 상품과 규격이 일치하지 않음 | 실물 사진 보존 작업과 규격 기반 형상 재현 작업을 구분해 검증 | 실물 보존에서는 상품을 새로 그리지 않음. 형상 재현은 도면·다각도 자료·검증 가능한 형상 모델 필요 |
| 한글 오타 | AI가 제안한 문구를 텍스트로 검토·수정한 뒤 폰트로 렌더링 | 사용자가 확정한 문자열과 렌더러 입력이 동일. 글자 깨짐·누락·넘침 확인. AI 번역·문안의 오타까지 자동으로 0이라고 보장하지 않음 |
| 치수 표시 불일치 | 표시 여부·단위·항목·선의 스타일을 명시적 설정으로 저장 | '규격 표시'를 켠 모든 출력에서 필요한 값·단위·치수선이 같은 정책으로 표시됨 |

## 핵심 구조

```text
원본 사진 + 상품 정보 + 치수 + 기업 정보
                 ↓
    대표 상품 사진 선택 / 상품 영역 확인
                 ↓
    원본 보존 + 수정 가능한 상품 마스크
                 ↓
 배경 준비 ─ 문구 작성·번역 ─ 치수 데이터 검증
                 ↓
   레이어 편집기: 상품 / 배경 / 문구 / 치수선
                 ↓
   검토 → 프로젝트 저장 → 7가지 광고 비율 중 선택 → PNG 내보내기
```

### 상품과 배경

- 업로드 원본 파일은 수정하지 않고 자산으로 보관한다. 배경 제거는 별도 알파 마스크에 저장한다.
- 가장자리·투명 용기·반사 금속·구멍이 있는 손잡이는 자동 분리가 어려울 수 있다. 사용자 마스크 보정과 원본 대조 기능을 제공한다.
- 상품 보호 모드에서는 이미지 생성 결과로 상품 내부를 대체하지 않는다. 이동·회전·균등 확대축소를 허용하고, 가로·세로를 독립적으로 늘려 상품을 변형하지 않는다.
- 배경 생성 요청은 상품 규격·배치 정보를 참고할 수 있지만 합성할 상품 자체는 원본 자산에서 가져온다.
- 배경·그림자를 별도로 편집한다. 그림자가 실제 상품의 일부를 덮거나 형태를 바꾸지 않는지 검토한다.
- 상품 자체를 바꾸는 편집은 별도 작업으로 구분하고 이전 버전을 보존한다. 이를 원본과 동일하다고 표시하지 않는다.

### 규격: 표시 정확성과 형상 정확성

1. 입력값을 정확히 표기하는 기능: 숫자·단위·축 이름을 구조화하고, 글자와 치수선을 프로그램으로 그린다.
2. 사진 위의 치수선 위치: 대표 상품의 모서리·변과 연결된 기준점을 저장한다. 첫 검증판은 사용자가 기준점을 확인·조정한다. 원근 때문에 화면상 선 길이가 실제 mm 비율과 같을 필요는 없으며, 선이 어느 축을 뜻하는지 정확해야 한다.
3. 실제 상품의 3차원 형상을 규격대로 만드는 기능: 사진 한 장과 숫자 세 개만으로 모든 상품의 숨은 면·형태를 정확히 복원할 수 없다. 박스는 도면·전개도 또는 알려진 형상과 면별 사진을 사용한 치수 기반 모델을 검토한다. 쇼핑백·파우치·곡면 용기는 별도 형상 모델이 필요하다.
4. 사진의 상품과 입력 규격이 다른 경우, 사진을 임의로 늘리거나 다른 상품을 생성하여 성공으로 처리하지 않는다. 원본 사진 유지 또는 추가 자료로 형상 구성하는 작업을 구분한다.
5. 명세서·청구항을 확보해 구성요소별 대응표를 작성했다. 실제 모델 송수신과 실물 검증이 남아 있어 '특허 적용 완료'로 표기하지 않는다.

### 문구와 다국어

- 제목, 장점, 가격, 설명, 회사명, 연락처를 각각 편집 가능한 텍스트로 저장한다.
- 숫자·단위·전화·이메일·상품 코드·상표는 번역 대상에서 기본 제외한다.
- 한국어·영어를 첫 검증 대상으로 삼는다. 추가 언어는 글꼴, 줄바꿈, 글자 방향과 번역 품질을 확인한 뒤 확장한다.
- 번역은 언어별 초안을 만들고 사용자가 확정한다. 언어가 길어지면 텍스트 영역 재배치·넘침 검사를 수행한다.
- 내보내기 전에 폰트 로딩, 지원 문자, 텍스트 경계, 최소 글자 크기를 점검한다.
- 원본 상품 사진에 인쇄된 글자는 상품 사진의 일부다. 홍보 문구 번역 시 함께 고쳐 쓰지 않는다. 패키지 인쇄 자체의 번역은 원본 디자인 자료를 사용하는 별도 편집 요구사항이다.

### 저장과 부분 수정

프로젝트에는 완성 PNG 외에 다음을 저장한다.

- 원본 파일 식별자·체크섬, 대표 사진, 참조 사진 목록과 용도
- 상품 마스크와 버전, 보호 여부, 배치·균등 배율·회전
- 배경·그림자 자산과 버전
- 언어별 문구, 사용자 확정 상태, 폰트·크기·위치
- 치수 원본값·단위·축·기준점·표시 설정
- 출력 비율, 템플릿 버전, 편집 이력, 마지막 내보내기 버전

언어·가격·연락처·치수 표시 수정은 전체 이미지 생성 작업을 호출하지 않는다. 배경 수정은 배경 자산을 교체하고 같은 프로젝트를 다시 합성한다. AI 요청과 내보내기는 별도 작업으로 관리한다.

## 2026-10-09 구현된 첫 검증판

React/TypeScript 기반 모바일 반응형 웹 편집기다. 독립 실행 HTML과 소스코드를 제공한다. 기존 홈페이지와 별도이며 Android APK나 상용 AI 앱은 아직 아니다.

- 포장재·식품·뷰티·전자제품·패션·가구·산업용품·기타 상품 분류 및 직육면체·평면·원통형·치수 없음 지원.
- PNG/JPG/WebP 사진 1장 입력, 10 MB·3,000만 화소 제한. 원본 바이트·SHA-256·비율 보존.
- 원본 사진의 균등 배율 조정. 상품 사진에 포함된 배경은 유지되며 투명 PNG 입력을 지원.
- 배경색·배경 사진, 한국어·영어 문구, 기업명·연락처를 각각 편집.
- 언어별 문구 별도 저장. 한국어 UI에서 콘텐츠만 언어 전환하며 자동 번역은 미연결.
- 가로·세로·높이 mm 입력, 규격 요약과 치수선의 공통 데이터 사용, 표시 설정 저장.
- 사진 위 치수선 시작·끝 위치 직접 조정. 자동 치수 측정·형상 재구성 기능은 아님.
- 20단계 되돌리기, IndexedDB 기기 저장·다시 열기, 원본 포함 JSON 백업·가져오기.
- 1:1·4:5·3:4·9:16·2:3·16:9·1.91:1 PNG 출력(비율별 픽셀은 README 참고). 잘못된 규격과 문구 넘침은 내보내기 차단.
- PNG는 평면 결과물이며 재편집은 JSON 프로젝트로 수행. 브라우저 데이터 삭제에 대비해 파일 백업 필요.

마스크 보정·자동 배경 제거, 상품 이동·회전, 자유 배치·폰트 조정, 가격·장점 전용 필드, 다중 사진, 자동 번역·AI 배경 생성, 사용자 인증·서버 저장·이용권·결제는 후속 구현이다. 테스트 사진으로 구조를 검증했으며 사용자의 원본 `18606.jpg`와 결과물 간 일치도 평가는 실제 파일을 받은 뒤 진행한다.

## 구현 순서와 모바일 방향

1. 전체 화면 흐름 확인 및 레이어 편집 시나리오 확정.
2. 휴대폰 브라우저에서 확인 가능한 핵심 편집기 검증판 제작.
3. 원본 상품 사진과 규격을 이용한 보존·출력 검증.
4. AI 배경·문구·번역 서버 연결과 사용자 저장소 구현.
5. Android 앱 패키징, 로그인·상품 관리·생성 이력 연결.
6. 이용권·결제·생성 실패 처리·중복 요청 처리와 운영 검증 후 출시.

현재 Google Play 서비스가 있으므로 Android를 첫 대상으로 가정한다. 기존 앱 업데이트로 배포할지 새 앱으로 배포할지는 Play Console 소유 권한과 서명·업로드 키 관리 상태를 확인한 뒤 정한다. 소스코드가 없어도 새 앱 개발은 가능하지만 기존 계정·결제 데이터 이전은 별도 데이터 접근과 이전 설계가 필요하다.

편집기와 저장 데이터는 모바일·웹에서 재사용하도록 분리한다. React/TypeScript 기반 편집기와 React Native 또는 네이티브 호스트 조합은 후보이며, 전체 화면·파일 입출력·폰트 렌더링을 검증한 뒤 확정한다. 새 유료 서비스 계약이나 AI 호출은 아직 수행하지 않았다.

## 실제 검증 자료

- 생성 전 실제 상품 사진과 입력한 정확한 치수
- 해당 입력으로 만들어진 현재 결과 이미지
- 상품의 로고·색·형태 중 반드시 유지해야 하는 부분
- 규격 재현 검증에 사용할 실제 박스 도면·전개도 또는 면별 사진
- 특허 전체 명세서·청구항: 수령·분석 완료, 공식 접수·등록 상태 확인은 별도

현재 홈페이지의 생성 결과 71장은 품질 문제와 목표 레이아웃 검토에 사용할 수 있다. 원본 사진과 짝을 맞추기 전에는 상품 일치도 검증 자료로 충분하지 않다.
