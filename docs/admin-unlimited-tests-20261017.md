# 관리자 이미지 생성 테스트 이용권 면제

사용자 요청: 2026-10-17. 관리자 로그인 후 테스트 이용권을 반복 지급하지 않고 이미지를 생성할 수 있어야 한다.

## 동작

- 인증된 서버 계정의 `role=admin`에만 새 이미지 작업의 이용권 개수 제한과 예약·차감을 면제한다. 0개 잔액에서도 테스트한다. 일반 회원의 이용권 정책은 그대로다.
- SQLite와 PostgreSQL 모두 작업별 `admin_test_jobs` 기록을 보관한다. 기존 작업의 양수 이용권 수량·예약 기록을 변경하지 않는 추가 테이블 방식이다.
- 확정·반려·실패·검토 만료·확정 오류 보정은 해당 작업의 저장된 정책을 따른다. 면제 작업으로 잔액을 증가시키거나 예약 잔액을 음수로 만들지 않는다.
- 관리자 권한은 요청 JSON이나 기기 세션 표시로 부여되지 않는다. 서버가 매 요청에 인증한 역할로 모드를 설정하고 권한 해제 후에는 새 작업을 면제하지 않는다.
- 실제 API 비용, 공급사 사용량, 불확실한 응답의 비용 보류, 서버 예산 한도, 요청 속도·동시 작업 제한, 사람의 검수·확정은 유지한다. 이용권 면제가 공급사 비용 무제한을 뜻하지 않는다.
- 관리자는 같은 입력의 연속 반려 횟수로 차단하지 않는다. 실제 비용·예산 한도와 일반 회원의 반려 제한은 유지한다.

## 앱 표시

서버 응답의 `wallet.unlimited=true`일 때 `관리자 테스트 · 이용권 차감 없음`을 표시한다. 확정 버튼의 차감 문구는 현재 권한이 아닌 작업별 `creditPolicy`와 `creditCost`를 사용한다. 이미 준비된 결과가 있으면 잔액 0개 경고가 결과 검토·저장을 가리지 않는다. 관리자 메뉴의 테스트 이용권 지급 폼 대신 면제 안내를 표시하고 예산 설정은 유지한다.

구버전 서버에서 관리자에게 `NO_TEST_CREDITS`가 오면 서버 업데이트가 필요하다고 안내한다. APK만 교체해서 서버의 차감을 우회하지 않는다.

## 검증 범위

고정된 이미지·사용 비용을 반환하는 공급사 대역으로 검사한다. 실제 OpenAI 유료 호출이나 실제 단말 설치 검사를 수행했다고 설명하지 않는다.

- 잔액 0개인 관리자 작업 35개를 연속 생성·확정하고 잔액 0개, 예약 0개, 공급사 비용 35단위 보관을 확인한다.
- 일반 회원의 위조된 관리자·면제 요청 차단, 관리자 권한 해제 후 캐시된 서비스의 면제 중단을 확인한다.
- 관리자에게도 공급사 미설정·예산 부족 차단을 유지한다.
- 반려·불확실 응답·만료·보정 및 SQLite 재시작 시 잔액과 비용 보존을 확인한다.
- PostgreSQL 계열 SQL 엔진을 사용하는 클라우드 검사에서 서버 재시작 후 작업 면제·결과·확정과 비용 기록을 확인한다. 테스트 연결은 실제 운영 `pg`의 정수 파서와 동일하게 BIGINT·NUMERIC을 처리한다.

서버 소스 반영과 Render 배포 후 관리자 재로그인·실제 이미지 생성 확인이 필요하다. 이 문서는 운영 배포 완료나 실제 생성 품질 검증 완료 기록이 아니다.
