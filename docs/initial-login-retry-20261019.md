# 최초 로그인 설정 조회 복구 — 0.2.47-demo

0.2.46의 로그인/가입 화면은 설정 조회를 10초에 중단하고 한 번만 실패해도 수동 재확인을 기다렸다. 버튼은 동일 API를 새로 호출한다. 앱 코드에 실패 응답 캐시는 없으며, 실제 사용자 요청의 상태/로그는 확보하지 않았으므로 Render cold start는 가설이다.

로그인/가입 화면의 설정 GET만 최대 3회(각 20초, 1초/2초 간격, 약 63초 상한) 조회한다. 네트워크 오류·timeout·408/429/일부 일시적 5xx에 한정한다. JSON이 아닌 일시적 API 응답도 재조회하되, 잘못된 설정 구조와 401/403 등은 바로 실패로 표시한다. 일반 로딩과 재연결 안내를 표시하며 소진 후 수동 재확인을 제공한다. 화면 이탈 시 요청과 예약 타이머를 취소한다. 설정 GET은 no-store로 호출한다.

서버가 검증 가능한 설정을 반환하기 전에는 로그인 폼을 추측하지 않는다. 기존 비밀번호/이메일/초대 방식과 세션 검사·origin 검사·결제 기능은 유지한다. 후속 사용자 요청에 따라 비밀번호 폼의 테스트 모드·이메일 소유 미확인 안내 문구만 삭제했다. 이는 이메일 인증 활성화나 소유 확인 완료를 의미하지 않는다. 결제 설정 조회의 기존 10초/수동 재시도 정책은 그대로다. POST를 자동 재시도하지 않는다.

APK는 기존 패키지/서명으로 0.2.47-demo(code49) 업데이트한다. 서버 후보331da9d는 별도 승인·배포 대상으로, 이 수정 작업에서는 배포하지 않는다. 실제 기기 최초 실행 및 운영 cold start 해소는 아직 검증되지 않았다.

후속 로그인 이동 요청: 일반 로그인 성공은 홈으로 이동한다. 초안의 returnPage는 작업 복구용으로 보존하되 로그인 목적지로 사용하지 않는다. 명시적인 결제 로그인에는 별도 origin/15분 만료/일회성 목적지를 기록하며 로그인 화면을 떠나면 지운다. 오래된 문자열 목적지는 무시한다. 지급 복귀는 기존 주문·동일 계정·영수증 검증을 유지한다.
