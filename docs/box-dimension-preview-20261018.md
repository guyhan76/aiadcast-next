# 박스 규격 핵심 경로 진단 — 2026-10-18

새 사례는 500×350×200 mm 열린 박스다. 기존 22986.png 1회/$0.03 승인과 다른 입력이며 유료 호출하지 않는다. 전달된 23009/23011/23013.jpg는 Library prepare는 성공했으나 공식 materialization 다운로드가 실패하여 이 환경에서 직접 열지 못했다. 부모 스레드가 직접 확인한 사진 설명과 저장소 재현을 구분한다.

## 확인한 결함과 우선 수정

1. GenerationPanel은 검수 광고를 render할 때 dimensionAnnotation을 undefined로 덮어썼다. 생성 전 직접/확대 표시 선택이 첫 검수 이미지에 합성되지 않았다.
2. buildGenerationRequest는 해당 선택이 있으면 공급사 숫자 표시를 끈다. 로컬 후처리를 의도했지만 일반 분석은 OFF이고 후처리 패널은 사용 확정 뒤에만 있었다. 따라서 표시 없는 미리보기와 사용 확정이 가능했다.
3. dimensionPlan은 치수 프롬프트의 전달 기록이다. 이미지 형상의 3D 제약이나 결과 검증이 아니다. '적용한 규격'이라는 카드 제목은 지나치게 강했다.
4. complete-ad render는 생성된 광고를 균일 contain할 뿐 형상을 수정하지 않는다. 전체 광고를 늘이거나 bbox를 500:350에 맞추는 것은 원근 직육면체 보정이 아니다.

수정은 (a) 선택한 후처리가 불가능하면 생성 POST 전에 중단, (b) 검수 미리보기에도 annotation을 유지, (c) 동일 검수 화면에서 배치를 완료하고 그 실제 픽셀을 검수한 뒤 확정, (d) 미완료/누락 좌표는 확정 차단, (e) 카드 제목을 '생성에 전달한 규격'으로 변경한다. 실패/중단 이력은 draft에 보존하고 재로드만으로 재분석하지 않는다. 실제 geometry exactness가 해결됐다는 주장은 하지 않는다.

## 필요한 구조 교정

규격 생성은 자연어만으로 완성 광고를 생성하는 경로와 분리해야 한다.

1. 본체 width/depth/height를 mm 단위 3D 좌표의 단일 원천으로 쓴다. 500:350:200 = 10:7:4. 높이는 바닥~본체 상단이며 덮개를 제외한다.
2. 카메라/단일 축척에서 모든 면과 치수선의 양 끝점을 함께 투영한다. 같은 함수 결과를 미리보기·확정·PNG에 사용한다.
3. 원본 면이 확인된 경우에만 각 면을 개별 UV/projective mapping한다. 기존 closed-cuboid 7점 투영은 열린 박스에 바로 적용할 수 없다. 내부·덮개·두께·인쇄 면 대응이 없으면 자동 보존을 주장할 수 없다.
4. 광고 문구·가격·배경은 제품 geometry와 독립 합성한다. 이미 글자가 들어간 전체 광고를 warp하지 않는다.
5. direct와 inset은 동일 모델/치수선에서 배치만 달리한다. inset을 강제하지 않는다.

`open-box-geometry.ts`는 본체 수치와 명시적 예시 덮개 각도/길이로 만드는 **미연결 기하 계산 모듈**이다. 500×350×200 축 길이, 덮개 제외 높이, 단일 축척, 화면 경계를 domain 검사한다. 참고 사진 재구성도 아니며 실제 광고 경로에 연결된 완료 기능도 아니다.

## 제품 결정이 필요한 경계

원본 면 정보가 없는 상태에서 (1) 치수 기반 열린 박스를 별도 명시된 모드로 제공하고 원본은 비교용으로 유지할지, (2) 실제 인쇄·재질 보존을 우선하여 면 자료 확인 전 형상 재구성을 보류할지 선택이 필요하다. 요청한 답이 오기 전 기하 모듈을 사용자 광고로 자동 대체하지 않는다. 현재 미리보기 차단 수정과 독립 기하 검증은 이 결정 없이 진행 가능하다.

실제 앱 경로의 500×350×200 제품 광고/직접 치수선/PNG 증거는 아직 완료하지 않았다. 좁은 기존 분석 승인을 소비하거나 새 유료 API를 호출하여 채우지 않는다.

추가 대역 검사는 생성 전에 direct를 선택한 500/350/200 입력으로 검수 이미지에 세 숫자가 그려진 것을 확인하고, 사용 확정 후 PNG가 검수 이미지와 바이트 단위로 일치함을 확인한다. fixture 형상은 재구성 증거가 아니므로 파일명에 mock을 명시한다. 기존 '규격 기반 생성' 입력명도 '규격을 AI 참고로 전달'로 명확히 변경한다.
