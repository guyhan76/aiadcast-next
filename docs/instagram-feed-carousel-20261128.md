# 인스타 피드 캐러셀 · 가변 장수

## 사용자 흐름

광고 이미지 만들기에서 **인스타 피드 캐러셀**을 선택한다. 기본값은 4장이고 **2·4·6·8·10장**을 고를 수 있다. 피드용 비율은 **4:5**다. 기존 일반 광고의 1·2·4·6·8·10장 선택은 유지한다.

사진과 상품·서비스 정보, 선택적 추가 요청을 바탕으로 선택 장수 전체의 구성안을 기획한다. 고객은 공통 연출과 각 장의 장면·문구를 검토·수정하고, 실제 장수 및 차감량을 확인한 뒤 생성한다. 첫 장의 후킹, 장면 간 연속성, 마지막 마무리를 장수에 맞춰 배치하며 4장 구성 뒤에 임의의 카드를 덧붙이지 않도록 지시한다.

기본 공용 크레딧은 이미지당 5크레딧이다. 따라서 기존 이용권을 사용하지 않는 일반 계정은 2장 10, 4장 20, 6장 30, 8장 40, 10장 50크레딧이다. 기존 이용권 우선 사용 및 서버에서 확인된 관리자 면제 정책은 기존 `batchPrice` 경로를 따른다.

## 데이터 및 과금 보호

- 계획 요청·응답·승인·생성 배치의 장수가 모두 일치해야 한다. 지원하지 않는 장수, 다른 장수의 구성안, 캐러셀의 4:5 이외 출력은 새 생성 전에 거절한다.
- 계획 요청의 캐시 식별자에 장수를 포함한다. 6장 계획 후 10장을 선택하면 새로운 10장 계획 요청으로 구분한다.
- `count`가 없는 이전 4장 요청은 기존 정규화 표현과 fingerprint를 유지한다.
- 장면과 승인 문구, 전체 계획의 연속성, 원본 참조사진은 순서대로 생성 요청에 전달한다. 프롬프트에서 상품의 형태·비율·색상·소재·브랜딩과 제공된 사실을 유지하도록 지시한다. 이 지침만으로 실제 생성물의 시각적 동일성을 보증하지 않는다.
- 고객 잔액이 부족하면 계획 API 호출 전에 차감 안내를 보여준다. 이미지 생성 직전 서버는 견적을 다시 검사하고, 기존 중복 요청 방지·실패분 복구 처리를 유지한다.
- 개별 저장한 카드는 `requestedImageCount: 1`과 전체 스토리 계획을 함께 보유할 수 있다. 프로젝트 가져오기는 이 기존 형태를 허용하며, 새 캐러셀 생성 단계에서만 견적 장수와 계획 장수를 일치시킨다.

## 서버 가용성 및 한계

이 기능은 기존 `/api/assistant`의 인증·허용 설정·공급사 예산 정책을 따른다. `assistant.available`이 false이면 새 계획을 호출하지 않고 안내한다. 현재 서버는 고객용 생성 모드 또는 공유 예산을 쓰는 일반 회원의 새 assistant 요청을 비활성으로 처리할 수 있다. 이 변경은 그 정책을 우회하거나 계정 권한을 확대하지 않는다. 운영 공개 전 실제 대상 계정의 계획 기능 가용성을 확인해야 한다.

계획 응답이 불확실한 상태로 기록되면 동일 요청 ID의 재시도가 새 유료 호출을 만들지 않는다. 명확한 공급사 429 응답인 경우만 기존 클라이언트 정책에 따라 새 요청 ID를 사용한다.

이 개발 검증에서는 유료 AI 생성, 실제 Instagram 게시 또는 광고 집행을 수행하지 않는다. 실제 이미지의 품질과 제품 동일성은 별도의 승인된 생성 결과로 확인해야 한다.

## 회귀 검증

전용 GitHub Actions 작업 `.github/workflows/story-carousel.yml`에서 다음을 실행한다.

1. 도메인 검사: 허용 장수 전체, 계획·견적 불일치, 개별 저장 카드의 복원, 서버 순서, 중복 요청, 일부 실패 복원, 기존 이용권 및 관리자 정책.
2. TypeScript·웹 빌드, PostgreSQL 변환본 검사, Android 웹 자산 준비.
3. PC와 모바일 브라우저에서 2·4·6·10장 구성·편집·생성·개별 저장 및 재열기, 6→10장 재기획, 이전 장수 응답 거절, 잔액 부족 시 API 미호출.

```sh
node --experimental-strip-types --test tests-domain/story-carousel.test.mjs tests-domain/carousel-submission.test.mjs tests-domain/text-assistant.test.mjs tests-domain/batch-art-direction.test.mjs tests-domain/ad-batch.test.mjs tests-domain/result-set-storage.test.mjs
npm run check:cloud
npm run build
node native/prepare-android.mjs
npm test -- tests/story-carousel.spec.ts
```

단위·브라우저 검사는 모의 공급사와 모의 잔액을 사용한다. 테스트 통과는 실제 유료 생성의 품질, 운영 배포, APK 설치 또는 스토어 등록 완료를 의미하지 않는다.
