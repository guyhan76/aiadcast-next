# 결과 안내 가독성 및 규격 처리 확인 — 2026-10-17

## 기준과 범위

사용자가 Render에 배포하고 실제 광고 생성 성공을 확인한 `0836e087ecdc60a3417a9aa5bc679148057c4af9`에서 시작한다. 이번 수정은 결과 안내의 표시만 변경한다. 생성 프롬프트·요청·저장 형식·결제 및 관리자 정책·사진·광고 이미지 렌더러는 변경하지 않는다. 실제 유료 생성이나 운영 배포는 실행하지 않는다.

## 읽기 어려웠던 이유와 수정

- `.accepted-ad p`의 가운데 정렬이 모든 안내 문단에 전파됐다. 이미지 저장 안내의 직계 문단에만 적용하고 결과 안내는 왼쪽 정렬한다.
- 제목과 작은 메타 문구가 한 행에서 경쟁했다. 제목 아래 별도 행으로 배치한다.
- 기존 규칙 기반 타깃 문장에 규격이 포함되고 제작 의도에 같은 타깃이 다시 포함됐다. 화면의 제작 의도는 상품명과 광고 목적 한 문장으로, 타깃은 별도 구역으로 표시한다. 원래 상세 기획과 추천 근거는 접힌 영역에서 읽을 수 있다.
- 채널은 모바일 한 열·넓은 화면 두 열 목록으로, 검색어는 모바일 두 열·넓은 화면 세 열로 정렬한다. 긴 문구를 잘라 숨기지 않고 셀 안에서 줄바꿈한다.
- 기존 `MarketingPlan`은 수정하지 않는다. UI에서만 요약하므로 생성 지침·저장된 기획·추천 검색어·채널 순서를 보존한다. 앱 언어 전환도 저장된 광고 문구를 번역하거나 새 이미지를 요청하지 않는다.

## 상품 규격과 이미지 규격은 다르다

**규격과 참조 이미지를 결합하는 생성 경로는 구현되어 있다.** 이 결합 자체와 결과의 정확한 실물 형상을 강제·검증하는 것은 별도다. 특허 또는 홈페이지의 결합 기술 주장을 일반적인 모델 한계로 대체하지 않는다. 아래는 현재 코드의 대응이며 출원 원문의 권리범위 판단은 아니다. 이번 검토에서 전달받은 출원서 원문 확인 내용(16쪽 [0047], 21쪽 청구항 1(c))은 규격 수치의 설명형 변환, 속성·타깃·형식 지침, 상품 이미지를 하나의 요청에 포함하는 방식을 설명한다. 현재의 이미지+구조화 정보+프롬프트 결합은 그 기술적 방식과 대응한다. 별도 형상 엔진이 없다는 이유만으로 이 결합을 미구현으로 분류하지 않는다.

| 단계 | 실제 코드와 동작 | 범위 |
|---|---|---|
| 입력 결합 | `buildGenerationRequest`가 사진별 해시/용도, 축별 mm, 소재·속성, 타깃·형식, `creativeDirection.referenceGeometry`를 한 요청에 결합 | 이미지와 규격이 각각 UI에만 있는 것이 아니라 같은 생성 요청에 연결됨 |
| 서버 정규화 | `normalizeGenerationRequest`가 규격·속성에서 타깃/기획을 재구성하고, `GenerationService.submit`이 이미지 바이트·해시·순서·총용량을 검사 | 클라이언트가 보낸 검증 주장이나 이용권 권한을 신뢰하지 않음 |
| 모델 입력 | `OpenAIImageAdapter.generate`가 창작 모드에서 원본 및 참조 이미지 바이트를 multipart `image`/`image[]`로 전송하고 동일 요청의 prompt에 규격·비례·사진 역할·표시 조건을 포함 | 숫자만 적는 경로가 아니라 실제 이미지와 구조화된 상품 정보를 함께 전달 |
| 조건부 입력 검사 | 수동 정면 두 축 비교(`assessReference`), 선택적 촬영면 확인 후 윤곽 비례 검사(`preflightProportions`)에서 불일치면 요청 차단 | 사용자가 확인한 촬영면/범위 및 검출 가능한 윤곽에 한정. 기본 허용 오차 10%, 사선/미확인/복잡한 윤곽은 미검증 |
| 결과 검증·보존 | 공급사 결과의 파일 형식·크기·픽셀 수·요청한 출력 해상도, 클라이언트 해시/메타데이터 검증, 사용자 검수·확정 및 스냅샷 저장 | 파일 무결성/출력 크기 검사이며 상품의 3D 치수 일치 검사와 다름 |
| 자동 정확도 보증과의 구분 | 선택적 원본-결과 비교는 있으나 기본 생성 경로의 결과 상품 자동 분할→축 대응→오차 판정→형상 보정의 닫힌 과정은 없음 | 결합 기능의 결여나 출원 청구항의 미충족을 뜻하지 않음. 자동 정확도 보증은 별도 검증 범위이며 이번에 형상 엔진을 추가하지 않음 |

1. `src/specification.ts`의 `referenceDimensionGuidance`가 실제 상품 사진 해시, 축별 mm 값, 정규화 비례, 규격 표시 여부를 전달한다. 디자인 참고 사진은 실물 형상의 근거에서 제외한다. 450×350×400mm는 가로·세로·높이와 비례 약 1:0.7778:0.8889로 전달된다. 규격 표시를 꺼도 비례 참고는 유지한다.
2. `server/openai-image-adapter.mjs`의 `completeAdPrompt`가 상품 사진과 수치·비례를 함께 참고하고 캔버스 비율과 구분하도록 지시한다. 표시를 선택하면 축·숫자·단위 표기도 요청한다.
3. AI 결과의 입체 형상·동일성·원근·치수 문자가 정확한지 자동으로 보증하지 않는다. `geometryVerified:false`를 유지한다. 화면의 실측값이나 이미지상의 길이를 자동 검출해 목표 비례에 강제 보정하는 단계는 없다. 예쁜 결과만으로 물리적 정확성을 입증할 수 없다.
4. 원본 사진 합성은 원본 형상을 유지하지만 입력 mm에 맞게 상품을 다시 만드는 기능은 아니다. 선택적 고급 규격 비교·박스 투영도 일반 AI 결과의 실측 인증과 구분한다.

**캔버스/PNG 크기는 별도 코드로 정해진다.** 현재 완성형 AI 광고의 요청 크기와 최종 출력은 다음과 같다 (`GENERATION_SIZES`, `src/formats.ts`). 공급사 요청 크기가 그대로 최종 PNG 크기인 것은 아니다.

| 선택 비율 | AI 요청 크기(px) | 최종 PNG(px) |
|---|---:|---:|
| 1:1 | 1024×1024 | 1080×1080 |
| 4:5 | 1024×1280 | 1080×1350 |
| 3:4 | 960×1280 | 1080×1440 |
| 9:16 | 864×1536 | 1080×1920 |
| 2:3 | 1024×1536 | 1080×1620 |
| 16:9 | 1536×864 | 1920×1080 |
| 1.91:1 | 1536×864 | 1200×628 |

`src/complete-ad.ts`의 `completeAdPlacement`는 실제 결과 이미지의 비율을 유지해 전체를 캔버스 안에 맞춘다. 비율이 다르면 여백이 생기며 이미지나 상품을 가로·세로로 늘이거나 자르지 않는다. `src/render.ts`와 `SimpleAdResult`가 이 결과를 PNG로 저장한다. 확대 저장은 새 디테일이나 물리적 정확성을 보장하지 않는다. 완성형 광고에 포함된 문구·치수는 이미지의 일부이므로 무료 수동 텍스트 편집과 구분한다.
