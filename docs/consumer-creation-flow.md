# 소비자 제작 흐름 · 2026-10-13

기존 입력 완료 버튼은 실제 생성이 아니라 저장 후 복잡한 편집기로 이동했다. 업종은 접힌 설정에 있었고 로그인이 없거나 예산이 막혀도 생성 준비 중이라는 일반 메시지와 비활성 버튼만 보였다. 입력 화면을 사용자가 지정한 8개 순서로 다시 구성하고, 창작 캠페인 결과는 간단한 결과 화면으로 연결했다.

1. 산업: 상품·서비스의 모든 기존 세부 업종을 한 선택 목록으로 제공한다.
2. 회사 정보: 접어둔 선택 항목이다. 회사명·전화·이메일·홈페이지를 받는다.
3. 사진: 다중 선택 10장·전체 10MB 제한과 대표 사진 선택을 유지한다. 서비스 사진은 선택이다.
4. 규격: 기본은 없음. 사각/평면/원통과 mm/cm/inch 및 광고 표시 선택을 제공한다. 서비스에는 규격을 만들지 않는다.
5. 상세설명: 이름과 재질·특징·장점·가격·배송 등 사실을 받는다.
6. 광고 문구: 기본 AI. AI 선택은 이미지 생성 모델에 마케팅 제목/설명을 함께 요청한다. 직접 입력은 제목/설명을 그대로 전달하고 준비 단계에서 덮어쓰지 않는다. 문구 선택은 프로젝트에 저장하며 예전 승인 문구는 수동 지침을 유지한다.
7. 목적: 선택하지 않으면 기본 방향으로 시작한다. 홍보·브랜드 신뢰 강조와 추가 요청을 제공한다.
8. 비율: 기본 9:16, 4:5·1:1과 다른 기존 비율을 제공한다. 광고 문구 언어를 별도로 바꿀 수 있다.

광고 생성 버튼의 명시적 요청은 기기 저장 후 결과 화면에서 서버 준비가 확인되면 한 번만 실행한다. 새로고침, 재로그인, 작업 열기만으로 자동으로 유료 공급사 요청을 만들지 않는다. 보관된 진행 작업이 있으면 먼저 복구한다. 결과 파일 검증·수락 전 검토·중복 요청 방지·예약/반려 복원은 기존 원장을 따른다. 결과 확인 후 사용 확정, 이미지 저장을 제공한다. 원본·사진 전용 과거 프로젝트의 고급 편집 경로는 유지하되 기본 소비자 제작에서는 사용하지 않는다.

인증이 없으면 입력을 보관하고 로그인 링크를 제공한다. 이메일 인증 기능이 서버에 설정되지 않은 비공개 베타는 기존 초대코드 로그인 경로를 로그인 화면에 직접 노출한다. 새 공개 회원가입 기능을 구현했다고 주장하지 않는다. 초대 로그인에서도 기기 초안은 해당 계정의 보관 영역으로 옮긴다. 예산·이용권·공급사 준비 문제는 원인을 안내하며 차단을 우회하지 않는다. 사용자에게 API 키나 서버 주소 입력을 요구하지 않는다.

검증은 TypeScript 빌드·도메인 입력/문구 계약·서버 원장 시험과 실제 공개 화면 확인을 구분한다. 브라우저 자동화 스펙은 가짜 공급사 결과를 사용한 입력→생성 요청→수락→다운로드와 로그인/예산 차단 사례로 작성했다. 이 환경의 Chromium 실행 파일 부재 및 다운로드 실패 때문에 자동화 실행은 별도로 확인해야 한다. 이를 실제 OpenAI 광고 품질 검증이나 완료된 화면 테스트로 계산하지 않는다. 앱 서버의 새 생성 결과는 사용자의 기존 인증으로 별도 시험해야 한다.
