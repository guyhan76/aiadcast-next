## 이번 변경

1. 원본·광고 결과 비교창에서 스크롤과 점 선택을 구분한다. 손가락을 누른 순간에는 점을 만들지 않으며, 8 CSS px보다 이동하거나 터치가 취소되면 측정점을 추가하지 않는다. 실제 탭, 마지막 점 취소, 키보드 이동·선택을 지원한다.
2. Android 뒤로가기는 열린 대화창을 먼저 닫는다. Window에 직접 전달한 이벤트의 리스너 등록 순서 때문에 편집 화면까지 이동하던 문제를 수정했다. 닫은 뒤 초점과 본문 스크롤 상태를 복원한다.
3. 비교창 안에 저장 상태를 계속 표시한다. 네이티브 저장 완료, 취소, 오류, 공유 앱 열림을 구분한다. 공유 앱을 열었다고 전송 완료로 표시하지 않는다. 브라우저에서는 다운로드 요청 상태까지만 표시한다.
4. 저장이 진행 중이면 비교 PNG와 사진·규격·측정 기록의 중복 내보내기를 막는다. 기록을 준비할 때도 버튼을 잠그고 원본과 결과의 실제 파일 해시를 확인한다.
5. 비교 PNG의 배경과 텍스트를 흰색·검정 계열로 정리했다. Android 버전을 0.2.17-dev로 올렸다.

수치 비례 비교는 선택 기능이다. 일반 광고 제작 전에 수동 점 선택을 강제하지 않는다. 광고 결과를 자동으로 실물 비례에 맞게 변형하는 기능으로 표시하지 않는다.

브라우저 검사는 Chromium 153, Playwright 1.63을 사용했다. 클라우드 환경의 캔버스 PNG 인코딩이 화면 크기 변경 후 약 6.7초 지연되는 경우를 추적 확인했다. 해당 완료 상태의 검사 대기 시간을 15초로 조정했으며, 고정 sleep이나 실패 재시도로 통과시키지 않았다. 최종 세 파일 회귀 검사는 workers=1로 실행했다.

모바일 터치 검사는 실제 브라우저 터치 이벤트로 스크롤이 발생하고 측정점은 추가되지 않는 것을 확인했다. 실제 탭만 한 점을 추가하며, 터치 취소·끌기·되돌리기·키보드 선택도 확인했다. 320/390/1440px 화면에서 비교창이 가로로 넘치지 않는지 검사했다.

원본·결과 PNG 및 JSON은 실제 생성된 바이트를 해석해 확인했다. 광고 생성 서버는 연결하지 않았고 유료 AI 요청을 하지 않았다. 기본 개발 서버의 `/api/status` 연결 실패 로그는 남으며, 서버 연결 완료로 처리하지 않았다.

## 실기기 확인 순서

1. Android 10 이상 기기에 개발 APK를 설치한다. 기존 작업이 있으면 먼저 프로젝트 JSON을 별도로 저장한다.
2. 상품 사진과 규격을 넣고 광고 편집 화면의 ‘원본과 결과 비교’를 연다.
3. 선택 항목인 ‘상품 비례 수치 비교’를 펼친다. 사진 위를 위아래로 밀면 스크롤되고, 가볍게 누르면 점이 하나 찍히는지 확인한다.
4. Android 뒤로가기로 비교창만 닫히고 편집 내용이 남는지 확인한다.
5. 비교 PNG와 사진·규격·비교 기록을 각각 저장한다. 취소·공유도 시험하고 실제 Files/공유 앱에서 결과를 연다.
6. 프로젝트 JSON 백업·복원, 앱 종료 후 재실행, 사진 선택기·키보드·회전·저장 공간 부족 상황을 확인한다.
