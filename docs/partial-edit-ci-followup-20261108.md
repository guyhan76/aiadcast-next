## 첫 원격 검사

커밋 `29cfb8e1ff2a4e7729998639c0ea255fa3124da4`의 GitHub Actions 실행 `42459706489`에서 격리·Cloud 일치·TypeScript 검사는 통과했다. 전체 도메인 검사는 917개 중 847개 통과, 1개 실패, 69개 건너뜀이었다. 실패로 뒤의 웹 빌드와 브라우저 검사는 실행되지 않았다.

실패는 `creativeCampaignDraft`가 편집용 초안을 열면서 제출용 `prepareCampaign`까지 실행하여 저장된 규격 표시 선택을 바꾸는 문제다. 사진·문구를 보존하는 기존 회귀 사례에서 `dimensions.visible`이 true에서 false로 바뀌었다. 동일 오류를 로컬에서도 재현했다.

## 후속 변경

- 편집용 초안과 제출용 규격 변환을 분리했다. 초안을 열 때 입력값·표시 선택을 유지하며, 이전 이미지의 치수선 배치 증거는 재사용하지 않는다. 실제 제출 시 기존 AI 규격 표시 규칙을 적용한다.
- 없음/본제품/작은 사진 선택을 포함한 회귀 검사를 추가했다.
- 기존 전체 검사와 병렬로 부분수정 브라우저 검사를 실행하는 CI 작업을 추가했다. 공급사 API는 모의 응답으로 대체하며 유료 이미지 호출·배포·운영 설정 변경은 없다. 전체 검사 실패를 통과로 처리하거나 검사를 제거하지 않는다.
- 성공한 편집창 스크린샷과 실패 화면/트레이스를 CI 증거 파일에 보관하도록 했다.

## 후속 검사와 증거 저장 제한

로컬 집중 검사 94개와 TypeScript 검사는 통과했다. 커밋 `614ad5e39a9c192ddb031b09e3a6d0d70184ceb6`의 원격 실행 `42464431323`에서는 웹 빌드와 부분수정 브라우저 **34개가 모두 통과**했다. 원본 선택, 같은 좌표 비교/확대, 중복 요청 방지, 계정 전환, 재다운로드 PNG 바이트 보존을 PC·모바일 브라우저에서 확인했다. 모바일 에뮬레이션 결과이며 Android 실기기 검증은 아니다.

그 다음 스크린샷 4개를 보관하는 단계에서 GitHub의 `Artifact storage quota has been hit` 오류가 발생했다. 따라서 해당 CI 작업 전체는 실패 상태이며, 브라우저 테스트 통과와 증거 파일 업로드 실패를 구분해야 한다. 기존 증거를 삭제하거나 저장 용량을 유료 확장하지 않았다. 테스트 통과 기록은 작업 로그에 남아 있지만 스크린샷 파일은 전달할 수 없다.

추가로 저장된 1·2·4·6·8·10장 각각에서 선택한 이미지 하나만 수정하고 전체 원본을 보존하는 PC·모바일 브라우저 사례 12개를 준비했다. 이 사례는 기존 저장된 광고의 선택·편집 흐름이며 새 이미지 10장을 실제 공급사에서 생성한 시험은 아니다. 실행 결과는 PR 검사에서 별도로 확인한다.

기존 결과 화면 회귀 검사도 확정된 `사용확정 / 부분수정 / 시안반려` 문구에 맞췄다. 검사 항목을 줄이지 않고 세 버튼의 동일 행 배치, 지원하지 않는 서버에서 부분수정 비활성, 체크박스 없는 확정, 반려 후 입력·사진 복구와 중복 반려 방지를 확인한다. 관련 PC·모바일 12개 사례를 집중 CI에 포함했다.

브라우저 동작, 실제 공급사 이미지 품질, PostgreSQL 실연동, Android 실기기와 운영 활성화는 각각 별도의 확인 대상이다. 테스트의 mock 결과를 실제 광고 품질 합격으로 설명하지 않는다.
