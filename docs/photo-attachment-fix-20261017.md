# 사진 첨부·용량 초과 안내 수정

2026-10-17 · Android Preview 0.2.27 · versionCode 29

## 문제와 동작

여러 사진의 합계가 10MB를 넘으면 기존 코드는 선택한 사진을 전부 검증한 뒤 전체를 취소했다. 빈 폼에서 이 오류가 발생하면 미리보기에 사진이 없고, 생성 버튼은 사진을 첨부하라는 일반 오류를 다시 보여줬다. 사용자가 제공한 화면에도 합계 용량 초과 오류와 빈 사진 영역이 확인됐다.

이제 각 파일을 따로 검증하고 수용 가능한 파일은 선택 순서대로 첨부한다. 기존 사진과 같은 선택의 정상 파일을 취소하지 않는다. 예를 들어 6MB 사진 두 장이면 첫 사진은 남고 두 번째 사진은 용량 초과로 제외된다. 뒤에 들어오는 작은 파일이 남은 용량에 맞으면 계속 수용한다. 실제 원본 바이트·상품 인쇄·사진 해시·사진 용도·확정 정보는 보존하며 자동 축소·재압축은 하지 않는다. 최대 10장·실제 파일 합계 10MiB 제한은 기존 서버와 동일하다.

## 화면

- `참조사진 전체 용량이 10MB를 초과했습니다.`를 사진 영역 상단에 빨간 제목, 20~26px 굵은 글씨, 빨간 테두리와 경고 아이콘으로 표시한다.
- 경고에 초점을 옮기고 화면에 보이도록 스크롤한다. 파일명과 합계 초과·개별 용량 초과·읽기 실패·중복·장수 초과를 구분한다.
- 첨부 완료 장수, 미리보기와 현재 합계 용량을 표시한다.
- 첨부가 전부 실패한 뒤 생성 버튼을 누르면 용량 초과 등의 원래 이유를 다시 표시하고 사진 영역으로 이동한다. 사진 없는 서비스 광고는 기존 흐름을 유지한다.

## 검증

사진 읽기·바이트 보존·용량 경계·사진 용도·규격·완성형 광고 요청·소비자 입력 관련 검사 28개가 통과했다. 6MB 두 장과 추가 작은 사진, 손상 파일과 정상 파일의 혼합, 기존 8MB 원본 유지, 중복·장수 제한을 다룬다. 실제 10MiB 사진을 초과로 잘못 계산하던 Base64 패딩 오차도 수정했다. 가짜 공급사로 요청을 보내 실제 원본 바이트와 추가 참조가 서버 검증을 통과하는지 검사했으며 유료 공급사 호출은 하지 않았다.

실제 소비자 입력 폼을 실행하는 DOM 통합 검사 2개도 통과했다. 일부 용량 초과 시 미리보기와 제출 프로젝트에 정상 사진이 남고, 전체 첨부 실패 후 제출하면 기존 용량 이유와 사진 영역 초점이 유지되는지 확인했다. 웹 빌드와 Android 단위 검사 7개, lint 오류 0건을 확인했다. 브라우저 기반 화면 검사는 실행 환경에서 Unix 소켓 생성이 차단되어 완료하지 못했다.

실기기에서 업데이트 설치·사진 선택·실제 광고 생성 확인은 별도 단계다. 공개 서버 배포·Google Play 등록 또는 실사 이미지 품질 검증 완료로 설명하지 않는다.
