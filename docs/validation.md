## 실행 환경

- Node.js 24.19.0 / npm 11.9.0 / 시스템 Chromium.
- `npm ci --cache /workspace/.npm-cache --no-audit --no-fund`: 성공, 잠금 파일 유지.

- `npm run build`: 타입 검사, Vite 빌드, 단일 HTML 생성 성공.
- `npm run dev`: 5180 포트 내부 HTTP 200, 편집 화면 렌더링 및 문구 탭 동작 확인.

## 브라우저 기능 검사

`npm test`: **12개 통과, 실패·건너뜀 0개**. Desktop Chrome 설정과 Pixel 7 화면 설정으로 각 6개 시나리오를 실행했다.

1. 상품 사진 업로드 → 문구·언어·배경·비율 변경 → 백업 파일에서 원본 바이트와 SHA-256 동일 확인. 한/영 문구가 별도로 보존되는지 확인.
2. 규격 변경 → 기기 저장 → 새로고침 → 작업 다시 열기 → JSON 가져오기에서 원본과 치수 복원 확인.
3. 두 출력 비율의 실제 다운로드 PNG가 1080×1920 / 1080×1620인지 검사. 단색 테스트 사진의 내부 대표 픽셀 색상 유지 확인.
4. 상품 사진 누락, 음수 규격, 텍스트 넘침에 대한 내보내기 차단 확인.
5. 치수 값·치수선 위치 수정과 되돌리기, 표시 설정 보존 확인.
6. 320 / 390 / 768 / 1440 px 너비에서 각 편집 탭의 가로 넘침과 JavaScript 오류가 없는지 검사.

첫 실행에서 4건은 textarea의 암시적 레이블 텍스트를 찾는 테스트 선택자가 맞지 않아 시간 초과가 났다. 실제 접근성 이름으로 textbox를 찾도록 수정했고 모든 검사가 통과했다. 검사나 검증 조건을 제거하지 않았다.

## 이번 검증이 보장하지 않는 것

- 테스트 입력은 합성한 단색 PNG다. 사용자가 업로드했던 원본 `18606.jpg`는 아직 없으므로 실제 상품의 로고·인쇄·모서리 보존 품질은 별도 검증 대상이다.
- 원본 파일 바이트 보존과 최종 합성 PNG의 모든 픽셀 일치는 서로 다르다. 최종 출력은 배율·리샘플링·문구·치수선 합성이 적용된다.
- 단일 사진으로 치수와 입체 형상을 복원하지 않는다. 치수선은 입력값을 수동 위치에 표시한다.
- 자동 배경 제거, 마스크/영역 편집, AI 이미지 생성, 자동 번역, 맞춤법 교정, 추가 언어, 결제·인증·서버 저장은 미연결이다.
- 모바일 검사는 Chromium 화면·터치 에뮬레이션이다. Android 실제 기기, iOS Safari, APK/AAB, Google Play 심사는 미검증이다.
- 상용 앱이나 공개 체험 URL을 배포하지 않았다. 회사 홈페이지 작업 트리는 변경 없이 유지했다.

## 광고 이미지 비율 확장

- 비율을 1:1, 4:5, 3:4, 9:16, 2:3, 16:9, 1.91:1로 확장했다. 픽셀·용도 정의를 공통 모듈로 관리하고 선택·저장·백업·가져오기·생성 요청에 적용했다. 1.91:1 출력은 표준 근사 크기 1200×628이다.

- `npm run test:domain`: 24개 통과, 실패·건너뜀 0개. 원본/창작 요청 모두 비율과 최종 출력 픽셀을 유지하고 지원하지 않는 비율을 거절하는지 포함한다.

## 규격 없는 업종 광고

- 자동차·모빌리티, 교육·강의, 보험, 서비스 업종을 추가했다. 해당 업종은 규격 정보 없음이 기본이며 모든 업종에서 직접 규격 사용을 켜거나 끌 수 있다. 기존 사진·문구·치수는 보존하고 규격 사용을 끄면 생성 요청에는 치수를 넣지 않는다.
- 교육·보험·서비스는 원본 사진 없이도 문구와 배경으로 광고를 내보낸다. 사진 자리 안내가 출력되지 않으며 문구 중심으로 배치한다. 사진을 쓰는 규격 없는 광고는 규격 표가 차지하던 공간을 사진 영역으로 활용한다.
- `npm run build`: 타입 검사·Vite 빌드·단일 HTML 생성 통과. `npm run test:domain`: **27개 통과**, `npm test`: PC·모바일 **24개 통과**, 실패·건너뜀 0개.
- 네 업종 모두 치수 필드 없이 출력하며, 이전에 입력한 잘못된 치수가 규격 없는 광고를 막지 않는지 확인했다. 다운로드한 PNG의 옛 규격 표 위치에서 규격 블록이 없음을 검사하고 원본 사진 바이트 보존을 확인했다.
- 사진 없는 교육 광고의 업종·서비스명·서비스 내용·비율을 저장하고 다시 열어 JSON 복원·PNG 출력했다. 창작 모드에서 사진 대신 광고 설명을 요구하며 실제 AI가 연결되지 않아 생성/내보내기가 대기 상태임을 검사했다.
- 7가지 비율의 사진 없는 문구 배치가 캔버스를 벗어나거나 규격 영역과 겹치지 않는지 검사했다. 실제 차량/상품의 보존 요청에서는 원본 사진을 계속 요구한다. 생성 모델 선택도 창작 광고에 원본 상품 동일성을 주장하지 못하도록 유지했다.
- 최종 단일 HTML에서 교육 광고 1080×1350 PNG 다운로드, 320/390/768/1440 px 화면 폭, 외부 요청·JavaScript 오류 0건을 확인했다. docs/previews/services-no-specs-mobile.png, service-editor-mobile.png, service-ad-example.png는 이 검증판의 실제 화면/출력이다. 예시 광고는 직접 입력한 문구로 합성했으며 AI 생성 결과가 아니다.
- 실제 OpenAI·결제·영상 연결이나 회사 홈페이지·Google Play 배포는 하지 않았다. 회사 홈페이지 작업 트리는 변경 없이 유지했다.
