# 광고별 선택·부분수정 후속 개발 — 2026-11-08

기준 코드: `feat/selective-image-edit-20261107`, `f456f84bc874898d37fdcca98a6a6945461a2a34`.
기존 부분수정 API, ROI 처리, 원본 보존 합성, 과금 원장을 재사용했다. 이 변경은 **검토용 개발본**이며 운영 배포·기능 활성화·APK 제작을 포함하지 않는다.

## 변경 내용

- 일반 광고 생성 입력에 1·2·4·6·8·10장 선택을 추가했다. 규격 기하 검증 화면은 기존 단일 출력이다.
- 여러 결과를 각각 별도 프로젝트로 보관한다. 같은 입력을 중복 제출하면 같은 결과 식별자를 사용하며, 기존 프로젝트는 덮어쓰지 않는다. 전체 목록 저장은 하나의 IndexedDB 트랜잭션으로 처리한다.
- 결과 목록에서 번호/썸네일로 한 장을 선택한다. 원본과 선택하지 않은 결과를 보존한다. 수정본은 원래 묶음에서 분리된 새 프로젝트와 PNG로 저장한다.
- 다음 장은 현재 장의 파일·미리보기 검증이 끝난 뒤 기존 GenerationPanel을 통해 요청한다. 목록 컨트롤러 자체는 API를 호출하지 않는다. 불확실·실패 결과를 건너뛰지 않는다.
- 다른 결과 선택, 남은 생성 중지, 준비 취소, 화면 숨김/pagehide, 계정 변경, 화면 이탈은 이후 자동 생성을 중단한다. 이미 서버에 접수된 요청의 취소나 환불을 뜻하지 않는다. 새로고침은 새 유료 요청을 자동 재개하지 않는다.
- 신규 크레딧 정책의 장별 차감 확인은 유지한다. 여러 장 전체의 별도 예산 예약은 추가하지 않았다. 각 장에 기존 서버 예산·크레딧 검사를 적용하며, 잔액/한도 부족 시 일부만 완성될 수 있다.
- 결과의 주요 세 버튼은 `사용확정`, `부분수정`, `시안반려`다. 기존 서버 반려 확인 후 입력 화면으로 돌아가는 처리를 유지했다. 입력 문구와 첨부사진을 지우는 코드는 추가하지 않았다.
- 사용확정 후에도 부분수정 진입 버튼을 제공한다. 서버 작업 ID·프로젝트·원본 해시·크기·문구 구성이 저장본과 일치해야 열린다.
- 브러시의 빠른 이동 사이를 선으로 연결하고 확대 보기를 추가했다. 현재 위치와 이동할 위치, 연결될 영역을 함께 지정하도록 안내한다. 비교 화면의 `원본 선택`은 수정본을 자동 확정/반려하지 않는다.
- 단독 프로젝트 가져오기와 새 시안 만들기는 기존 결과 묶음과 분리한다.

## 실제 신발 광고 확인

원본 PNG(1080×1920), 기존 마스크와 실패했던 수정본을 찾아 시각적으로 확인했다. 원본 SHA-256은 `fcfcf78a39244c84e36de3ea62f3459cf3776b0c1d0ed9818492e4eed8f52208`이다.

대화의 이미지 생성 도구로 새 품질 시안을 만들었다. 작은 뒤쪽 신발을 오른쪽 뒤로 옮기고 바지 끝→발목→양말→신발이 연결되는 형태를 관찰했다. 이 결과는 **앱 API에서 생성한 결과가 아니며**, 941×1672 출력이라 원본 해상도·픽셀 보존을 주장할 수 없다. 문구·가격·전면 제품은 육안 비교 대상이며 동일성 인증을 통과한 것이 아니다.

앱의 실제 합성 함수를 이용한 별도 로컬 실험에서는 생성 후보만 원본 크기에 맞춰 비교했다. 원본은 리사이즈하지 않았다. 선택 픽셀 226,198개 중 225,925개가 바뀌었고, **선택 밖 변경은 0픽셀**, 결과 크기는 1080×1920이었다. 그러나 옛 다리 위치와 바지·문구 주변 경계에 이음새/번짐이 보여 **시각 품질 불합격**으로 판정했다. 픽셀 보존 통과와 자연스러운 수정 성공은 서로 다른 조건이다. 이 불합격 합성본을 최종본으로 제공하거나 원본을 교체하지 않았다. 실험의 후보 리사이즈를 운영 어댑터에 도입하지 않았다.

## 운영 반영 전에 남은 사항

1. 브라우저가 실행되는 환경에서 최종 빌드의 묶음 생성·선택·반려 후 입력 복원·비교·터치 브러시·확정본 재편집을 검증한다. 계정 전환과 네트워크 단절도 포함한다.
2. 현재 운영 원장과 연결된 검증용 요청으로 실제 원본/마스크의 모델 출력을 검사한다. 원본 보존과 자연스러운 연결, 경계, 제품·문구·로고 보존을 모두 통과해야 한다. 이번 앱 경로의 실유료 이미지 생성 호출은 0회다.
3. 기존 공급자 호출의 최대 비용 경계, 큰 이미지 메모리/동시 실행 부하, Android 기기 검증은 기존 미해결 사항이다. 누적 예산 관리 코드를 유지했다는 사실만으로 이 위험들이 해결되지 않는다.

`GenerationService.selectiveEditingEnabled`와 `OpenAIImageAdapter.selectiveEditReady`는 기본 비활성 상태를 유지한다. 운영 서버·DB·배포 설정·API 키를 변경하지 않았다. 이 문서는 실제 이미지 품질과 배포 완료를 선언하지 않는다.
