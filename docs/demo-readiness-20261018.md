## 검증 가능한 시연과 한계

- 기존 광고 흐름: 사진 첨부/복구, 합계 10 MB 초과 안내, 규격 입력·참조 전달, 직접/작은 동일 사진 치수 표시, 관리자 이용권 미차감, 저장·다운로드, 생성 당시 기획/매체/SEO 정보는 로컬 대체 provider 회귀 검사로 확인한다. 실제 신규 유료 생성 성공이나 사진 동일성 검증을 대신하지 않는다. SEO는 검색량 조회가 아닌 규칙 기반 추천이다.
- 로컬 재질 경로: 실제 Blender 박스 500×350×200 mm 및 원통 지름 80/높이 200 mm 산출물이 있다. 입력 치수로 본체를 만들고 동일 카메라 축으로 주석을 합성한다. 기존 산출물 복구는 새 렌더가 아니다. 절차적 재질·예시 덮개이며 고객 사진의 로고/인쇄/재질을 복원하지 않는다. 프리미엄 광고 완성 사례로 제시하지 않는다.
- 완료 렌더의 브라우저 보관은 최신 1건과 같은 탭 복구에 한정한다. 검증된 PNG를 내려받아 시연 자료로 별도 보관한다. 서버에서 실행 중이던 작업은 서버 재시작 후 복구되지 않는다.

## 운영으로 연결할 경로

현재 Docker 이미지에는 Blender가 없고 운영 API도 로컬 렌더 API를 실행하지 않는다. localhost 제한을 풀어 공개하는 방식으로 배포하지 않는다. 웹 서버와 분리된 렌더 실행 환경에서 입력 검증 → 인증된 작업 접수 → 작업 소유권/대기열 → Blender 실행과 자원 제한 → 결과 PNG/manifest 영속 저장 → 인증된 조회/취소/다운로드 순서를 구현·부하 검증해야 한다. 무료 Render로 이 경로가 동작한다고 가정하지 않는다. 현재 코드는 로컬에서 렌더 후 PNG를 가져오는 시연까지 가능하다.

사진 정체성까지 갖춘 고급 결과를 위해서는 승인된 실제 사진 자산을 확보하고 규격 우선 형상에 제품별 재질/인쇄를 적용하는 경로와 동일 입력 비교 검수가 필요하다. 범용 박스나 프롬프트 전달만으로 해결 완료라고 주장하지 않는다. 현재 자료에 없는 고유 인쇄/재질은 임의로 복원하지 않는다.
