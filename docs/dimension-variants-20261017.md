# 선택적 규격 기반 생성과 제한된 평면 보정

개발 브랜치: `feat/dimension-variants-planar-control-20261017`. PR #8 최종 커밋 `e9eb57ee89fbad5427ccce8a454f4cad92a2ebe6`에서 이어간다. 기존 PR #5–8의 사진·관리자·초안 복구·결과 안내 변경을 포함한다. main으로 덮어쓰지 않는다.

## 사용 범위

기본 생성은 변경하지 않는다. 사진과 숫자 치수를 입력하고 **규격 기반 생성**을 직접 선택하면 이번 규격 이름·치수 기준·실제 측정값을 원본 사진과 함께 생성 요청에 전달한다. 한 번에 한 규격만 생성한다. 여러 규격 목록 관리·일괄 생성 기능은 아니다. 다른 규격은 별도 프로젝트로 저장할 수 있다.

- 포장재: 상품 본체 가로·깊이·높이. 열린 덮개와 손잡이를 본체 치수로 해석하지 않는다.
- 용기: 본체 지름·높이 또는 적합한 외곽 치수. `500 ml` 같은 규격 이름은 설명이며 용량에서 형상을 추정하지 않는다.
- 의류: 평면 규격에서 치수 기준을 `펼친 의류`로 선택하고 가슴 단면·총장을 직접 입력한다. S/M/L만으로 치수·핏·둘레를 만들지 않는다.

이 경로는 기존 완성 광고 생성·문구·고품질 설정을 유지한다. 치수와 사진의 동시 전달은 생성 제약이지 실물 비례 보장이 아니다. 결과에는 전달한 규격의 스냅샷과 이 한계를 표시한다. 기존 참조 사진 비례 검사는 **다른 규격을 생성하는 경우** 원본과의 불일치만으로 막지 않으며, 일치 판정도 하지 않는다.

## 별도 선택: 정면 평면 자동 보정

평면 규격 + 본체 외곽 기준일 때만 선택한다. 사용자는 가림 없는 정면 평면 직사각형 사진임을 확인해야 한다. 열린 박스, 곡면 용기, 의류, 입체 형상, 회전된 사선 사진은 이 보정의 지원 대상이 아니다.

1. 서버가 원본에서 균일 배경/알파와 독립된 직사각형 외곽을 확인한다. 외곽을 확인하지 못하면 예약·provider 호출 전에 거절한다.
2. 원본 파일을 보존한 채 분리한 평면을 목표 비율로 배치한 1024px 참조 가이드를 만든다. 이번 요청은 상품만 별도로 생성하는 경로로 전환한다.
3. 생성 결과를 최대 512px 분석으로 검사한다. 축에 평행한 직사각형 외곽, 잘림·다중 물체·외곽 가림·추가 콘텐츠 등의 모호함이 있으면 보정하지 않는다. 목표와 25% 넘게 차이 나는 결과도 강제로 맞추지 않는다.
4. 조건을 만족하면 **분리된 상품 평면 픽셀만** 목표 비율로 조정한다. 광고 전체·광고 문구·배경을 늘이지 않는다. 상품 자체 인쇄도 평면 픽셀과 함께 변하므로 세부 검수가 필요하다.
5. 보정 전 원본·후처리 결과·입력 비율·추정 외곽 비율·적용 후 비율·상태를 별도로 보존한다. 이후 광고 문구와 합성한다. 결과 파일 비율과 보고값을 검증하고, 사용 확정은 사람이 한다.

직사각형 외곽 검출은 촬영 각도·내부 가림·상품 동일성·실물 치수 또는 3D 형상을 증명하지 않는다. `geometryVerified`와 `identityVerified`는 항상 false다. 보정 실패 시 원본 결과를 그대로 검토하며 재생성/유료 재시도를 자동 실행하지 않는다. 실물 비례의 범용 자동 검사·보정 완료로 홍보하면 안 된다.

## 데이터와 비용

원본 source hash, 생성 전 원본 파일, 생성 보정 전 raw artifact, 최종 artifact, 규격 스냅샷을 보존한다. 규격 이름/기준/치수 변경은 이전 결과를 새 규격 결과로 재사용하지 못하게 한다. 설정·새로고침·로컬 보정·이미지 저장에는 별도 provider 호출이 없다. 새 광고 요청 한 번에 provider 요청 한 번이며 기존 idempotency·예산·불명확한 실행 보류를 유지한다. 관리자 이용권 미차감도 API 비용 원장/예산 제한을 면제하지 않는다.

클라이언트와 서버를 함께 배포해야 한다. `dimensionVariants`/`planarControl` 지원이 없는 구형 서버에는 선택 옵션 요청을 보내지 않는다. 새 DB 테이블이나 권한 확대는 필요하지 않으며 기존 request/metadata JSON과 비공개 이미지 저장소를 쓴다. 이미지 두 벌 보관으로 프로젝트/스토리지 한도에 더 빨리 도달할 수 있다.

## 검증과 배포

대체 provider의 픽스처로만 검사했다. 실제 유료 AI 품질·복잡한 상품·다양한 촬영 환경에서의 정확도를 검증한 결과가 아니다. 도메인 검증에는 단순/가린/기울어진 외곽, 큰 불일치, 입력 위조, 원본 보존, 규격 간 분리, 관리자 비용 보호, SQLite/PostgreSQL 재시작 복구를 포함한다. 브라우저 검증은 선택/해제·초안 즉시 복구·320/360/390/1440px·사용 확정·1080×1920 다운로드·구형 서버 차단을 포함한다.

배포 전 실제 Render 서비스/저장소/연결 브랜치/Live SHA/환경/기존 Supabase 데이터를 읽기 전용으로 확인하고, draft PR의 **검사 통과한 정확한 head SHA**를 배포 대상으로 고정한다. 인증된 Render 실행 경로가 현재 작업 환경에 없다. 공개 health 읽기도 프록시 `Tunnel connection failed: 403 Forbidden`으로 차단되어 현 운영 상태를 확인하지 못했다. 배포 요청은 실행하지 않았다. 사용자 보고상 이전 `0836e087ecdc60a3417a9aa5bc679148057c4af9` 수동 배포와 실제 생성은 성공했으며, 이를 PR #8 또는 이번 변경 배포 완료로 해석하지 않는다. 키·예산·권한·유료 플랜을 변경하지 않는다.
