## 적용 경로와 검토

관리자 페이지에서 대상 회원 선택 → `지원 적용 전 조회` → 이메일, 관리자 사용·보류액, 관리자 $4/회원 $1/전체 $5, 추가 이용권을 확인 → `조회한 시연 지원 적용` 및 확인창. 조회와 적용 사이에 잔액/비용이 바뀌면 기존 조회를 거부한다. 응답 유실 후 같은 요청 또는 새 조회를 해도 월별 단일 지원 기록을 반환한다. 사용한 이용권은 재충전하지 않는다. 실제 결제·이미지/문구 AI 호출은 없다.

이 기능은 동일 PostgreSQL 연결 안에서 계정/관리자 비용/회원 이용권 스키마를 원자적으로 처리할 수 있을 때만 사용한다. 별도 SQLite 파일 구성은 `DEMO_SUPPORT_ATOMIC_STORAGE_REQUIRED`로 거부하며 UI에 제공하지 않는다. 로컬 검증은 PGlite PostgreSQL 대체 엔진과 모의 provider로 수행한다. 운영 Supabase 다중 연결 부하 검증을 수행한 것은 아니다.

## 일관성

- 승인 원본 `monthly_budget_approvals`의 $5를 수정하지 않고 `monthly_demo_support`에 월별 단일 재배정을 기록한다. effectiveBudget에서 관리자 -$1/회원 +$1을 함께 반영한다. 기존 승인 버튼 재실행·서버 재시작으로 관리자 $5가 다시 채워지지 않는다.
- 관리자 spent+held가 $4를 넘으면 지원을 거부한다. 기존 비용·불확실한 비용 보류·기존 작업을 삭제하지 않는다.
- 재배정, 지급 장부, 관리자 감사 로그를 하나의 PostgreSQL 트랜잭션으로 묶는다. 뒤의 감사 로그 쓰기 실패도 배정과 이용권을 모두 되돌린다. 외부 공급사 API는 트랜잭션 안에서 호출하지 않는다.
- PostgreSQL 트랜잭션들은 공통 advisory lock을 취하며 다른 스키마의 중첩 작업도 동일 연결을 사용한다. Promise.all 조회의 search_path 변경을 연결 내에서 순서대로 실행한다. 베타 환경에서 일관성을 우선한 것으로 트랜잭션 처리량은 이전 사용자별 잠금보다 줄 수 있다.
- 이미지와 문구 예산 조회/예약을 같은 잠금 안에서 실행하여 지원 적용 전의 관리자 $5 한도를 늦게 예약하지 못하게 한다. 문구는 원래 기본 예산과 현재 유효 배정 중 작은 한도를 유지한다.
- 월 경계에서는 적용 마지막에도 기간을 검사해 전체를 롤백한다. 11월에는 이전 기본 배정/기본 총예산으로 복귀하고 월별 지원으로 기본 배정을 늘리지 않는다.
- 비용 보호는 기존 추정비용·요청당 $0.50 예약 정책을 보존한다. 공급사 청구 자체를 정확히 $5 이하로 제한하는 외부 하드 상한은 아니다.

**지원 실제 적용 후에는 이 저널을 모르는 이전 서버 코드로 곧바로 롤백하면 안 된다.** 이전 코드는 관리자 $5를 다시 허용하면서 회원의 이미 사용한 비용을 새 배정에 제대로 반영하지 못할 수 있다. 적용 후 롤백은 저널을 보존하는 호환 수정 또는 생성 중지와 비용 정합성 검토를 먼저 준비해야 한다. 데이터/저널/이용권 기록을 삭제하거나 기본 예산을 다시 세팅해서 복구하지 않는다. 지원 전에는 기존 배포 후보의 코드 롤백 기준을 따른다.

## 최종 회귀 검사에서 발견한 제작 시작 경쟁

기존 `CreateCampaign`의 중복 클릭 방지가 React 상태 갱신에만 의존해 같은 이벤트에서 두 번 클릭하면 `onReady` 저장·전환이 두 번 호출됐다. 전체 로컬 검사에서 사진 없는 예시 생성이 중단된 뒤, 공급사 상태 조회를 보류한 결정적 회귀 테스트로 저장 2회를 재현했다(기대 1회). 즉시 적용되는 ref 잠금으로 제작 시작을 한 번으로 제한하고 오류/완료 후 잠금을 해제한다. 기존 생성 단계의 변경 감지와 중복 공급사 요청 방지는 유지한다. 새 테스트는 데스크톱/모바일 모두 저장 1회와 생성 POST 1회를 확인한다. 대기시간이나 기존 검수 조건을 완화하지 않았다.
