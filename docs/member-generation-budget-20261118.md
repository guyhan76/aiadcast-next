# aiadcast 이미지 광고 이용권과 비용 운영 설계

## 운영 기준

| 구분 | 적용 기준 | 한도 또는 잔액을 소진했을 때 |
| --- | --- | --- |
| 개발·테스트 | 관리자와 테스트 계정의 공급사 비용을 기간 제한 없이 합산한다. 과거 사용액과 미확정 예약액을 포함한 승인 한도는 100달러다. | 남은 예산이 다음 호출 예약액보다 적으면 새 테스트 호출을 중단한다. |
| 일반 고객 | 인증된 신규 회원에게 무료 1장을 한 번 지급한다. 서버에서 검증한 실제 구매분은 해당 회원에게만 추가한다. | 잔액이 없으면 새 생성을 접수하지 않는다. 다른 회원의 사용량과 테스트 예산은 이 판단에 들어가지 않는다. |
| 서비스 운영비 | 고객 무료분과 구매분을 제공할 때 발생한 이미지 공급사 비용을 별도 기록한다. | 판매량, 호출량, 확정 비용, 미정산액과 이상 신호를 관리자가 점검한다. 비용 경고로 전체 고객의 생성을 차단하지 않는다. |

예를 들어 테스트 누적 비용이 이미 100달러여도 무료 1장이 남은 회원은 1장을 만들 수 있다. 3장을 구매한 다른 회원은 한 장을 받은 뒤 2장을 더 사용할 수 있다. 여러 장을 동시에 주문하면 요청한 장수만큼 먼저 예약하고 결과가 전달된 장수만 차감한다.

## 생성과 비용 정산

1. 서버가 인증 정보로 관리자·테스트 계정과 일반 고객을 구분한다. 일반 고객 화면에는 남은 광고 장수를 표시한다.
2. 무료분, 검증된 구매분, 이미 사용하거나 예약한 장수를 확인한다. 요청을 접수할 때 작업별 비용 구분을 고정하고 요청 ID와 결과를 연결한다.
3. 같은 요청은 기존 작업을 반환한다. 공급사에 다시 보내거나 같은 이용권을 두 번 차감하지 않는다. 결과가 정상 전달되면 장당 1장을 확정 차감한다.
4. 확인된 생성 실패는 이용권을 복구한다. 공급사 비용이 실제로 발생했다면 이용권 복구와 별개로 기록한다. 응답 단절로 비용이 불명확하면 비용 예약액을 보존하고 같은 요청의 자동 재호출을 막는다.
5. 결제는 서버에서 회원, 상품, 수량, 구매 상태와 영수증을 확인한다. 테스트 결제와 수동 테스트 지급분은 고객 광고에 사용할 수 없다. 같은 영수증을 복원해도 장수와 판매량을 한 번만 기록한다.

## 관리자 화면과 초기 경고 기준

- 최근 24시간 판매 장수, 공급사 호출 건수와 생성 비용을 함께 본다. 무료 광고도 비용과 호출 건수에 포함한다. 구매와 실제 사용 시점이 다를 수 있다.
- 공급사 사용량으로 산정한 생성 비용을 직전 24시간과 비교한다. 최근 비용이 1달러 이상이면서 직전의 2배 이상이면 비용 급증을 표시한다. 초기 탐지 기준으로, 매출·매입 마감 자료는 별도 대사가 필요하다.
- 한 계정에서 10분간 공급사 호출이 30건 이상이면 다량 호출 계정 수에 표시한다. 같은 요청을 재사용한 횟수와 비용 미확정 건수도 함께 표시한다. 중복 요청 건수에는 정상적인 통신 재시도도 포함된다.
- 운영자가 관리자 화면을 새로고침할 때 집계를 조회한다. 외부 메시지 전송이나 실결제 개시는 별도 운영 결정이다.

## 적용 범위

고도화 버전의 PostgreSQL 생성 서버에 적용하는 설계다. 기존에 승인된 테스트 누적 정책을 먼저 확인하고, 고객 경로를 처음 활성화할 때 `AIADCAST_CUSTOMER_GENERATION_ENABLED=true`를 사용한다. 기존 누적 정책의 관리자 연결 설정은 `AIADCAST_MEMBER_GENERATION_BUDGET_OWNER_ID`다. 전환 상태와 과거 비용은 데이터베이스에 보존해 서버 재시작 후에도 같은 기준을 적용한다. 기존 공유 정책에서 발생한 과거 비용은 그대로 두고 전환 후 접수한 고객 작업부터 운영비로 분리한다.

기존 베타 데이터를 전환할 때 과거 결제의 검증 여부가 구분되지 않는 잔액은 테스트 잔액과 합치지 않는다. 이전 실제 구매분이 있는 계정은 영수증 복원과 사용 내역 대사를 거쳐야 한다. 이번 범위는 이미지 광고 생성과 해당 공급사 비용이며, 결제 환불 동기화 및 공급사 청구서 대조는 출시 검증 대상이다.
