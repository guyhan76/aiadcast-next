# AI 자동 규격 표시 — 2026-10-18

후보 `feat/ai-dimension-display-20261018`, 기반 PR31 `1f2ddeb0e127e93c210d216c798201b3ab9f1219`. 기존 디자인과 이용권·인증·예산 정책을 유지한다. APK는 0.2.33-demo/code35이며 기존 demo 서명을 재사용한다.

입력 폼의 규격 표시 방법에서 AI 자동 표시와 기존 위치 확인 후 합성을 구분한다. AI 방식은 본제품 직접 표시 또는 우측 아래 같은 제품 작은 사진을 선택하고, 실제 상품 사진·축별 수치·표시 단위를 단일 이미지 생성 요청에 전달한다. 직육면체·평면·원통의 지원 축을 서버에서 검증한다. 디자인 참고는 실물 규격의 근거가 아니다. 원본 합성·규격 표시 없음·기존 위치 합성의 동작은 유지한다.

별도 분석 API를 호출하지 않는다. 로컬 오프라인 합성기는 AI 기능을 지원한다고 표시하지 않으며 구서버에서도 유료 생성 전에 차단한다. 동일 작업 복구는 조회로 수행하고 자동 재생성하지 않는다. 관리자 이용권 면제는 예산·동시성 제한을 면제하지 않는다.

입력 계약에 사진 해시/역할, 규격 형태·축·값·단위, 표시 단위·배치를 포함해 서버에서 해시를 만든다. 미리보기에서 결과 파일 및 입력 해시를 검사한다. 사람은 수치/단위, 축, 누락 여부 세 항목과 기존 광고 검수를 확인해야 사용 확정할 수 있다. 서버는 결과 해시에 연결한 검수 기록과 이용권 확정을 한 트랜잭션으로 저장한다. 입력 변경·위조 해시·미검수 결과는 최종 이미지 저장 조건을 충족하지 못한다. 저장 후 재접속해도 같은 입력/결과와 검수를 복원한다.

검증은 대체 provider, 주입한 fetch, 모의 이미지 및 SQLite/PGlite를 사용한다. 본제품/작은 사진 요청, 세 규격 형태, 정확한 축 전달, 단일 생성 호출, 추가 분석 없음, 중복 생성/확정 방지, 계정 격리, 예산/이용권, 재시작 복구, 입력 변경과 해시 오류 차단을 확인한다. 브라우저 모의 이미지는 실제 AI 품질 증거가 아니다.

실제 원본 상품의 동일성·물리 비례·문자/축 정확도를 검증한 상태가 아니다. 사용자 예시 광고는 연출 참고이며 새로운 원본 사진으로 간주하지 않는다. 원본 사진·규격과 별도 실제 호출 승인을 받은 뒤 결과를 평가해야 한다. 유료 API, 운영 배포, 키·환경·플랜 변경은 이 작업에 포함하지 않는다.

## 기존 데이터와 운영 설정

추가 DB 마이그레이션과 신규 환경변수는 없다. 기존 generation_records의 요청/metadata JSON에 자동 표시 계약과 검수 기록을 저장하며, 기존 SQLite/PostgreSQL 구조와 기존 결과의 선택적 필드 호환성을 유지한다. 기존 지원 저널, 비용 지출/보류, 이용권 예약/확정 정책을 변경하거나 재적용하지 않는다. 새 서버의 `generation.aiDimensionDisplay` 응답으로 기능을 확인한다. API 키나 별도 분석 권한을 추가할 필요가 없다. 배포 전 기존 데이터·환경·연결 브랜치를 운영자가 확인해야 한다.

## 사용자 단계

1. 기존 앱과 같은 패키지·서명의 새 APK를 설치하고 같은 계정으로 로그인한다. 서버도 이 후보로 갱신돼야 자동 표시가 가능하다.
2. 광고 만들기에서 실물 상품과 실제 상품 사진을 선택한다. 예시 광고는 디자인 참고로 구분한다.
3. 상품의 축별 규격과 표시 단위를 입력하고 `규격 표시 방법 → AI 자동 표시 · 광고와 함께 생성`을 선택한다.
4. `본제품에 직접 표시` 또는 `같은 제품 작은 사진에 표시`를 선택한다. 후자는 우측 아래 동일 상품 인셋을 요청한다. 기존 `위치 확인 후 치수선 합성`과는 별도 방식이다.
5. 별도로 승인된 실제 생성 시험에서 광고 생성을 한 번 요청한다. 구서버이면 요청 전에 차단되며, 응답 유실 시 기존 작업을 조회해 복구한다. 추가 분석이나 자동 재생성은 없다.
6. 결과의 수치·단위, 각 축, 누락 여부 세 항목과 광고 전체를 직접 확인한 뒤 사용 확정한다. 일반 회원 이용권과 관리자 비용 예산 제한은 기존 정책을 따른다.
7. 이미지 저장으로 검수한 PNG를 내려받는다. 같은 결과의 재다운로드에는 재생성·추가 차감이 없다. 입력을 바꾸면 이전 검수의 유효성을 다시 확인한다.

## 결제 상태 조회 순서 수정

PR31/초기 PR32의 CheckoutPage는 초기 조회가 진행 중이면 사용자의 `결제 상태 확인` 클릭을 버렸다. 초기 주문 응답이 pending이고 뒤의 잔액 응답이 새 값이면 잔액은 갱신됐지만 주문 화면은 다음 자동 폴링까지 pending으로 남을 수 있었다. 자동 폴링을 멈추고 첫 응답을 보류한 데스크톱/모바일 검사에서 수동 클릭 후에도 주문 GET이 1회에 머무르는 것을 재현했다.

수정은 진행 중인 조회 뒤에 사용자 요청을 한 번 이어서 처리한다. 여러 클릭은 합치며 조회 진행 상태를 표시한다. 잔액 증가만으로 완료를 추정하지 않고 해당 주문 응답의 paid 상태를 확인해야 완료 화면으로 바뀐다. 주문 생성/결제 확정 POST나 지원 저널 변경을 추가하지 않는다. 테스트의 시간 제한은 늘리지 않는다.
