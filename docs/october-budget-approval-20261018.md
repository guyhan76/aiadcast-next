# 2026년 10월 일반 광고 생성 예산 승인

## 승인과 적용 범위

사용자 승인: **2026-10 UTC 한 달만**, 일반 광고 생성 서버 총예산 **US$5**, 지정된 기존 관리자 배정액 **총 US$5**. 기존 사용액·보류액을 포함한다. 추가 $5 지급, 총 $10, 매월 반복 인상이 아니다. 참조 원본 분석의 별도 누적 **10회/US$0.30**, 일반 자동 분석 OFF, 관리자 이용권 미차감 정책을 변경하지 않는다.

사용자 Render 화면에서 확인된 현재 운영 기준은 PR #14 `12b088765ae20ad181e905d8b552c5bff5940609`이며 2026-10-18 10:33:03 GMT+9에 Live다. 이 수정 브랜치 `feat/october-budget-approval-20261018`은 해당 커밋을 조상으로 유지한다. `main`이나 과거 PR #5 브랜치로 교체하지 않는다.

## 기존 차단 원인

사용자 관리자 화면의 당시 값은 총예산/본인 배정 $1, 사용 $0.5273, 보류 $0이다. 남은 $0.4727가 요청 전 예약금 $0.50보다 $0.0273 작아 생성이 차단됐다. 이용권 미차감과 공급사 비용 한도는 별개다. 공급사 실제 잔액은 조회하지 않았다.

기존 설정은 월이 바뀌어도 유지되는 기본값이다. 환경 변수만 5로 바꾸면 저장된 기본 총예산과 충돌해 시작이 실패할 수 있다. 기존 CLI는 Supabase 원장 변경을 지원하지 않으며 기본 배정액은 증가만 허용한다. 따라서 월말 수동 되돌림에 의존하지 않고 별도 기간 승인 기록을 사용한다.

## 구현

- 배포만으로 한도는 오르지 않는다. 기존 설정된 소유 관리자 계정만 `POST /api/admin/october-budget`에 빈 객체를 보내 활성화한다. UI에는 고정된 `10월 한도 총 $5 적용` 버튼이 있다. 클라이언트가 금액·기간·대상 계정을 정할 수 없다.
- 계정 DB의 `monthly_budget_approvals`에 기간·대상·총액·배정액·기본값·시각을 한 번 기록한다. 반복 요청은 같은 기록을 반환하며 원장 비용을 초기화하지 않는다. 기존 다른 회원에게 양수 배정이 있으면 충돌로 차단한다. 활성 기간 중 다른 회원의 양수 배정도 차단한다.
- 기본 `settings` 총예산과 `users.budget`을 수정하지 않는다. 요청할 때마다 서버가 UTC 월과 현재 역할을 확인한다. `2026-11-01T00:00:00Z`부터 기본 총예산과 기본 계정 배정액을 사용한다. 재시작이나 예약 작업이 필요 없다. 승인 대상이 관리자 권한을 잃어도 남은 한도를 다른 계정에 재배정하지 않는다.
- 실제 생성 예약은 기존 원장 트랜잭션 안에서 현재 월 한도만 적용한다. 사용액과 불확실한 비용 보류는 보존한다. 월이 바뀌기 직전 얻은 승인으로 만료 후 새 예약을 할 수 없다. 이미 시작된 요청의 정산은 시작 월에 남는다.
- 텍스트 도우미는 기본 예산 범위에 남는다. 참조사진 분석 원장과 한도, 일반 분석 스위치는 건드리지 않는다. 유료 공급사 호출은 구현·검증에 사용하지 않는다.

## 배포 및 활성화 순서

1. 수정 draft PR의 **최종 head SHA와 그 SHA의 원격 CI 성공**을 확인한다. 기존 Render 서비스 `aiadcast-next`, 저장소 `guyhan76/aiadcast-next`, 기존 Supabase 프로젝트와 현재 운영 SHA를 대조한다.
2. 운영자가 새 브랜치의 정확한 SHA를 수동 배포한다. 프런트와 API를 함께 배포한다. 기본 예산 환경값, 키, 플랜, 권한을 변경하지 않는다. 이 작업 환경에서는 Render 인증 경로를 확인하지 못했으므로 운영 배포·활성화를 실행하지 않는다.
3. 기존 소유 관리자 계정으로 로그인하고 관리자 페이지에서 현재 총예산·본인 배정·사용·보류를 확인한다. `2026년 10월 한도`의 만료 시각을 확인하고 `10월 한도 총 $5 적용`을 누른다. 다른 회원 양수 배정이 발견되면 임의 회수하거나 총액을 늘리지 말고 충돌 원인을 확인한다.
4. 총예산 $5 / 본인 월 배정 $5, 기존 사용·보류 유지, 한 번만 적용됨을 새로고침 후 확인한다. API 기준은 `/api/admin/overview`의 `octoberApproval.active=true`, `budget.limitMicros=5000000`, 본인 `budget.limitMicros=5000000`이다. 사용액이 당시 $0.5273이고 보류가 0으로 그대로라면 남은 금액은 $4.4727다. 버튼 적용 자체는 광고를 생성하지 않는다.
5. 11월 1일 00:00 UTC부터 새 요청/화면은 기본 총예산과 기본 본인 배정(현재 각각 $1)을 사용한다. 10월 사용·보류·승인 기록은 삭제하지 않는다. 새 달 추가 인상은 별도 승인 대상이다.

활성화 후 과거 버전으로 바로 롤백하면 과거 생성 서버가 10월의 증가된 원장 한도를 기본 $1과 비교하여 시작을 거부할 수 있다. **원장을 낮추거나 비용을 삭제해 우회하지 않는다.** 이 기간 승인 로직을 유지한 수정 버전으로 복구한다. 활성화 전 배포만 한 상태에는 예산 원장을 늘리지 않는다.

예약금은 공급사가 강제하는 결제 상한이 아니라 앱의 사전 admission 한도다. 실제 응답 원가가 예약금보다 클 수 있으며 기존 정산 정책은 실제 원가를 보존하고 후속 요청을 차단한다. 무조건 정확히 $5 이하로 공급사 청구를 보장한다고 설명하지 않는다.

## 검증 근거

SQLite와 실제 PostgreSQL SQL/트랜잭션을 실행하는 PGlite에서 동일한 기간·금액·재시작·역할·동시 예약·월 경계 검사를 수행한다. 실제 로컬 HTTP/인증/SQLite를 사용하는 브라우저 검사는 활성화 전후 금액, 새로고침, 모바일 표시, 다음 달 복귀를 확인한다. 로컬 대체 provider만 사용하며 실제 OpenAI·운영 데이터·키를 사용하지 않는다. 최종 검사 결과와 원격 실행 링크는 해당 draft PR에 기록한다.
