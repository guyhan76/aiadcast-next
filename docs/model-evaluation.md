# 모델 도입과 품질 검증 기준

현재 실제 AI 공급사 어댑터와 모델은 미연결이다. 아래는 신규 상용 앱에 적용할 기준이며 평가를 완료했다는 보고가 아니다.

## 후보 선택

- 이미지 생성, 배경 분리, 영역 수정, 번역, 영상의 후보를 각각 비교한다.
- 공식 문서에서 모델 ID·지원 API·해상도·지역/계정 접근·가격·서비스 조건을 확인한 날짜를 남긴다. 현재 환경에서 최신 공식 문서를 직접 확인하지 못한 항목은 미확인으로 표시한다.
- 품질 우선 후보와 비용 대비 후보를 동일한 입력으로 평가한다. 새 모델이라는 이유만으로 기본값을 바꾸지 않는다.
- 테스트용 API 프로젝트와 예산 한도를 별도로 설정한다. 고객에게 보여주는 이용권 비용과 공급사 비용을 각각 측정한다.

## 초기 평가 자료

포장재 외에 자동차·뷰티·전자제품·의류·유리/금속·식품 및 교육·보험·서비스 광고를 포함한다. 초기 목표는 주요 업종별 실제 사례 5개 이상이며 제공된 원본·확정 문구·치수 또는 규격 없음·기대 편집 범위를 한 묶음으로 관리한다. 브랜드/로고, 투명 물체, 반사, 복잡한 윤곽, 긴 한글·영문, 7가지 출력 비율을 넣는다. 특허 명세서 전체는 2026-10-09 수령·분석했다. 실제 원본 18606.jpg와 대응 규격 자료는 아직 실물 일치도 평가에 사용하지 못했다.

| 항목 | 통과 판단 |
|---|---|
| 원본 보존 광고 | 원본 레이어를 다른 상품으로 다시 그리지 않음. 원본 해시·합성 범위 기록, 마스크 경계와 로고를 사람도 확인 |
| 창작 광고 | 원본과 다른 디자인일 수 있음을 구분. 사용한 참고 자료와 모델/프롬프트 버전 기록 |
| 한글·다국어 | 확정한 문구를 별도 글꼴 레이어로 출력. 문자열 누락·잘림 없음. 번역 문안은 의미·가격·조건을 대조 |
| 규격 | 같은 값에서 표·선 출력. 규격 없음은 입력/요청/표시 모두 생략. 표시 숨김과 규격 미사용 구분 |
| 부분 수정 | 지정한 배경/문구/영역만 변경. 원본·이미 승인한 내용·이력 보존 |
| 과금 | 중복 요청·실패·앱 종료·늦은 응답에도 이중 차감 없음. 고객 이용권과 API 원장 대사 |
| 운영 | 응답 시간·성공률·실제 단가·메모리·다운로드 실패·복구 시간 측정. 초기 수치는 측정 후 확정 |
| 영상 | 상품/로고/문자 일관성을 프레임별 검사. 생성형 영상의 동일성을 무조건 보장하지 않음 |

## 적용과 되돌리기

`server/model-router.mjs`는 평가 승인된 명시적 리비전만 선택한다. `evaluationPassed` 플래그만으로 실평가를 대신하지 않도록 `server/model-evolution.mjs`에 별도의 서명 보고서 검증과 제한 배포 제어기를 추가했다. 생산 모델 목록은 여전히 비어 있다. 미승인 모델과 원본 보존을 지킬 수 없는 경로는 선택하지 않는다.

개발 → 시험 → 제한된 사용자 → 정식 순으로 적용하고, 기존 승인 모델/템플릿/어댑터 조합을 보관해 되돌릴 수 있게 한다. 진행 중 작업은 시작할 때의 모델·견적·입력 버전을 유지한다. 변경 후 비용 또는 실패율이 기준을 넘으면 신규 요청을 멈추고 이전 조합으로 돌아간다.

## 이번에 구현한 제어기와 실행 조건

1. `npm run models:discover`는 새 앱 전용 `AIADCAST_NEXT_LOCAL_OPENAI_API_KEY`가 있을 때만 `/v1/models` 목록을 읽는다. 없으면 조회하지 않고 종료한다. 기존 MVP의 키나 일반 `OPENAI_API_KEY`를 대체 키로 쓰지 않는다. 이미지 생성 호출은 하지 않는다. 공급사 카탈로그에 나온 이름만으로 이미지·영상 지원이나 가격을 추정하지 않는다.
2. 후보에는 공급사 모델 ID, 불변 리비전, 어댑터 버전·해시, 가격 기준 버전과 기능 목록이 필요하다. `latest`처럼 부동 이름은 거절한다. 새로운 API 형식과 기능은 먼저 어댑터 연결이 필요하며, 모델 이름 교체만으로 앱이 새 기능을 얻지는 않는다.
3. 평가 보고서는 신뢰하는 별도 평가 서비스가 Ed25519로 서명한다. 후보 전체 해시·승인 데이터셋·평가 도구 버전·평가 시각이 맞아야 한다. 앱에서 보내는 `통과: true`를 출시 승인으로 취급하지 않는다.
4. 현재 초안 정책은 원본·한글·다국어·규격·규격 없는 서비스·비율·오류/과금의 7개 그룹에 각 4개 이상, 총 28개 이상의 서로 다른 평가 사례를 요구한다. 모든 사례 통과, 평균 원가 $0.30 이하, P95 120초 이하, 기존 평균 원가 대비 10% 초과 상승 없음이 기본값이다. 이는 **실제 모델 성능 측정치가 아닌 초기 평가 정책**이다. 이미지·번역·영상별로 검증된 정책을 따로 확정해야 한다.
5. 승인 후보는 기존 생산 모델이 있을 때 신규 작업의 10%에 배정할 수 있다. 서버가 고정한 작업 ID로 결정하며 실제 운영에서는 해당 선택을 견적/예약과 함께 영속 저장해야 한다. 재시도에서 다시 추첨하지 않는다.
6. 서로 다른 제한 배포 작업 30개 이상을 관찰하고, 품질 결함 없음·비용 한도·실패율 3% 이하이면 자동 승격한다. 품질 결함이나 평균 비용 초과는 즉시 후보를 중단하고 기존 생산 모델을 유지한다. 중복 관찰은 표본 수를 늘리지 못한다. 실제 초기 출시 승인 없이 후보 모델을 일반 고객에게 자동 배정하지 않는다.

정책 파일은 `config/model-evolution-policy.json`이다. 현재 승인 데이터셋 목록은 비어 있고 `discoveryOnly: true`, `automaticPaidEvaluation: false`다. 실제 AI 성능이 좋다고 주장할 근거를 임의로 채워 넣지 않는다. 테스트에 쓰는 모델 이름·보고서·서명키는 테스트 픽스처이며 상용 모델 평가가 아니다.

**미연결:** 주기 실행 서버/스케줄러, 실제 평가 실행기, 승인 데이터셋, 서명키 보관, 공급사 어댑터, 영속 상태/분산 락, 운영 모델 레지스트리 반영, 정식 승격 이후 상시 감시·자동 롤백. 현재 제어기는 메모리 기반 참조 구현으로, 제한 배포 중 후보 중단과 기존 모델 유지까지 테스트한다. 운영에서 매번 프로세스를 재시작하면 상태가 유실되므로 이 코드를 그대로 운영 서비스로 노출하지 않는다.

초기 연결 후 목표 운영은 ‘정기 목록 확인 → 기능/가격 확인 → 예산 범위 내 평가 → 서명 증거 검증 → 제한 배포 → 자동 승격 → 상시 감시’다. 고객이 받는 견적과 모델 버전은 작업 중 바뀌지 않아야 한다.
