# 규격 기하 검증과 실사 렌더 준비 — 2026-10-18

**품질 검토 후 범위 정정:** 아래 Canvas 출력은 도식에 가까운 기하 검증 이미지이며 프리미엄 실사 광고의 수용 결과가 아니다. 일반 만들기 화면에서는 노출하지 않고 `?dimensionProof=1#create` 검증 진입점에서만 선택한다. 화면·버튼·내보낸 PNG에 검증용/광고 완성본 아님을 표시한다. 기존 프로젝트에 저장된 검증 모드도 같은 명칭으로만 연다.

로컬 Blender 4.3.2가 있어 `scripts/geometry/render-product.py`로 동일 입력 치수의 3D 메시·고정 카메라·절차적 재질·조명·투명 PNG와 치수축 투영 manifest를 생성하는 실험을 추가했다. 유료 호출 없음. 이 스크립트는 **운영 서버·일반 광고 경로 미연결**이며 원본 로고/인쇄 복원도 하지 않는다. 설치된 빌드의 OpenImageDenoise 미지원으로 denoise는 끄고 샘플 수를 올려 검토한다.

실사 광고 연결의 다음 단계는 고정 제품 메시의 재질/UV/색상·조명을 확인한 렌더러가 투명 제품+그림자와 source/dimensions/camera-bound manifest를 반환하고, 기존 문구/배경 합성기가 그 픽셀만 배치한 뒤 manifest 축으로 정확한 치수선을 그리는 것이다. 생성 모델에 제품이나 완성 광고를 다시 그리게 해 geometry를 바꾸지 않는다. 기존 생성 광고에 이미 제품이 있으면 그대로 겹쳐 붙이지 않는다. 배경 전용 자산 또는 검증된 분리/복원 과정이 필요하다.


사용자 결정: 참조 사진의 과거 비례보다 입력 규격을 우선한다. 사진은 외관 참고다. 이 결정은 새 유료 API 호출/키/권한 승인이 아니다.

후속 브랜치 `feat/dimension-controlled-products-20261018`은 PR #19 최종 `62fda85b80fd2087247697863d4fc50c4ce2a03f`를 유지한다. PR #18 홈페이지와 독립이다. 운영 배포하지 않는다.

## 실제 연결된 경로

검증 진입점 → 규격 입력 → **규격 기하 검증용 구성** → 직접/작은 제품 보기/표시 없음 → 기하 검증 화면 → 검증 결과 확인 → 검증 PNG.

미리보기와 저장은 같은 렌더를 사용한다. source hash·의미 치수·표시 방식·단위·매체·문구·연락처의 fingerprint가 바뀌면 기존 확정은 무효다. 복구 시 현재 fingerprint를 다시 확인한다. 이 모드는 공급사 생성 요청을 만들지 않으며 generation request builder도 명시적으로 거부한다. 원본 사진 모드로 바꾸거나 규격 없음을 선택하면 로컬 제어 선택을 해제한다.

## 구현 범위와 외관 한계

- 열린 박스: 입력 width/depth/height로 본체 8개 3D 꼭짓점을 구성. 한 투영/한 축척에서 면과 축 끝점을 계산한다. 높이는 덮개 제외. 덮개 길이/각도는 명시된 예시 구조로 실측 보장하지 않는다. 500×350×200은 첫 수용 사례이며 하드코딩한 유일 규격이 아니다.
- 직선 원통 본체: 지름/높이와 한 축척. 병 목·어깨·뚜껑은 생성하지 않는다. 전체 병을 재구성했다고 표현하지 않는다.
- 가방·의류·복합 형상: 해당 전략 미지원으로 표시. 박스/원통으로 자동 대체하지 않는다. 기존 사진 광고는 유지한다.
- 외관: 참조 이미지에서 대표 색상 구간을 추출한 단색 음영 재질. 원본 데이터는 유지하나 출력은 재구성된 제품 렌더다. **실사 재질, 로고, 인쇄, 재봉선, 라벨 UV 복원은 미구현**이며 선택 전/검수 화면에 표시한다. 사진 픽셀 동일성이나 프리미엄 실사 품질 완성을 주장하지 않는다.

실제 사용자 첨부 23009/23011/23013은 이 환경의 Library 다운로드 실패로 직접 확인하지 못했다. 자동 테스트는 명시적인 색상 fixture를 사용한다. 출력 PNG의 제품 형상은 fixture 이미지를 붙인 것이 아니라 입력 치수로 실제 계산한 결과다. 사진 외관 복원 증거와 구분한다.

## 공통 의미 계약의 현재 구현

`dimension-control.ts`의 adapter는 기존 mm 소수 문자열/표시 단위를 유지하면서 body.width/depth/height, body.diameter, plane.width/height, garment.chestFlatWidth/totalLength를 구분한다. body.height의 flaps/handles 제외와 원통 cap/shoulder 제외를 기록한다. 의류 sleeveLength는 현재 저장 축이 없어 추정하지 않는다. 미지원 형상은 기본 cuboid로 떨어지지 않는다.

신규 Project.dimensionControl은 버전/명시적 shape/annotation/accepted fingerprint만 추가한다. 기존 프로젝트 파일은 유지한다. 전체 v2 semantic measurement 저장 스키마·소매 등 임의 축 편집·형상별 사진 대응 검증은 후속 단계다.

## 검증

- 수치: 500:350:200 = 10:7:4, 본체 높이에 덮개 미포함, 모든 면/치수선 동일 축척. 원통 여러 지름/높이 조합의 축 길이/축척 검증.
- 의미: 지름을 가로 폭이나 둘레로 혼동하지 않음. 의류 두 축과 가방 제외 부위를 구분. unsupported shape, 잘못된 옵션, 변경 fingerprint, 공급사 요청 차단 검사.
- 실제 앱: 박스 500/350/200 및 원통 80/200 만들기→검수→확정→PNG. 검수/PNG 바이트 일치, 새로고침 복구, main/inset 내보내기, 높이 변경 후 재확정 요구, 생성 POST 0회. 모바일 가로 넘침/가방·의류 미지원/원본 모드 분리 검사.
- 첫 검수/저장의 한글 글꼴 준비 차이와 모바일 canvas 크기 문제를 수정했다. 강제 클릭/검사 삭제로 우회하지 않는다.

최종 검사 수·SHA·원격 CI는 draft PR에 기록한다. 독립 lint 스크립트 없음. 타입/build/domain/browser/cloud/isolation을 구분한다.

## 후속 단계

1. 실제 상품 면/마스크/인쇄 대응과 보존할 디자인 요소를 공통 계약에 연결한다. 사진 전체 또는 광고 전체 warp 금지.
2. 박스 면별 UV, 원통 펼친 라벨/곡면 재질의 대응 및 출력 검수를 별도 구현한다. 불가능한 외관 보존은 생성 전에 설명한다.
3. 가방 실루엣/손잡이/재봉선, 의류 패턴/포즈/총장·가슴·소매 전략은 독립 구현·시험 후 지원으로 표시한다.
4. 사진 기반 자동 대응에 외부 모델이 필요하면 정확한 입력·작업·호출 수·비용을 확인한다. 기존 박스 사진 1회 승인을 다른 이미지에 사용하지 않는다.
