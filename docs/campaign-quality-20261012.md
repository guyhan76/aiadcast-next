# 광고 구성 재설계 · 2026-10-12

## 해결한 문제

대표자가 제공한 실제 결과는 상품명·설명·가격이 작고, 생성 사진의 빈 벽이 큰 면적을 차지했다. 외주 제작 사례는 큰 카피, 제품 중심 사진, 장점 구획, 규격·가격, 연락처를 함께 구성했다. 이전 수정의 ‘글자가 보인다’는 검증으로 광고의 시각적 완성도를 설명할 수 없었다.

캠페인 광고의 큰 헤드라인·상품명·사진·제공 장점·수량/가격·선택적 규격·연락처를 별도 구획으로 조합한다. 서비스도 사진과 문구로 구성하며 규격을 만들어 넣지 않는다. 수동 치수선과 박스 면 투영은 기존 배치를 유지한다. 사용자가 편집한 문구와 연락처, 규격 표시 선택을 유지하며 없는 혜택·배송 조건·가격을 추가하지 않는다. 가격에 붙은 ‘월’, ‘판매가’, ‘부터’ 등의 조건을 분리하지 않는다. CTA는 요청할 때만 넣는 기존 정책을 유지한다.

자동 캠페인의 공급사 출력은 최종 포스터가 아니라 큰 상품 사진이다. 세로 광고는 1536×864 사진, 가로 광고는 1024×1024 사진을 생성한 뒤 앱에서 최종 7가지 비율을 조합한다. 제품 사진은 완전히 들어오도록 균등 축소하며 기존 세로 사진도 자르거나 늘이지 않는다. 공급사 호출의 사진 크기 검증과 최종 PNG 크기 검증을 구분한다. 새 연출은 과도한 빈 벽을 요구하지 않고, 박스에는 인쇄·면 접합·크라프트 질감·실제 발송 맥락에 맞는 연출을 사용한다.

9:16 내부 구성은 상단 190px, 하단 350px, 우측 160px를 주요 글자의 여유 공간으로 둔다. 이는 보수적인 앱 설계값이며 인스타그램의 모든 기기·노출 위치에서 공식 안전 영역을 보장한다는 뜻이 아니다. 최종 게재 화면 검토가 필요하다.

## 확인과 범위

- TypeScript·Vite·단일 HTML 빌드, 전체 도메인 테스트, PostgreSQL 변환 확인을 수행한다.
- 실제 상품 정보의 1080×1920 출력에서 상품명, 헤드라인, 소재/장점, 수량·가격, 규격, 회사·전화·이메일·홈페이지의 표시를 검사한다. 같은 프로젝트의 검토 PNG와 수락 후 출력 PNG가 동일한지 비교한다.
- 같은 렌더러로 7가지 크기를 출력해 글자 넘침 오류를 확인한다. 로컬 PNG 검사는 Native Canvas와 Noto Sans의 정적 400/800 인스턴스를 사용했다. 브라우저 전체 흐름 검증과 구분한다.
- 사진 시안은 내장 이미지 생성 도구로 참조 상품을 연출한 별도 디자인 검토 자산이다. Render에 설정된 API 키로 이 수정판을 실제 생성한 시험이나 공급사 비용 측정으로 계산하지 않는다. 시안 자산을 앱의 기본 광고 사진으로 바꾸지 않는다.

사진 한 장과 규격 숫자로 실제 입체 치수·깊이를 인증하지 않는다. 생성 사진의 작은 인쇄 문자·QR·상품 동일성은 원본과 비교 검수가 필요하다. 이번 작업을 특허 청구항 구현 완료, 자동 3D 검증, 자동 오타·잡티 검출, 외주 사례보다 우수하다는 실증 결과로 설명하지 않는다. 상품별 자동 세부 사진 생성과 다중 사진 상세 브로셔 구성은 추가 품질 시험이 필요하다.
